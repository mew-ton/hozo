# http の語彙のプラグイン

## この文書が決めること

語彙のプラグイン `http`（`docs/plugin-protocol.md`「語彙のプラグイン」）が持つ、`http` の語彙の、**言語に依らない決まり**: どの op が経路か（「対象」）、通信の上の形（「通信の形」）、書いたものの整合の検査（「診断」の HTTP-*）。プラグインは `plugins/http/`。決まりを読み解くコードは、Go のライブラリ `plugin/httpvocab`（`docs/packages.md`「`plugin/httpvocab`（公開）」）で、このプラグインと、`http` の語彙を Go に出す `go-http`（`docs/plugin-go-http.md`）が、同じものを使う。

語彙の宣言（デコレータ、例外、model）と、その意味の持ち主は `docs/vocab.md`「同梱する語彙」「`http` の語彙」。ある言語への出し方（ハンドラ、テストの口）は、その言語のトランスパイラの文書が持つ。

## マニフェスト

```toml
name     = "http"
wasm     = "plugin.wasm"
protocol = "0.23"

[read]
namespaces = ["http"]
```

- 読み解くのは、標準の語彙 `http`（`vocab/http.hozo`。hozoc に同梱）。このプラグインは、語彙の宣言（`.hozo`）を持たない。
- トランスパイラは、提供しない: ファイルを出さず、単位の `transpilers` に書く名前を持たない。
- 頼まれるのは、仕様のどこかに `http` のデコレータが付いているとき（`docs/plugin-protocol.md`「語彙のプラグイン」）。出力の単位は、要らない。

## 対象

仕様の op（どの名前空間のものも。出力の単位がない名前空間と、外の仕組みの名前空間の op も、含む）のうち、`@http.get` か `@http.post` の付いたものが**経路の op**。経路は、op に付いた `@http.get` / `@http.post` ごとに一つ（両方が付いた op は、書かれた順に二つの経路を持つ）。経路の op が一つもなければ、このプラグインは、何も返さない。

**`http` のデコレータを、読むトランスパイラのない印として付けておくことは、できない**: このプラグインが入っていれば、下の決まりは、どの経路の op にも掛かる。足りないもの（`export`、入力の model、場所のデコレータ）も、設計だけの段階の仕様と、外の仕組みの op に、同じに求める（`docs/decisions.md`「決めたこと」429）。

- **経路の op は `export` が付いていなければならない。** 経路の op は、名前空間の外からの呼び出しが届く入口。付いていなければ HTTP-1。黙ってその経路を飛ばすことはしない（仕様に書いた経路が、気づかないうちにサーバーから消える）。`@http.*` が付いていれば `export` と見なすこともしない（語彙のデコレータが、本体の検査の結果を変えることになる）。
- 経路の op の引数は、0 個か、model 一つ（**入力の model**）。それ以外は HTTP-2。インデックスの model（`docs/types.md`「インデックスの model」）は、フィールドを持たないので、入力の model にできない（HTTP-2）。
- 入力の model の各フィールドは、要求のどこから読むかを言う六つのデコレータのどれかを、**ちょうど一つ**持つ。そうでなければ HTTP-3。六つは、三つの場所（ヘッダ、クエリ、本文）ごとの、**項目の形**（`@http.header` / `@http.query` / `@http.body`）と、**全体の形**（`@http.headerObj` / `@http.queryObj` / `@http.bodyObj`）。意味の持ち主は `docs/vocab.md`「`http` の語彙」で、そこが言う二つの決まりを、このプラグインが確かめる:
  - 全体の形は、型が、フィールドを持つ model のフィールドにだけ付けられる（省略可能な model、配列、インデックスの model には、付けられない）。そうでなければ HTTP-9。
  - 全体の形は、一つの場所に高々一つで、同じ場所の項目の形とは一緒に書けない（`@http.bodyObj` と `@http.body` を、一つの入力の model に書けない）。そうでなければ HTTP-10。
- **要求に項目がないときの扱い**を言う二つのデコレータ（`@http.required`、`@http.default`。意味の持ち主は `docs/vocab.md`「`http` の語彙」）について、このプラグインが確かめる決まりは四つ:
  - 二つのデコレータを付けられるのは、項目の形（`@http.header` / `@http.query` / `@http.body`）を持つフィールドだけ。そうでなければ HTTP-11。全体の形のフィールドにも、全体の形で受け取る model の中のフィールドにも、付けられない: 全体の形の中の項目は、なければ、いつも零値のまま（扱いを言いたい項目は、項目の形で書く）。
  - 省略可能なフィールド（`T?`）には、どちらも付けられない。付いていれば HTTP-12。型は「なくてよい」と言っている: なければ誤りにするなら、また、なければ値を入れるなら、省略可能にしない。
  - 一つのフィールドに、両方は付けられない。付いていれば HTTP-13。
  - `@http.default` のリテラルは、フィールドの型（scalar は元の核の型）に渡せなければならない（`docs/types.md`「互換」の 10: 整数のリテラルは `float` にも渡せる）。渡せなければ HTTP-14。
- フィールドの型（scalar は元の核の型で見る）。全体の形では、その model のフィールドの一つずつを、同じ場所の項目として見る:

| 場所 | 受け付ける型 | それ以外 |
|---|---|---|
| ヘッダ | `string`、その省略可能 | HTTP-4 |
| クエリ | `string` / `int` / `float` / `boolean`、その省略可能 | HTTP-4 |
| 本文 | JSON にできる型（下の「JSON にできる型」） | HTTP-5 |

- `@http.get` の op は、本文のデコレータ（`@http.body`、`@http.bodyObj`）のフィールドを持てない（HTTP-6）。
- パスは、`/` で始まる、決まった文字列。`{` か `}` を含むパス（パスの中の値）は、それを入力のフィールドに結ぶ語彙がまだないので HTTP-7。
- **一つの名前空間の中で、同じメソッドとパスの組が二つあれば HTTP-8。** 別の名前空間の経路とは、比べない（別のサーバーでありうる）。
- **JSON にできる型**: 核の型、scalar、model（インデックスの model を含む）、`optional`、`array`、通信に出せる union（「通信の形」の「union」）と、それらの組み合わせ。通信に出せない union（`arms`）と、それを中に持つ型は、本文（`@http.body`、`@http.bodyObj`）、結果、`@http.status` を持つ例外の引数の型のどこに現れても HTTP-5。
- **入力の model の検査は、model ごとに一度。** 二つの経路の op が、同じ model を入力にしていても、その model の診断（HTTP-3、HTTP-4、HTTP-9〜HTTP-15）は、一度だけ返す。

## 通信の形

**この節は規範。** `@http.get` / `@http.post` の付いた op を HTTP で呼ぶとき、要求と応答は次の形をしていなければならない。サーバーを出すトランスパイラ（`go-http`: `docs/plugin-go-http.md`）も、クライアントを出すトランスパイラも、これに合わせる。その言語のコードの都合では、変えない。

### 要求

| 部分 | 形 |
|---|---|
| メソッドとパス | `@http.get(path)` は `GET <path>`、`@http.post(path)` は `POST <path>` |
| `@http.header` のフィールド | ヘッダ `<名前>`。値は、フィールドの値の文字列そのまま。値がない（省略可能で、ない）なら、ヘッダを送らない。空の文字列のヘッダは、ないものとして読まれる |
| `@http.query` のフィールド | クエリの `<名前>=<値>`。`string` はそのまま（URL のエンコードだけ）、`int` は 10 進、`float` は 10 進の小数か指数、`boolean` は `true` / `false`。値がないなら、送らない |
| `@http.body` のフィールド | 本文が、JSON のオブジェクトで、キー `<名前>` の値が、フィールドの値の JSON。`@http.body` のフィールドが一つでも、オブジェクトで包む。省略可能で値がないフィールドは、キーを省く。`Content-Type: application/json` |
| `@http.headerObj` / `@http.queryObj` のフィールド | その model のフィールドの一つずつが、フィールドの名前の、ヘッダ一つ、クエリの項目一つ（上の二行と同じ） |
| `@http.bodyObj` のフィールド | 本文が、その model の JSON（「値の JSON」）。フィールドの名前では包まない。`Content-Type: application/json` |

`<名前>` は、デコレータの引数。省いていれば、フィールドの名前（`docs/vocab.md`「`http` の語彙」）。

**要求に項目がないときに、サーバーがどう読むかは、フィールドのデコレータで決まる。**

| フィールド | 項目を送らないと |
|---|---|
| `@http.required` | op は呼ばれず、400（「op を呼ぶ前の失敗」）。呼ぶ側は、必ず送る |
| `@http.default(v)` | サーバーが、v として読む。呼ぶ側は、v でよければ、送らなくてよい |
| どちらもない | サーバーは、零値として読む（省略可能なフィールドは、値がない） |

値を入れるのは、要求を読むサーバーで、呼ぶ側は、`@http.default` の値を自分では入れない。

### 値の JSON

| 型 | JSON |
|---|---|
| `string` | 文字列 |
| `int` | 数（整数）。64 ビットの範囲。2^53 を超える値は、数を倍精度で持つ言語では正確に読めない |
| `float` | 数 |
| `boolean` | `true` / `false` |
| `datetime` | RFC 3339 の文字列（小数部は 0〜9 桁、時刻帯は `Z` か `±hh:mm`） |
| `date` | `2026-11-21` の形の文字列 |
| `time` | `09:30:00` の形の文字列。秒より細かい部分は、小数部（書くときは、末尾の 0 を除く。読むときは、0〜9 桁） |
| `duration` | 数（整数のナノ秒） |
| scalar | 元の型の JSON |
| model | オブジェクト。キーはフィールド名（仕様に書いたまま）。並びはフィールドの順 |
| `optional(T)` のフィールド | 値がなければ、キーを省く。読む側は、キーがないことと `null` を、どちらも「ない」と読む |
| `array(T)` | 配列。読む側は、`null` も空の配列と読む（op の結果そのものが空の配列なら、必ず `[]` を返す。model の中の空の配列は、`[]` か `null`） |
| インデックスの model への `ref` | オブジェクト。キーは、キーの型の文字列 |
| union（`arms`） | アームの値の JSON、そのまま。どのアームかは、書かない（下の「union」） |

読む側は、知らないキーを無視する。

### union

`docs/decisions.md`「決めたこと」399。union（`arms`）の値は、**アームの値の JSON を、そのまま**書く。どのアームかを言うキーは、足さない。

- **読む側は、構造から、アームを決める**: JSON のオブジェクトに、そのアームの**決め手**（下）のキーが、一つでもあるアーム。決め手のあるアームが、ちょうど一つでなければ（どのアームの決め手もない。二つ以上のアームの決め手がある。JSON が、オブジェクトでない）、読めない値。要求の本文なら、`body: invalid JSON`（「op を呼ぶ前の失敗」）。
- **書く側は、迷わない**: 値が、自分のアームを持っている。
- **省略可能な union**（`U?`）は、`optional` の行のとおり（値がなければ、キーを省く。`null` も「ない」と読む）。

**通信に出せる union** は、次の二つを満たすもの。満たさない union が、本文、結果、`@http.status` を持つ例外の引数の型（の中）にあれば、HTTP-5。

1. アームの型が、どれも、フィールドを持つ model への `ref`（その場で書いた model、別の名前空間の model を含む。インデックスの model は、含まない）。
2. アームごとに、**決め手**が、一つ以上ある。決め手は、そのアームの model の、省略可能でないフィールドのうち、ほかのどのアームの model の、どのフィールド（省略可能なものを含む）とも、名前が違うもの。

- 縛るのは、通信に出る union だけ。通信に出ない union（画面の状態の union など）は、同じ構造のアームを、名前で分けてよい: プロセスの中の値は、自分のアームを持っている。
- 条件は、仕様だけから決まる。見分ける必要があるかは、受け取った側が判断し、要るときに、`classify` を定義して、型で分ける（`docs/check.md`「ケースの判定」の、型で決まる分類）。

### 成功の応答

| 返す値 | ステータス | 本文 |
|---|---|---|
| ある | 200 | その JSON。`Content-Type: application/json`。空の配列は値で、`[]` |
| ない（戻り値のない op。省略可能な戻り値で、値がない） | 204 | なし |

- 一つの op が、呼び出しによって 200 も 204 も返す（省略可能な戻り値）。op の型では決まらず、返す値で決まる。`null` は返さない。
- 空の配列は `[]`、空の、インデックスの model は `{}` を返す（値がある）。値がないことと、空であることを、分けて持てない言語のトランスパイラは、省略可能な配列と、省略可能な、インデックスの model（`T[]?`、`Attrs?`）を返す op を、自分の診断で断る（`go-http` は GOHTTP-16: `docs/plugin-go-http.md`「対象」）。

### 失敗の応答

本文は、どれも `Content-Type: application/json` の、例外の形:

```json
{ "error": "<例外の FQN>", "value": { "<引数の名前>": <その値の JSON>, … } }
```

- `value` は、**例外の引数の名前をキーにしたオブジェクト**（`exception LimitExceeded(retryAfter: duration);` なら `{"error":"rate.LimitExceeded","value":{"retryAfter":30000000000}}`）。キーの並びは、宣言の引数の順。値の形は「値の JSON」で、省略可能な引数で値がなければ、キーを省く。引数が一つでも、オブジェクトで包む。
- `value` は、引数のない例外にはない。

| 場合 | ステータス | 本文 |
|---|---|---|
| op が、`@http.status(n)` を持つ例外を投げた | n | `{"error":"<FQN>"}`。引数を持つ例外なら `value` を足す |
| op を呼ぶ前の失敗（下） | 400 | `{"error":"http.BadRequest","value":{"message":…,"violations":[…]}}` |
| それ以外（`@http.status` を持たない例外、保存先のエラー、中断を含むほかのエラー） | 500 | `{"error":"internal"}`（中身を出さない。`internal` は例外の FQN ではない） |

- 例外の FQN は、その例外を宣言した名前空間の名前を含む（`type.Unauthorized`）。例外を別の名前空間に移すと、通信の上の名前が変わる。
- 経路にない要求と、メソッドの合わない要求への応答の本文は、決めない（ステータスは 404 と 405。本文は、サーバーの実装のもの: `go-http` は `docs/plugin-go-http.md`「出力」）。

### op を呼ぶ前の失敗

op を呼ぶ前の失敗は、`http` の語彙の例外 `http.BadRequest`（`docs/vocab.md`「同梱する語彙」）で伝える。`value` は、その二つの引数: `{"message": string, "violations": [{"path": string, "constraint": string}]}`（`violations` は、空でも `[]`）。op は呼ばない。

| 場合 | `message` | `violations` |
|---|---|---|
| 要求を入力に読めない（本文が JSON として読めない・型が違う、クエリが読めない、`@http.required` の付いた項目がない） | `<場所>: <理由>` の決まった文言: `body: invalid JSON`、`query <名前>: invalid int`（`float`、`boolean`）、`<場所> <名前>: missing`（場所は `header`、`query`、`body`） | `[]` |
| 読んだ入力が制約に合わない（サーバーが、入力の制約を確かめる設定のときだけ。`go-http` では `validate = true`: `docs/plugin-go-http.md`「制約の検査」） | `invalid input` | 違反の一覧。確かめた順 |

- 違反の `path` は、**通信の上の場所**と、その中のパス（`body.email`、`body.lines[1].quantity`、`query.page`）。通信の上の場所は、項目の形が `header.<名前>`、`query.<名前>`、`body.<名前>`、全体の形が `header`、`query`、`body`。入力の model のフィールド名（通信に現れない名前）は出さない。`constraint` は、`valid` の語彙のデコレータの名前（`min`、`length`、…）。
- 読めない要求が先で、次に制約の検査、その後に op。認証を op の中で確かめる仕様では、トークンのない要求でも、本文が制約に合わなければ 400 が先になる。

## 補う値と制約

`@http.default` の値は、そのフィールドの制約（`@valid.*`。フィールドに付いたものと、型の scalar に付いたもの）で確かめる。合わなければ HTTP-15。書いたものどうしの矛盾なので、実行時の検査（合わなければ、その項目のない要求がいつも 400 になる）には任せない。サーバーが、入力の制約を確かめる設定かどうかに、よらない。確かめるのは `plugin/govalid` の、値一つを制約で確かめる関数（`docs/packages.md`「`plugin/govalid`（公開）」）で、`go-cli` の `@cli.default` も同じ関数を使う（`docs/plugin-go-cli.md`「補う値と制約」）。

## 診断

`read` の応答の `errors` で返す（`docs/plugin-protocol.md`「read」）。位置は、表に書いた宣言の FQN。warning は、返さない。

| ID | 重さ | 意味 |
|---|---|---|
| HTTP-1 | error | `@http.get` / `@http.post` の付いた op に `export` がない。位置は op |
| HTTP-2 | error | 経路の op の引数が、0 個でも、フィールドを持つ model 一つでもない（インデックスの model は、入力の model にできない）。位置は op |
| HTTP-3 | error | 入力の model のフィールドが、要求のどこから読むかを言う六つのデコレータ（`@http.header` / `@http.query` / `@http.body` / `@http.headerObj` / `@http.queryObj` / `@http.bodyObj`）のどれも持たない、または二つ以上持つ。位置は model |
| HTTP-4 | error | ヘッダかクエリから読むフィールド（全体の形なら、その model のフィールド）の型が受け付けられない（「対象」の表）。位置は、そのフィールドを持つ model（全体の形なら、全体の形で受け取る model） |
| HTTP-5 | error | 本文、結果、`@http.status` を持つ例外の引数の型（の中）に、通信に出せない union がある（「通信の形」の「union」の二つの条件）。メッセージに、union と、満たさないアームと、理由（アームの型が、フィールドを持つ model でない。決め手がない）を示す。位置は op |
| HTTP-6 | error | `@http.get` の op の入力が、本文のデコレータ（`@http.body`、`@http.bodyObj`）のフィールドを持つ。位置は op |
| HTTP-7 | error | パスが `/` で始まらない、または `{` か `}` を含む。位置は op |
| HTTP-8 | error | 一つの名前空間の中に、同じメソッドとパスの経路が二つある。位置は後ろの op |
| HTTP-9 | error | 全体の形（`@http.headerObj` / `@http.queryObj` / `@http.bodyObj`）を付けたフィールドの型が、フィールドを持つ model でない（省略可能な model、配列、インデックスの model を含む。「対象」）。位置は model |
| HTTP-10 | error | 入力の model の一つの場所に、全体の形が二つ以上ある、または、全体の形と項目の形の両方がある（「対象」）。位置は model |
| HTTP-11 | error | `@http.required` か `@http.default` の付いたフィールドが、項目の形（`@http.header` / `@http.query` / `@http.body`）を持たない。入力の model のフィールドと、全体の形で受け取る model のフィールドを見る（「対象」）。位置は、そのフィールドを持つ model |
| HTTP-12 | error | `@http.required` か `@http.default` の付いたフィールドの型が、省略可能（`T?`）。見るフィールドと位置は HTTP-11 と同じ |
| HTTP-13 | error | 一つのフィールドに、`@http.required` と `@http.default` の両方がある。見るフィールドと位置は HTTP-11 と同じ |
| HTTP-14 | error | `@http.default` のリテラルが、フィールドの型（scalar は元の核の型）に渡せない（「対象」）。メッセージに、フィールド、リテラル、型を示す。見るフィールドと位置は HTTP-11 と同じ |
| HTTP-15 | error | `@http.default` の値が、フィールドの制約（`@valid.*`）に合わない（「補う値と制約」）。メッセージに、フィールド名と、合わなかった制約を入れる。リテラルが型に渡せないフィールド（HTTP-14）は、見ない。見るフィールドと位置は HTTP-11 と同じ |

- **どの診断も、書いたものの整合の検査**: デコレータが言ったことと、model と op の宣言が食い違っていれば、error にする。出し方を、型に合わせて変える言語のトランスパイラは、ない（`docs/requirements.md`「出力を推論しない」）。
- **HTTP-* は、`go-http` の診断から移したもの。** どの GOHTTP-n が、どの HTTP-n になったかの表は `docs/plugin-go-http.md`「診断」の「欠番」。
- 仕様が、検査の前提を欠くとき（要求に `spec` がない）は、診断にせず、異常終了する（`proc.Crashed`。`docs/plugin-protocol.md`「起動」）。
