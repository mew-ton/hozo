# 名前の解決

## この文書が決めること

表面の構文に書かれた名前（`QualifiedName`、値の位置の `Path`、`Ident`。`docs/grammar.md`「識別子」）が、どの宣言・引数・束縛を指すかを決める規則。設計書 §3.2 の規則を手続きにしたもの。結果は `docs/ir.md` の FQN になる。解決できなければこの文書の「診断」の `RES-*`。

## スコープ

内側から外側へ、次のスコープがある。外側を自動で探すのは「現在の名前空間 → グローバル」の一段だけ（§3.2「外側の名前空間を自動で探す仕組みは持たない」）。

| スコープ | 中身 | 有効な範囲 |
|---|---|---|
| 配線 | `const` で束縛した名前 | その行より下の行（§9「名前は使う前に上で定義する」） |
| op の引数 | `OpParam` の名前 | その op の本体と、その op に付いたデコレータの引数のうち値を取るもの（`@cache(key: ["orders", query])`。§11.1） |
| デコレータの引数 | `Param` の名前 | そのデコレータの宣言の `throws` / `catches`（`catches error recovers`。§4.2） |
| 現在の名前空間 | その名前空間の宣言（併合後） | その名前空間のブロックの中。親子は別（§3.2） |
| グローバル | `namespace` の外の宣言 | すべて |
| ルート | 名前空間の名前 | 修飾の先頭としてだけ |

## 手続き

名前 `a.b.c`（セグメントの列）を位置 P で解決する。位置が受け付ける種類は「位置ごとに受け付ける種類」の表。

1. **先頭のセグメント `a` を決める。** 次の順で最初に当たったもの。
   1. P が配線の中で、`a` がその行より上で束縛された名前、または op の引数名 → 値の参照（`Atom.name`）。
   2. P がデコレータの宣言の `throws` / `catches` の中で、`a` がそのデコレータの引数名 → `$param:a`。
   3. P が op に付いたデコレータの引数の値で、その引数の `Param.type` が `type`（`any ...` でない）で、`a` がその op の引数名 → `$param:a`。`any ...` の引数ではこの段を飛ばす（§11.2 の `@page.route(from: query)` は状態 `browser.query` を指すため）。
   4. セグメントが二つ以上あり、`a` がルートの名前空間の名前 → 名前空間のパス。以降のセグメントは名前空間の子か、その名前空間の宣言。セグメントが一つだけのとき名前空間は候補にならない（`@db` はグローバルの `db`。§3.2）。
   5. `a` が現在の名前空間の宣言 → その宣言。
   6. `a` がグローバルの宣言 → その宣言。
   7. どれでもない → `RES-1`。
2. **残りのセグメントを順に辿る。** 直前に決まったものの種類で、次のセグメントが指せるものが決まる。

   | 直前 | 次のセグメントが指すもの |
   |---|---|
   | 名前空間 | 子の名前空間、またはその名前空間の宣言。両方あれば `RES-2`。どちらもなければ `RES-1` |
   | 値の参照（束縛・引数） | その値の型のフィールド（型が model、または model の `optional`）。それ以外の型なら `RES-3` |
   | `classify` | ケース名 → 絞り込まれた型の元（`Type.case`）。`default` は指せない |
   | `union`（`arms`） | アーム名 → `ArgValue.variant` |
   | `state` | `post` / `put` / `delete` → 状態への操作（`effect ... on`、`any effect on` の位置でだけ） |
   | それ以外 | `RES-3` |

3. **位置が受け付ける種類か確かめる。** 表にない種類なら `RES-4`。

`bind s to ns.*` の `ns` は、常に名前空間として解決する（セグメントが一つでも 1.4 を使う）。

## 位置ごとに受け付ける種類

| 位置 | 受け付けるもの |
|---|---|
| `classify C of ...` の対象 | 一つで型を指せば値の分類（下の「型」と同じ）。すべてが現在の名前空間の `state`（基底の状態）なら状態の分類。型と状態の混在、状態でないものを含む並びなどは CLS-3（`docs/check.md`「classify / match」）。対象が一つで型でも状態でもなければ RES-4 |
| 型（フィールド、引数、戻り値、`scalar extends`、`state` の要素） | `model`、`scalar`、`union`（`arms`）、`classify` のケース（`C.Case<T>` の形でだけ）。核の型は予約語なので解決しない |
| `exception X: T` の `T` | `model` |
| ユニオンのメンバー `X;` | `exception`、`effect`、`union`（`set`） |
| `effect e on s.op` の `s` | 現在の名前空間の `state`。別の名前空間の状態なら `RES-5` |
| `effect e on X: A -> B` の `X` | 現在の名前空間の、状態を対象にした `classify`、または組み込みの分類を持つ `state`（`list` / `nullable`）。別の名前空間のものなら `RES-5`。値を対象にした `classify` なら RES-4 |
| 遷移のケース名 `A`、`B` | `X` が `classify` ならそのケース。`X` が状態なら `Empty` / `HasItems` |
| `any effect on s.op` の `s` | どの名前空間の `state` でも |
| `throws` の要素 | `exception`、`union`（`set` で要素が例外）、デコレータの宣言の中なら `any exception` の引数 |
| `catches` の要素 | `throws` と同じ |
| `halts e` の `e` | `effect`、デコレータの宣言の中なら `any effect` の引数 |
| `effects` の要素 | `effect`、`union`（`set` で要素が効果） |
| `@name`（`@external` を除く。`docs/grammar.md`「予約語」） | `decorator`。付ける先の種類との照合は DEC-1 |
| デコレータの引数の値 | `Param.type` による（`docs/types.md`「デコレータの引数」） |
| `match x by C` の `C` | 現在の名前空間の、値を対象にした `classify`（NS-4） |
| `match s by list` / `by nullable` の `s` | 現在の名前空間の `state` |
| `match by C` の `C` | 現在の名前空間の、状態を対象にした `classify` |
| `match` のアームのケース名 | その分類のケース。組み込みの分類なら `Empty` / `HasItems` |
| 呼び出しの op | `op` |
| 呼び出しの引数の `Atom.name` | 束縛、引数、そのフィールドのパス |
| `bind s to ns.*` の `s` | 現在の名前空間の `state`。`ns` は名前空間 |
| `model P is U` の `U` | `model` |
| `@param x` | その op（またはデコレータ）の引数名 |
| `@throws X` | その op の `Signature.exceptions` に含まれる例外か、その op に付いた `external` なデコレータの `throws` の例外（外から見たときだけ起きる例外も書ける。DOC-1 の手続きは `docs/check.md`「名前空間」） |
| `@see X` | どの宣言でも |

## 名前空間の併合と重複

- 同じ FQN の名前空間は一つにする（§3.2）。
- 同じ名前空間に同じ名前の宣言が二つあれば `RES-6`。種類が違っても重複（`model X` と `op X` は共存できない）。正規化で合成する model（`docs/ir.md`「正規化」）は親の名前の下に置くので衝突しない。
- グローバルに同じ名前の宣言が二つあれば `RES-6`。語彙どうし、または語彙とユーザーの宣言の衝突も同じ。両方が語彙なら NS-3（`docs/check.md`）として報告する。
- 名前空間の名前と、グローバルの宣言の名前は別の空間（`@db` と `db.key`。§3.2）。衝突にしない。
- 現在の名前空間の宣言がグローバルの宣言を隠す（手続きの 5 が 6 より先）。隠すこと自体は診断しない。

語彙の `.hozo` の読み込み方は `docs/vocab.md`「読み込み」。解決では、ユーザーのファイルと同じ規則で扱う。

## 診断

| ID | 重さ | 意味 | 位置 |
|---|---|---|---|
| RES-1 | error | 名前が見つからない。同じ種類で編集距離 2 以内の名前、および修飾なしで別の名前空間に同じ名前があればその FQN を、候補として `Data.candidates` に入れメッセージに示す | その名前 |
| RES-2 | error | 名前空間の子と宣言の両方に当たって曖昧 | その名前 |
| RES-3 | error | 直前のものから次のセグメントを辿れない | 辿れなかったセグメント |
| RES-4 | error | その位置で受け付けない種類のものを指している | その名前 |
| RES-5 | error | `effect ... on` が別の名前空間の状態を指している | その名前 |
| RES-6 | error | 同じスコープに同じ名前の宣言が二つある。相手の位置を `Related` に示す | ユーザーのファイルの側。両方ユーザーのファイルなら `docs/ir.md`「原則」の順で後の方 |
