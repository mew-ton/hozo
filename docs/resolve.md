# 名前の解決

## この文書が決めること

表面の構文に書かれた名前（`QualifiedName`、値の位置の `Path`、`Ident`。`docs/grammar.md`「識別子」）が、どの宣言・引数・束縛・状態を指すかを決める規則と、その手続き（出どころは設計書 §3.2）。結果は `docs/ir.md` の FQN になる。解決できなければこの文書の「診断」の `RES-*`。

## スコープ

内側から外側へ、次のスコープがある。外側を自動で探すのは「現在の名前空間 → グローバル」の一段だけ（§3.2「外側の名前空間を自動で探す仕組みは持たない」）。

| スコープ | 中身 | 有効な範囲 |
|---|---|---|
| 配線 | `val` の名前と、`for` の変数 | `val` は、宣言したブロックの、宣言より下（中のブロックを含む）。`for` の変数は、その `for` のブロックの中（`docs/check.md`「値の入れ物」の「見える範囲」。§9「名前は使う前に上で定義する」） |
| op の引数 | `OpParam` の名前 | その op の本体と、その op に付いたデコレータの引数のうち値を取るもの（`@cache(key: ["orders", query])`。§11.1）。`exception`、`effect`、`read` の引数の名前は、どのスコープにも入らない（本体を持たない。呼び出しの引数を位置で対応付けるのと、`@param` に使う） |
| デコレータの引数 | `Param` の名前（残りの引数を含む） | そのデコレータの宣言の `throws` / `catches` / `reads` / `effects`（`catches error recovers`。§4.2。`reads counter`、`effects targets`） |
| 現在の名前空間 | その名前空間の宣言（併合後）。状態は、配線の値の位置では値として参照できる（「位置ごとに受け付ける種類」） | その名前空間のブロックの中。親子は別（§3.2） |
| グローバル | `namespace` の外の宣言 | すべて |
| ルート | 名前空間の名前 | 修飾の先頭としてだけ |

## 手続き

名前 `a.b.c`（セグメントの列）を位置 P で解決する。位置が受け付ける種類は「位置ごとに受け付ける種類」の表。

1. **先頭のセグメント `a` を決める。** 次の順で最初に当たったもの。
   1. P が配線の中で、`a` が、そこで見えている `val` の名前、`for` の変数、または op の引数名 → 値の参照（`Atom.name`）。代入が済んでいるか（WIRE-10）は、解決の後で、検査が見る（`docs/check.md`「値の入れ物」の「代入が済んでいるか」）。
   2. P がデコレータの宣言の `throws` / `catches` / `reads` / `effects` の中で、`a` がそのデコレータの引数名 → `$param:a`。
   3. P が op に付いたデコレータの引数の値で、その引数の `Param.type` が `type`（`any ...` でない）で、`a` がその op の引数名 → `$param:a`。`any ...` の引数ではこの段を飛ばす（§11.2 の `@page.route(from: query)` は状態 `browser.query` を指すため）。
   4. セグメントが二つ以上あり、`a` がルートの名前空間の名前 → 名前空間のパス。以降のセグメントは名前空間の子か、その名前空間の宣言。セグメントが一つだけのとき名前空間は候補にならない（`@localStorage` はグローバルのデコレータ `localStorage`。§3.2）。
   5. `a` が現在の名前空間の宣言 → その宣言。
   6. `a` がグローバルの宣言 → その宣言。
   7. どれでもない → `RES-1`。名前が、なくした核の型の名前（`Time`、`Duration`。`docs/grammar.md`「決めたこと」）なら、メッセージに、今の語（`datetime`、`duration`）を足す。

   配線の値の位置で状態の名前が`val`、`for` の変数、引数と同じなら、段 1 が先なので、そちらを指す（状態を隠す。診断しない。`docs/check.md`「状態の参照」）。
2. **残りのセグメントを順に辿る。** 直前に決まったものの種類で、次のセグメントが指せるものが決まる。

   | 直前 | 次のセグメントが指すもの |
   |---|---|
   | 名前空間 | 子の名前空間、またはその名前空間の宣言。両方あれば `RES-2`。どちらもなければ `RES-1` |
   | 値の参照（`val`・`for` の変数・引数。配線の値の位置では、現在の名前空間の `state` も） | その値の型のフィールド（型が model、または model の `optional`）。それ以外の型なら `RES-3`。`match` のアームの中では、絞り込まれた型から辿る（`docs/types.md`「アームの中の対象の型」） |
   | `classify` | ケース名 → 絞り込まれた型の元（`Type.case`）。デコレータの引数の値の位置では、分類のケース（`ArgValue.case`） |
   | `union`（`arms`） | アーム名 → `ArgValue.variant` |
   | `state`（値の位置でないとき） | `post` / `put` / `delete` → 状態への操作（`effect ... on`、`any effect on`、`effects` の要素、配線の呼び出しの位置でだけ） |
   | それ以外 | `RES-3` |

3. **位置が受け付ける種類か確かめる。** 表にない種類なら `RES-4`。

`bind s to ns.*` の `ns` は、常に名前空間として解決する（セグメントが一つでも 1.4 を使う）。

## 位置ごとに受け付ける種類

| 位置 | 受け付けるもの |
|---|---|
| `classify C of ...` の対象 | `never` なら、対象のない分類（予約語で、解決しない。`docs/check.md`「分類」の「対象のない分類」）。一つで型を指せば値の分類（下の「型」と同じ）。一つで `op` を指せば op の分類（どの名前空間の op でも。`export` は要らない。値を返さない op は CLS-4）。すべてが現在の名前空間の `state`（基底の状態）なら状態の分類。型や op と状態の混在、状態でないものを含む並びなどは CLS-3（`docs/check.md`「classify / match」）。対象が一つで、型でも op でも状態でもなければ RES-4。対象が形の語か `?` / `[]` を持つ型（`nullable<User>`、`User?`）なら、型として読む |
| ケースの `X as T` の `X` | その分類の対象と同じもの: 値の分類なら型（`subject` の型と等しいこと）、op の分類ならその `op`、状態の分類なら対象の `state` のどれか。解決は対象と同じ規則で行い、対象でなければ CLS-5（`docs/check.md`「classify / match」） |
| ケースの `X as T` の `T` | 下の「型」と同じ。絞り込める型かどうかは CLS-6。残りのケースの `X as else` の `else` と、ない側のケースの `X as none` の `none` は予約語で、解決しない（`X` は上の行と同じ） |
| 型（フィールド、引数、戻り値、`scalar extends`、`state` の型、`as` の後ろ） | `model`、`scalar`、`union`（`arms`）、核の型と形の語は予約語なので解決しない。`classify` と、そのケースは、型にならない（RES-4）: 絞り込んだ型は、`T on C.K` と書く（下の行） |
| 絞り込んだ型のケース `C.K`（`T on C.K`。`docs/grammar.md`「型」の `OnType`） | 最後の要素 `K` を除いた名前 `C` を、`classify` として解決する（どの名前空間のものでもよく、別の名前空間のものは修飾して書く）。`classify` でなければ RES-4。`C` は値の分類か op の分類で、状態の分類と、対象のない分類なら RES-4。`K` が `C` のケースでなければ RES-3。並べたケースが一つの分類のものか、同じケースが二度ないか、`T` が対象の型に渡せるかは TYPE-12（`docs/types.md`「型の種類」の「絞り込んだ型」） |
| ユニオンのメンバー `X;` | `exception`、`effect`、`union`（`set`） |
| `exception`、`effect`、`read` の引数の型、`read` の結果の型 | 上の「型」と同じ |
| `effect fn e(…): effects s.op` の `s` | 現在の名前空間の `state`。別の名前空間の状態なら `RES-5` |
| `read fn r(…): T reads s` の `s` | 現在の名前空間の `state`（基底の状態）。別の名前空間の状態なら `RES-5`。状態でなければ（状態の分類を含む）RES-4（`docs/check.md`「read の宛先」） |
| `effect fn e(…): effects X as A -> B` の `X` | 現在の名前空間の、状態を対象にした `classify`、または組み込みの分類を持つ `state`（`list` / `nullable`）。別の名前空間のものなら `RES-5`。値を対象にした `classify` なら RES-4 |
| 遷移のケース名 `A`、`B` | `X` が `classify` ならそのケース。`X` が状態なら、その形の、組み込みの分類のケース（`docs/check.md`「状態の形」の表） |
| 行の遷移のケース `C.K`（`effect fn e(…): effects s.op as C.K`） | 最後の要素 `K` を除いた名前 `C` を、`classify` として解決する（どの名前空間のものでもよく、別の名前空間のものは修飾して書く）。`classify` でなければ RES-4。`K` は、その分類のケース。`C` が行の分類か（値の分類で、対象の型が状態の要素の型か）と、`K` がケースかは STATE-7（`docs/check.md`「行の遷移」の「結びつき」） |
| `any effect on s.op` の `s` | どの名前空間の `state` でも |
| `throws` の要素 | `exception`、`union`（`set` で要素が例外）、デコレータの宣言の中なら `any exception` の引数 |
| `catches` の要素 | `throws` と同じ |
| `halts e` の `e` | `effect`、デコレータの宣言の中なら `any effect` の引数 |
| `effects` の要素 | 名前で書いた要素: `effect`、`union`（`set` で要素が効果）。直に書いた要素: `state`（基底の状態。どの名前空間のものでも解決する）から辿った `post` / `put` / `delete`（下の「`effects` の要素の読み分け」）。デコレータの宣言の中なら `any effect` の引数（残りの引数でもよい）も。操作を付けない `state` と `classify` は RES-4（分類の遷移は直に書けない）。操作が状態の形になければ STATE-1、葉の op が節を書けば STATE-5、配線の op に書いたものが計算と食い違えば EFF-2（`docs/check.md`「状態と効果」） |
| `reads` の要素 | 名前で書いた要素: `read`。直に書いた要素: `state`（基底の状態）。どちらも、どの名前空間のものでも解決する。デコレータの宣言の中なら `any state` の引数（残りの引数でもよい）も。どれでもなければ RES-4（状態の分類も書けない）。同じ名前空間に同じ名前の `read` と `state` は宣言できない（RES-6）ので、名前がどちらを指すかは一つに決まる。葉の op が節を書けば STATE-5、配線の op に書いたものが計算と食い違えば READS-2（`docs/check.md`「状態と効果」） |
| `@name`（核の印 `@external` と `@repeatable` を除く。`docs/grammar.md`「予約語」） | `decorator`。名前の最後の要素は予約語でもよい（`@db.list`。`docs/grammar.md`「識別子」の `DecoratorRef`）。付ける先の種類との照合は DEC-1 |
| デコレータの引数の値 | `Param.type` による（`docs/types.md`「デコレータの引数」）。分類のケースを受け取る引数（`any case`、`any case of never`、`any case of Actor`）には、分類のケース（`Actor.Customer`。どの名前空間の分類でもよく、別の名前空間のものは、修飾して書く）。`any op` の引数に渡した op が、デコレータを付けた宣言とは別の名前空間の、`export` のない op なら NS-5 |
| デコレータの宣言の、分類のケース（`case of 名前`。`docs/grammar.md`「decorator の宣言」の `CaseKind`）の、`of` の後ろの名前 | 型（上の「型」と同じ）か、`classify`（どの名前空間のものでもよく、別の名前空間のものは、修飾して書く）。`classify` なら、その分類のケース。型なら、対象が、その型の分類のケース。どちらでもなければ（op、状態など）RES-4 |
| `match (x by C)` の `C` | `classify`（値の分類、op の分類、状態の分類。対象のない分類なら MATCH-7）。どの名前空間のものでもよく、別の名前空間のものは修飾して書く。対象の有無と分類の種類の照合は MATCH-7 |
| `match (by C)` の `C` | 同上。状態の分類が別の名前空間のものなら `RES-5` |
| `match (x by list)` / `(x by nullable)` の `list` / `nullable` | 解決しない（標準の分類の名前。予約語） |
| `match` のアームのケース名 | その分類のケース。標準の分類なら、`docs/check.md`「分類」の「標準の分類」の表のケース |
| 配線の呼び出しの名前（`Call` の `QualifiedName`） | `op`、`read`、`effect`、現在の名前空間の `state`（基底の状態）から辿った `post` / `put` / `delete`（下の「呼び出しの読み分け」）。別の名前空間の、`export` のない op なら NS-5、別の名前空間の `read` か `effect` なら NS-6（`docs/check.md`「名前空間」）、別の名前空間の状態の操作なら RES-5。効果の `union`、操作を付けない `state`、`classify` は RES-4 |
| 配線の値の位置の `Path`（呼び出しの引数、レコードリテラルの値、`val`・`=`・`collect`・`return` の値、`match` の対象、アームの本体の値、`for` の頭の並び） | `val`、`for` の変数、引数、現在の名前空間の `state`（基底の状態。修飾して書いても同じ）と、そのフィールドのパス。`val`、`for` の変数、引数は `Atom.name`、状態は `Atom.state` になる（`docs/ir.md`「配線」）。別の名前空間（かグローバル）の `state` に解決できたら `RES-5`。それ以外の宣言なら RES-4 |
| 値を入れる文の左（`x = 式`）、集める文の左（`xs collect 式`） | そこで見えている `val`（「スコープ」の「配線」）。見えている名前でなければ `RES-1`。引数や、`for` の変数を指していれば、WIRE-11（値を入れる文）か WIRE-14（集める文）（`docs/check.md`「値の入れ物」「繰り返し」） |
| アームの本体の `throw E`、`throw E(…)` の `E` | `exception`（どの名前空間のものでも）。ユニオン（`set`）とデコレータの引数は RES-4 |
| `bind s to ns.*` の `s` | 現在の名前空間の `state`。`ns` は名前空間 |
| `model D extends B` の `B` | `model`（その場で書いた model は名前を持たないので書けない）。循環は TYPE-10 |
| `override f` の `f` | 元の model のフィールド（`docs/types.md`「継承した model」の「フィールド」で作った後の並び）。なければ TYPE-10 |
| `@param x` | その宣言（op、デコレータ、`exception`、`effect`、`read`）の引数名 |
| `@throws X` | その op の `Signature.exceptions` に含まれる例外か、その op に付いた `external` なデコレータの `throws` の例外（外から見たときだけ起きる例外も書ける。DOC-1 の手続きは `docs/check.md`「名前空間」） |
| `@see X` | どの宣言でも |

### `effects` の要素の読み分け

`effects` の要素 `a.b.….z`（`docs/grammar.md`「op」の `EffectElem`）は、ほかの名前と同じ「手続き」で一度だけ解決し、行き着いたものの種類で、名前で書いた要素か、直に書いた要素かが決まる。

| 行き着いたもの | 読み方 |
|---|---|
| `effect`、効果の `union` | 名前で書いた効果 |
| `state` から `post` / `put` / `delete` を辿ったところ（手続き 2 の表） | 直に書いた、その状態の組み込みの効果 |

見分けるための別の規則は持たない。二通りに読めそうな名前は、手続きの順で一つに決まる。

- セグメントが一つの名前（`effects post`）は、いつも宣言の名前（効果 `post`）。状態への操作は、状態の名前と操作の、二つ以上のセグメントを要る。
- `users.post` の `users` が、ルートの名前空間の名前でも、現在の名前空間の状態の名前でもあるとき、名前空間が先（手続き 1.4 が 1.5 より先）: 名前空間 `users` の効果 `post` を指し、なければ RES-1。状態を指すには、修飾して書く（`store.users.post`）。
- 名前空間 `ns` が、子の名前空間 `users` と状態 `users` の両方を持つとき、`ns.users.post` は RES-2（手続き 2 の表の「名前空間」の行）。

### 呼び出しの読み分け

配線の呼び出しの名前 `a.b.….z`（`docs/grammar.md`「配線」の `Call`）は、ほかの名前と同じ「手続き」で一度だけ解決し、行き着いたものの種類で、何を呼ぶかが決まる。

| 行き着いたもの | 読み方 |
|---|---|
| `op` | op の呼び出し |
| `read` | `read` の呼び出し |
| `effect` | 効果（宣言）の呼び出し |
| `state` から `post` / `put` / `delete` を辿ったところ（手続き 2 の表） | その状態の組み込みの効果を、直に呼ぶ |

- 手続きの順は「`effects` の要素の読み分け」と同じ: セグメントが一つの名前（`post(x)`）は、いつも宣言の名前。`users.post(x)` の `users` がルートの名前空間の名前でもあれば、名前空間が先。
- 呼び出しの名前の先頭が、そこで見えている `val`、`for` の変数か、op の引数の名前と同じなら、手続き 1.1 が先で、値を指す（値は呼べないので、`users.post(x)` なら RES-3、`users(x)` なら RES-4）。状態と同じ名前の引数を持つ配線から、その状態の操作を呼ぶには、修飾して書く（`store.users.post(x)`）。
- 呼び出しの位置は、配線の値の位置ではない: 状態の名前の次のセグメントは、その値のフィールドではなく、操作。

## 名前空間の併合と重複

- 同じ FQN の名前空間は一つにする（§3.2）。
- 同じ名前空間に同じ名前の宣言が二つあれば `RES-6`。種類が違っても重複（`model X` と `op X` は共存できない）。正規化で合成する model（`docs/ir.md`「正規化」）は親の名前の下に置くので衝突しない。
- グローバルに同じ名前の宣言が二つあれば `RES-6`。語彙どうし、または語彙とユーザーの宣言の衝突も同じ。両方が語彙なら NS-3（`docs/check.md`）として報告する。
- 名前空間の名前と、グローバルの宣言の名前は別の空間（§3.2 の例は、グローバルのデコレータ `db` と、名前空間 `db` の `db.key`）。衝突にしない。
- 現在の名前空間の宣言がグローバルの宣言を隠す（手続きの 5 が 6 より先）。隠すこと自体は診断しない。

語彙の `.hozo` の読み込み方は `docs/vocab.md`「読み込み」。解決では、ユーザーのファイルと同じ規則で扱う。

|---|---|---|---|
| RES-1 | error | 名前が見つからない。同じ種類で編集距離 2 以内の名前、および修飾なしで別の名前空間に同じ名前があればその FQN を、候補として `Data.candidates` に入れメッセージに示す | その名前 |
| RES-2 | error | 名前空間の子と宣言の両方に当たって曖昧 | その名前 |
| RES-3 | error | 直前のものから次のセグメントを辿れない | 辿れなかったセグメント |
