# 名前の解決

## この文書が決めること

表面の構文に書かれた名前（`QualifiedName`、`Ident`）が、どの宣言・引数・束縛を指すかを決める規則。設計書 §3.2 の規則を手続きにしたもの。結果は `docs/ir.md` の FQN になる。解決できなければ診断 `RES-*`（`docs/check.md`）。

## スコープ

内側から外側へ、次のスコープがある。外側を自動で探すのは「現在の名前空間 → グローバル」の一段だけ（§3.2「外側の名前空間を自動で探す仕組みは持たない」）。

| スコープ | 中身 | 有効な範囲 |
|---|---|---|
| 配線 | `const` で束縛した名前 | その行より下の行（§9「名前は使う前に上で定義する」） |
| op の引数 | `OpParam` の名前 | その op の本体と、その op に付いたデコレータの引数（`@cache(key: ["orders", query])`。§11.1） |
| デコレータの引数 | `Param` の名前 | そのデコレータの宣言の `throws` / `catches`（`catches error recovers`。§4.2） |
| 現在の名前空間 | その名前空間の宣言（併合後） | その名前空間のブロックの中。親子は別（§3.2） |
| グローバル | `namespace` の外の宣言 | すべて |
| ルート | 名前空間の名前 | すべて（修飾の先頭として） |

## 手続き

名前 `a.b.c`（セグメントの列）を位置 P で解決する。

1. **先頭のセグメント `a` を決める。** 次の順で最初に当たったもの。
   1. P が配線の中で、`a` がその行より上で束縛された名前、または op の引数名 → 値の参照（`Atom.name`）。
   2. P がデコレータの宣言の `throws` / `catches` の中で、`a` がそのデコレータの引数名 → `$param:a`。
   3. P が op に付いたデコレータの引数の中で、`a` がその op の引数名 → `$param:a`。
   4. `a` がルートの名前空間の名前 → 名前空間のパス。以降のセグメントは名前空間の子か、その名前空間の宣言。
   5. `a` が現在の名前空間の宣言 → その宣言。
   6. `a` がグローバルの宣言 → その宣言。
   7. どれでもない → `RES-1`（見つからない）。
2. **残りのセグメントを順に辿る。** 直前に決まったものの種類で、次のセグメントが指せるものが決まる。

   | 直前 | 次のセグメントが指すもの |
   |---|---|
   | 名前空間 | 子の名前空間、またはその名前空間の宣言。両方あれば `RES-2`（曖昧）。どちらもなければ `RES-1` |
   | 値の参照（束縛・引数） | その値の型のフィールド（型が model、または model の `optional`）。それ以外の型なら `RES-3` |
   | `classify` | ケース名 → 絞り込まれた型の元（`Type.case`）。`default` は指せない |
   | `union`（`arms`） | アーム名 → `ArgValue.variant` |
   | `state` | `post` / `put` / `delete` → 状態への操作（`effect ... on`、`any effect on` の位置でだけ） |
   | それ以外 | `RES-3`（辿れない） |

3. **位置が受け付ける種類か確かめる。** 下の表にない種類なら `RES-4`（種類が合わない）。

## 位置ごとに受け付ける種類

| 位置 | 受け付けるもの |
|---|---|
| 型（フィールド、引数、戻り値、`scalar extends`、`state` の要素、`classify of`） | `model`、`scalar`、`union`（`arms`）、`classify` のケース（`C.Case<T>` の形でだけ）。核の型は予約語なので解決しない |
| `exception X: T` の `T` | `model` |
| `effect e on s.op` の `s` | 現在の名前空間の `state`（別の名前空間の状態は書けない。STATE-2 より前に、文法上は FQN を許すが解決で `RES-5` にする） |
| `throws` の要素 | `exception`、`union`（`set` で要素が例外）、デコレータの宣言の中なら `any exception` の引数 |
| `prevents` / `keeps` の要素 | `effect`、`union`（`set` で要素が効果） |
| `catches` の要素 | `throws` と同じ |
| `halts e` の `e` | `effect`、デコレータの宣言の中なら `any effect` の引数 |
| `effects` の要素 | `effect`、`union`（`set` で要素が効果） |
| `@name` | `decorator`。付ける先の種類との照合は DEC-1 |
| デコレータの引数の値 | `Param.type` による（`docs/types.md`「デコレータの引数」） |
| `match x by C` の `C` | 現在の名前空間の `classify`（修飾されていたら、現在の名前空間の FQN と一致するときだけ。NS-4） |
| `match` のアームのケース名 | その `classify` のケース |
| 呼び出しの op | `op` |
| 呼び出しの引数の `Atom.name` | 束縛、引数、そのフィールドのパス |
| `bind s to ns.*` の `s` | 現在の名前空間の `state`。`ns` は名前空間 |
| `model P is U` の `U` | `model` |
| `@param x` | その op（またはデコレータ）の引数名 |
| `@throws X` | その op の `Signature.exceptions` に含まれる例外（DOC-1） |
| `@see X` | どの宣言でも |

## 名前空間の併合と重複

- 同じ FQN の名前空間は一つにする（§3.2）。
- 同じ名前空間に同じ名前の宣言が二つあれば `RES-6`（重複）。種類が違っても重複（`model X` と `op X` は共存できない）。例外: 正規化で合成する model（`OrderPage.Ready`）は親の名前の下に置くので衝突しない。
- グローバルに同じ名前の宣言が二つあれば `RES-6`。標準の語彙どうし、または標準の語彙とユーザーの宣言の衝突も同じ（§3.2「複数のプラグインが同じ名前をグローバルに宣言していたら、組み合わせた時点でエラー」は NS-3 として、出どころがプラグインのときのメッセージにする）。
- 名前空間の名前と、グローバルの宣言の名前は別の空間（`@db` と `db.key`。§3.2）。衝突にしない。
- 現在の名前空間の宣言がグローバルの宣言を隠す（手続きの 5 が 6 より先）。隠すこと自体は診断しない。

## 標準の語彙

`docs/vocab.md` の `.hozo` は、ユーザーのファイルより前に読んだ同じプロジェクトのファイルとして扱う。名前空間（`http` / `valid` など）もグローバル（`db` / `cache`）も、ユーザーの宣言と同じ規則で解決し、ユーザーが同じ名前空間に宣言を足せる（§3.2、§6.5）。

## 診断

| ID | 意味 | 位置 |
|---|---|---|
| RES-1 | 名前が見つからない。候補（編集距離 2 以内の同じ種類の名前）があれば示す | その名前 |
| RES-2 | 名前空間の子と宣言の両方に当たって曖昧 | その名前 |
| RES-3 | 直前のものから次のセグメントを辿れない | 辿れなかったセグメント |
| RES-4 | その位置で受け付けない種類のものを指している | その名前 |
| RES-5 | `effect ... on` が別の名前空間の状態を指している | その名前 |
| RES-6 | 同じスコープに同じ名前の宣言が二つある。両方の位置を示す | 後に出てきた方 |
