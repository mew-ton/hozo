# Go の既定の出力

## この文書が決めること

設計書 §4.3「言語ごとの既定の出力」を Go で具体化する。`internal/emit/golang` がこの文書を写す。入力は `docs/ir.md` の `View`（見る側は出力する名前空間）。出力は `View.config.out` の下のファイル。TS の既定の出力は段階 5 で別の文書にする。

既定の出力が守ること（§4.3）: プラグインがなくても生成でき、呼び出す側から見た関数のインターフェースがこの文書の形で、プラグインの専用の出力もこの形を保つ。

## 配置

- 名前空間 N のファイルは `<ルート>/<Conf(N).out>/<P>/` に置く。P は、N の祖先のうち `out` を自分で書いた最も近い名前空間 A からの相対パス（A 自身なら空、`server.admin` で `server` が書いていれば `admin`）。Conf は `docs/config.md`「名前空間の設定の解決」。Go のパッケージ名は N の最後のセグメントを小文字にし、英数字以外を落としたもの。
- import パスは、`<Conf(N).out>` から親へ向かって最初に見つかる `go.mod` の `module` にディレクトリの相対パスを足したもの。`go.mod` が見つからなければ GOEMIT-1。
- 別の名前空間 M の型と op を使うとき、M の言語が Go で同じプロジェクトなら M のパッケージを import する。そうでなければ（段階 5 以降の TS の名前空間など）、使う型を N のパッケージに複製する（§4.5「その型は使う側の名前空間の言語でも型として出力する」）。
- ファイルの先頭は `// Code generated by hozoc <hozoc の版>; DO NOT EDIT.`。`go/format` で整形する。整形に失敗したら内部エラー（生成器の不具合）で、整形前の内容を `<out>/.hozoc-failed/<ファイル>` に書いてメッセージで示す。
- 生成するファイル（中身がなければ作らない）:

| ファイル | 中身 |
|---|---|
| `doc.go` | パッケージの説明（名前空間の `description`） |
| `types.go` | model、scalar、union、exception、effect |
| `validate.go` | `Validate` メソッド |
| `ops.go` | `Leaves`、`Ops`、`Deps`、`States`、`Wrappers`、`Classifiers`、`New`、`ops` 構造体 |
| `wiring.go` | 配線の op の本体 |
| `classify.go` | 分類の型と判定関数 |

## 名前

| IR | Go |
|---|---|
| 宣言名（型の位置） | 先頭を大文字に（NAME-1 は warning なので小文字で始まる名前も来る） |
| 合成した model `OrderPage.Ready`（`docs/ir.md`「正規化」） | 名前空間より後ろのセグメントを連結: `OrderPageReady` |
| フィールド名 | 先頭を大文字に（`id` → `Id`、`userId` → `UserId`）。`json:"<元の名前>"` タグ。省略可能なら `,omitempty` |
| op 名 | 先頭を大文字に（メソッド名） |
| effect 名 | 先頭を大文字にし、`Effect` を前に付ける（`EffectCreateSession`） |
| classify のケース | `<分類名><ケース名>`（`WarrantyKindYamada`）。`default` は `<分類名>Default` |
| Go の予約語と衝突する名前 | 末尾に `_` |
| 大文字化で衝突する二つの名前（`id` と `Id`） | GOEMIT-2 |

先頭だけを大文字にする（`Id`、`Url`）のは、Go の慣習（`ID`）より決定性と予測しやすさを取るため。規則の実装は `plugin/golang`（`docs/packages.md`）に置き、Go のプラグインと共有する。

## 型

| IR | Go |
|---|---|
| `string` / `boolean` / `int` / `float` | `string` / `bool` / `int64` / `float64` |
| `Time` / `Duration` | `time.Time` / `time.Duration` |
| `optional(T)` | T が `array` か `record` ならそのまま（`nil` が「なし」）。それ以外は `*T` |
| `array(T)` | `[]T` |
| `record(K, V)` | `map[K]V` |
| model への `ref` | 構造体の型 |
| scalar への `ref` | 名前付きの型 |
| union（`arms`）への `ref` | インターフェースの型 |
| `case(C, cases, of)` | `of` の型（絞り込みは Go の型にしない。ドキュメンテーションコメントに前提として書く） |

## model

```go
// User は ...（description.body）
type User struct {
    Id    UserId `json:"id"`
    Email Email  `json:"email"`
    Name  string `json:"name"`
}
```

- フィールドの説明はフィールドのコメントに。
- 既定値（`page: PosInt = 1`）を持つフィールドが一つでもある model には `func New<Model>() <Model>` を生成し、既定値を入れて返す。
- `derivedFrom` を持つ model も普通の構造体。元の model からの変換関数 `func <Base>To<Derived>(v <Base>) <Derived>` を生成する（フィールドを写す）。
- union のアームの合成 model には、union のマーカーメソッドを足す（下）。

## scalar

```go
// Email は ...
type Email string

func (v Email) Validate() error { ... }
```

- `Validate` はすべての scalar に生成する。`valid.*` のデコレータを順に確かめ、違反を `*runtime.ValidationError`（`Violations: []runtime.Violation{{Path: "", Constraint: "format"}}`）で返す。違反がなければ `nil`（制約がなければ常に `nil`）。
- 標準の制約の実装:

| `valid` | 実装 |
|---|---|
| `min(value)` / `max(value)` | 数値の比較。元の型が数値でなければ GOEMIT-3 |
| `length(min?, max?)` | `utf8.RuneCountInString`。元の型が `string` でなければ GOEMIT-3 |
| `pattern(regex)` | パッケージ変数 `var pattern<Scalar> = regexp.MustCompile(...)` で `MatchString`。RE2 で解釈できなければ GOEMIT-3 |
| `format(name)` | `runtime.CheckFormat(name, v)`。知らない `name` は GOEMIT-3 |

- ユーザーが `valid` に足した制約（§6.5）は、`validate.go` のインターフェース `ConstraintImpls`（メソッドは制約ごとに `CheckDigit(v string) bool`。引数の型は元の型）にし、パッケージ変数 `var Constraints ConstraintImpls` を人が設定する。未設定で `Validate` が呼ばれたら panic（メッセージに変数名）。
- scalar の継承（`scalar A extends B` で B が scalar）は、B の制約も確かめる。

## model の Validate

すべての model に `func (m Model) Validate() error` を生成する。各フィールドについて、型が scalar なら `Validate` を呼び、フィールドに付いた `valid.*` を確かめ、型が model なら再帰する。`array` は要素ごと、`record` は値ごと。`optional` で `nil` なら飛ばす。違反の `Path` はフィールド名を `.` でつなぐ（`body.email`、`items[2].id`）。

## union

```go
type OrderPage interface{ isOrderPage() }

func (OrderPageReady) isOrderPage()     {}
func (OrderPageEmpty) isOrderPage()     {}
func (OrdersUnavailable) isOrderPage()  {}
```

- `variant: "set"` のユニオンは Go の型にしない（例外と効果の集合は `throws` と `effects` に展開済み）。
- アームの型が別の名前空間の model なら、その名前空間のパッケージでマーカーを生やせないので、N のパッケージに `type <Union><Arm> struct{ <Model> }` の包む型を作る。

## exception

```go
// InvalidCredentials: メールアドレスかパスワードが一致しない
type InvalidCredentials struct{}

func (InvalidCredentials) Error() string          { return "server.InvalidCredentials" }
func (InvalidCredentials) HozoException() string  { return "server.InvalidCredentials" }

type ClientError struct{ Value Violations }
```

`runtime.Exception` インターフェース（`error` と `HozoException() string`）を満たす。値を運ぶなら `Value` フィールド。

## effect

```go
const EffectCreateSession runtime.Effect = "server.createSession"
```

## state

状態そのものは出力しない（保存場所は語彙とプラグインが決める。§5.2）。N の配線から N 自身の op を呼ぶ呼び出しで `Call.bound` が空でないとき、その状態ごとに `States` インターフェースの取得メソッドを生成する（`bind` は `single` だけ。BIND-6）。

```go
type States interface {
    Token(ctx context.Context) (*server.Token, error)   // single<Token?> なら *T、single<T> なら T
}
```

別の名前空間の op への呼び出しの `Call.bound` は、`Deps` の実装者が埋める（下の「インターフェース」）。

## op

### 関数の型

```go
Login(ctx context.Context, in LoginInput) (LoginOk, error)   // 引数は OpParam の並びのまま。void なら error だけ
```

- 例外は `error` で返す。投げうる例外の型（`Signature.exceptions`）と効果（`Signature.effects`）はメソッドのコメントに `Throws:` / `Effects:` として並べる。
- 絞り込まれた型の引数はコメントに前提として書く。

### インターフェース

```go
// Leaves は人が実装する葉の op
type Leaves interface { Login(ctx context.Context, in LoginInput) (LoginOk, error); ... }

// Ops は呼び出す側が使う、この名前空間のすべての op
type Ops interface { ...葉と配線のすべて... }

// Deps は別の名前空間の op。viewer から見た関数の型（bind で埋まる位置は引数から消えている）
type Deps struct { Server ServerOps }
type ServerOps interface { GetMe(ctx context.Context, in GetMeInInput) (server.PublicUser, error) }

func New(leaves Leaves, deps Deps, states States, wrappers Wrappers, classifiers Classifiers) Ops

// ops は New が返す非公開の構造体。フィールドは New の引数そのまま
type ops struct { leaves Leaves; deps Deps; states States; wrappers Wrappers; classifiers Classifiers }
```

- `Deps` のフィールドは、配線から呼んでいる別の名前空間ごとに一つ。インターフェース名は `<名前空間の最後のセグメントを大文字に>Ops`。
- `ServerOps` の引数の型は `View.ops[fqn].params`。`bind` でフィールドを除いた合成 model（`docs/ir.md`「その名前空間から見た IR」の `<viewer>.<op 名>$<引数名>`）は N のパッケージに `<Op><Param>Input` の名前（`GetMeInInput`）で構造体にする。
- `Deps` の実装者が、`bind` で埋まる位置（`View.ops[fqn].bound`）に状態の値を入れて呼び出し先に渡す。実装者は hozoc の外（同じプロジェクトの Go なら `server.New(...)` の戻り値を包み、状態の値を足す人の手のコード。別の言語なら http クライアントのプラグインの出力。§4.3）。
- `ops` の各メソッドは、葉なら `leaves` の同名のメソッドを、配線なら生成した本体（「配線の本体」）を、その op の `Wrappers` のメソッドで内側から順に包んだもの。
- 使わないインターフェース（`States` に要素がない、など）は生成しない。`New` の引数と `ops` のフィールドもその分だけ。

### デコレータ

op に付いたデコレータのうち、次の両方を満たすものを「包む関数」にする（§4.3「対応するプラグインがなければ、既定の出力として包む関数のインターフェースを出し、人が実装する」）。

- 宣言が `external` でない（運搬の境界は同じプロセスの中では意味がない）。
- Conf(N).plugins のどのマニフェストの `entry` / `stop` にも含まれない（起点と打ち切りはプラグインが別の形で扱う。`docs/plugin-protocol.md`「entry / stop / decorate の意味」）。

`decorate` に含まれるものも包む関数にする。その実装はプラグインが出力し、人は書かない。

```go
type Wrappers interface {
    // FetchMe に付いた @redirectToLogin（= redirectOn(server.Unauthorized, transitionToLogin)）。
    // catches server.Unauthorized halts browser.transitionToLogin
    FetchMeRedirectToLogin(ctx context.Context, next func(ctx context.Context) (server.PublicUser, error)) (server.PublicUser, error)
    LoginValidated(ctx context.Context, in LoginInput, next func(ctx context.Context, in LoginInput) (LoginOk, error)) (LoginOk, error)
}
```

- メソッド名は `<Op><デコレータ名（via があれば via の名前）>`。同じ op に同じデコレータは DEC-13 で弾かれているので重複しない。
- 引数は op の引数 + `next`。`next` の形は op の関数の型。
- `New` が返す `Ops` の葉のメソッドは、`leaves` のメソッドを内側のデコレータから順に包む。配線のメソッドも同じく本体を包む。
- 包む関数の宣言（`throws` / `catches`）は、コメントに写す。

### 配線の本体

```go
func (o *ops) OpenOrders(ctx context.Context, query OrdersQuery) (OrderPage, error) {
    me, err := o.FetchMe(ctx)
    if err != nil { return nil, err }
    orders, err := o.FetchOrders(ctx, query)
    if err != nil { return nil, err }
    return o.OrderPageVm(ctx, me, orders)
}
```

| 文 | Go |
|---|---|
| `const x = call` | `x, err := <呼び出し>; if err != nil { return <零値>, err }` |
| `call;` | `if err := <呼び出し>; err != nil { return ... }` |
| `return call` | `return <呼び出し>`（戻り値の型が一致するとき）。射影が要るなら束縛してから変換関数 |
| `return atom` | 射影が要れば変換してから `return` |
| `const x = match` | 下 |
| 同じ名前空間の op の呼び出し | `o.<Op>(ctx, ...)` |
| 別の名前空間の op の呼び出し | `o.deps.<Ns>.<Op>(ctx, ...)` |
| 引数の `name` | その Go の式（`query.Page`） |
| 引数の `record` | 構造体リテラル |
| 引数の `none` | `nil` |
| 引数の `literal` | Go のリテラル（`Duration` は `time.Duration(ns)`） |
| `Call.bound`（同じ名前空間の op への呼び出し） | 呼び出しの前に `tok, err := o.states.Token(ctx)` で取り、引数の値のそのパスに入れる。引数が `name` なら一度変数に複製してからフィールドに代入 |
| `Call.bound`（別の名前空間の op への呼び出し） | 何もしない。`Deps` の引数の型にその位置はなく、`Deps` の実装者が埋める |
| 射影（model → model） | `<From>To<To>(v)` の変換関数（上の `derivedFrom` と同じ形）。必要になった組だけ生成 |

- 零値: ポインタ・インターフェース・スライス・マップは `nil`、構造体は `T{}`、名前付きの型は `T("")` など Go の零値。
- 実行の順序は行の順。並列化はしない（§9「展開器は…自由に実行してよい」の範囲だが、既定の出力は最も単純な形にする）。

### match

```go
kind, err := Classify<C>(o.classifiers.<C>, item)
if err != nil { return nil, err }
var warranty *server.WarrantyLine
switch kind {
case WarrantyKindStandard:
    warranty, err = o.ChooseStandardWarranty(ctx, item, line)
case WarrantyKindYamada:
    warranty, err = o.ChooseYamadaWarranty(ctx, item, line)
case WarrantyKindNoWarranty:
    warranty = nil
}
if err != nil { return nil, err }
```

- 束縛する変数の型は `docs/types.md`「式の型」の `match` の型。
- `default` のアームは `case <C>Default:`。
- 値のない `match` は `switch` だけ。

## classify

```go
type WarrantyKind int
const (
    WarrantyKindStandard WarrantyKind = iota
    WarrantyKindYamada
    WarrantyKindNoWarranty
    // hasDefault なら WarrantyKindDefault
)

// WarrantyKindCases は人が実装するケースごとの述語（§10.3）
type WarrantyKindCases interface {
    Standard(v server.Item) bool
    Yamada(v server.Item) bool
    NoWarranty(v server.Item) bool
}

type Classifiers struct { WarrantyKind WarrantyKindCases }

func ClassifyWarrantyKind(c WarrantyKindCases, v server.Item) (WarrantyKind, error)
```

- 判定関数はすべての述語を評価し、真の数を数える。`hasDefault` が false なら 1 でなければ、true なら 2 以上なら `*runtime.ClassificationError{Classify, Hits}` を返す（§10.3 の表）。0 で `hasDefault` なら `<C>Default`。
- 「本番で全部の述語を評価して検証するか、最初に真になったものを返すか」（§10.3）は、既定の出力では常に全部評価する。切り替えは段階 6（§12）で考える。

## runtime パッケージ

生成したコードが import する `github.com/mew-ton/hozo/runtime`。

```go
type Effect string
type Exception interface { error; HozoException() string }
type Violation struct { Path, Constraint string }
type ValidationError struct { Violations []Violation }      // Error() を持つ
type ClassificationError struct { Classify string; Hits []string }
func CheckFormat(name, v string) bool                       // "email" / "uri" / "uuid" / "date-time"
```

API を変えるときは、生成したコードのヘッダに書く hozoc の版（「配置」）と合わせて互換を保つ。

## 診断

| ID | 重さ | 意味 |
|---|---|---|
| GOEMIT-1 | error | `out` の上に `go.mod` がない |
| GOEMIT-2 | error | 大文字化でフィールド名か op 名が衝突する |
| GOEMIT-3 | error | `valid` の制約が元の型に合わない、または `pattern` が RE2 でない、または `format` の名前を知らない |

GOEMIT-* は `CheckFailed`（終了コード 1）。
