# go-valid プラグイン

## この文書が決めること

`valid` の語彙（`docs/vocab.md`「同梱する語彙」）の制約を確かめる Go の関数を出す、標準の検証のトランスパイラ `go-valid`。Go の基底 `go`（`docs/plugin-go.md`）に相乗りする。プラグインは `plugins/go-valid/`、ほかの相乗りが使う規則の写しは公開の `plugin/govalid`（`docs/packages.md`）。期待する出力の実物は、サンプル `tests/samples/shop-server/` の `gen/type/validate.go` と `gen/server/inner/validate.go`。

制約（`@valid.*`）は、型に一度だけ書く、型の性質。それ自体は何も起こさない。このトランスパイラが出すのは**確かめる関数**だけで、**いつ確かめるか**（HTTP の要求を受けたとき、コマンドの引数を読んだとき）は、境界を持つ相乗り（`docs/plugin-go-http.md`、`docs/plugin-go-cli.md`）が決め、失敗をその語彙の形で伝える。語彙ごとに制約のデコレータを持つ形（`@http.valid.*`）は採らない。

## マニフェスト

```toml
name     = "go-valid"
command  = ["go", "run", "github.com/mew-ton/hozo/plugins/go-valid"]
protocol = "0.17"

[[transpiler]]
name     = "go-valid"
language = "go"
requires = ["go"]
```

- 読む語彙は、標準の `valid`（`min` / `max` / `length` / `pattern` / `format`）。語彙は提供しない。
- オプションはない。`[emit.options.go-valid]` にキーがあれば GOVALID-7。

## Validate を持つ型

`Validate` を持つかどうかは、仕様だけから決まる（設定によらない）。規則の写しは `govalid.HasValidate`。

名前空間の scalar と model のうち、次のどれかに当たるものが `Validate` を持つ。当たるものがなくなるまで繰り返して決める（互いを参照する model があってもよい）。

1. `@valid.*` が付いた scalar。
2. 元の型（`Scalar.base`）が、`Validate` を持つ scalar である scalar。
3. `@valid.*` が付いたフィールドを持つ model。
4. `Validate` を持つ型を、フィールドの型に持つ model。フィールドの型は、`optional`、`array` と、インデックスの model（`docs/types.md`「インデックスの model」）の値を通して見る（`T?`、`T[]`、`model Items { [name: string]: T; }` の `Items`）。インデックスの model そのものは、`Validate` を持たない: 値を回すのは、それをフィールドの型に持つ model。

- 継承した model は、展開済みのフィールド（受け継いだデコレータを含む）で判定する。受け継いだ制約は外せない。
- union と exception は `Validate` を持たない（例外の引数の型が `Validate` を持つ型でも、例外の構造体には出さない。例外の値を確かめる者は、いない）。フィールドの型（上の 4 と同じに通して見たもの）が union（`arms`）で、そのアームの型のどれかが `Validate` を持つなら GOVALID-4（インターフェースにメソッドを足せないので、まだ形がない）。
- 結果の型にも出る（入力にしか使わない型かどうかは見ない）。
- その場で書いた model（union のアームの `{ … }`。`docs/ir.md`「正規化」）は、普通の model として数える。例外は、その場の model を持たない: 運ぶ値は、引数（`docs/grammar.md`「exception / effect / read」）。`View` が見る側のために合成した model（`docs/plugin-go.md`「出力の対象」）は、Go の型にならないので、数えない。

## 出力

`Validate` を持つ型が N に一つもなければ、何も出さない（warning もない）。あれば、N の**定義のパッケージ**（`docs/plugin-go.md`「内側のフォルダと入口」）に `validate.go` を一つ。先頭は `// Code generated by hozoc go-valid <版>; DO NOT EDIT.`。

- メソッドは、宣言順に、型ごとに一つ: `func (v <Scalar>) Validate() error`、`func (m <Model>) Validate() error`。値のレシーバ。入口のパッケージの別名からも、そのまま呼べる。
- 違反は `*runtime.ValidationError`（「runtime」）で返す。違反がなければ `nil`。違反は、確かめた順にすべて集める（最初の一つで止めない）。
- **別の名前空間の型**の `Validate` は、その型のメソッドを呼ぶ。メソッドは型の定義のパッケージにしか書けないので、その名前空間の型の置き場（`docs/config.md`「型の置き場」）の単位も、`transpilers` に `go-valid` を並べていなければならない。並べていなければ GOVALID-3（黙って確かめずに済ませない）。scalar の元の型（「scalar」）が、別の名前空間の scalar のときも同じ。
- 非公開の名前は `valid` で始める。補助の関数は、`validAppend`（「runtime」）と `validKeys`（インデックスの model のキーを辞書順に並べる。「model」）の二つで、使うときだけ、パッケージごとに一つずつ、この順でファイルの末尾に出す（`validAppend` は、元の scalar が `Validate` を持つ scalar も使う）。`pattern` の正規表現は、パッケージの変数 `validPattern<型名>`（フィールドの制約なら `validPattern<Model><フィールド名を先頭大文字に>`）に `regexp.MustCompile(…)` で一度だけ作り、ファイルの先頭（import の後）に宣言順で並べる。変数の名前が当たれば（model `Item` のフィールド `color` と、scalar `ItemColor`）、後ろの方に `2`、`3`、… を付ける。
- メソッドの中の局所の名前（レシーバ `v` / `m`、違反を集める `violations`）が、このファイルが import するパッケージの名前（元の scalar の名前空間のパッケージ）と当たれば、局所の名前の方の末尾に `_` を足す（`docs/plugin-go.md`「名前」の「局所の名前」と同じ扱い）。

### scalar

```go
// Validate は type.Password の制約を確かめる。違反がなければ nil。
func (v Password) Validate() error {
	var violations []runtime.Violation
	if l := utf8.RuneCountInString(string(v)); l < 8 || l > 128 {
		violations = append(violations, runtime.Violation{Path: "", Constraint: "length"})
	}
	if len(violations) == 0 {
		return nil
	}
	return &runtime.ValidationError{Violations: violations}
}
```

確かめる順: 元の scalar が `Validate` を持つなら、まずそれ（`violations = validAppend(violations, "", <元の型>(v).Validate())`）。次に、自分に付いた `@valid.*` を、書かれた順に。`Path` は `""`。

### model

```go
// Validate は type.User の各フィールドの制約を確かめる。違反の Path はフィールド名を . でつないだもの。
func (m User) Validate() error {
	var violations []runtime.Violation
	violations = validAppend(violations, "email", m.Email.Validate())
	if l := utf8.RuneCountInString(string(m.Name)); l < 1 || l > 100 {
		violations = append(violations, runtime.Violation{Path: "name", Constraint: "length"})
	}
	if len(violations) == 0 {
		return nil
	}
	return &runtime.ValidationError{Violations: violations}
}
```

フィールドの順に、フィールドごとに次の二つを、この順で確かめる。どちらもないフィールドは飛ばす。

1. フィールドの型が `Validate` を持つなら、それを呼ぶ: `violations = validAppend(violations, "<フィールド名>", m.<F>.Validate())`。
2. フィールドに付いた `@valid.*` を、書かれた順に。値は `m.<F>`、`Path` はフィールド名。

フィールドの型が包まれているとき:

| フィールドの型 | 形 |
|---|---|
| `optional(T)`（Go でポインタ） | `if m.<F> != nil { … }` の中で、値を `*m.<F>` として、上の 1 と 2 |
| `array(T)` | `for i0, x0 := range m.<F> { … }` の中で、要素 `x0` について 1。`Path` は `"<フィールド名>["+strconv.Itoa(i0)+"]"`。入れ子の配列は `i1`、`x1`、…。配列そのものに付いた `@valid.*` は GOVALID-1（下の表の、型の合わない制約） |
| インデックスの model への `ref`（値の型が T） | `for _, k0 := range validKeys(m.<F>) { x0 := m.<F>[k0]; … }`（キーの辞書順に回す。`validKeys` は、キーを並べ替えて返す補助の関数）の中で、値 `x0` について 1。`Path` は `"<フィールド名>["+string(k0)+"]"`。キーは確かめない。インデックスの model を型に持つフィールドに付いた `@valid.*` は GOVALID-1 |

- 省略可能な array と、省略可能な、インデックスの model は、Go でポインタにならない（`docs/plugin-go.md`「型」）ので、`nil` を確かめずに、上の二つの行のまま回す。
- 包まれた型は、入れ子にできる（`T?[]`、値の型が `T[]` のインデックスの model、値の型が別のインデックスの model であるもの）。入れ子の番号は、配列とインデックスの model で通しに振る（`x0` の中の `k1`、`x1`）。

### 制約

| `valid` | 条件（違反のとき真） | 付けられる元の型（違えば GOVALID-1） |
|---|---|---|
| `min(value)` | `<数の型>(<値>) < <value>` | `int`（`int64(…)`）か `float`（`float64(…)`）。`int` に付けた `value` が整数でなければ GOVALID-1 |
| `max(value)` | `<数の型>(<値>) > <value>` | 同上 |
| `length(min?, max?)` | `l := utf8.RuneCountInString(string(<値>)); l < <min> \|\| l > <max>`（片方だけなら、その比較だけ。どちらもなければ GOVALID-1） | `string` |
| `pattern(regex)` | `!validPattern….MatchString(string(<値>))`。RE2 で解釈できなければ GOVALID-1 | `string` |
| `format(name)` | `!runtime.CheckFormat("<name>", string(<値>))`。知らない `name`（「runtime」）は GOVALID-1 | `string` |

- 「元の型」は、scalar ならその継承を辿った核の型、フィールドなら、その型（scalar なら同じに辿る）。
- 違反は `violations = append(violations, runtime.Violation{Path: "<パス>", Constraint: "<デコレータの名前>"})`。`Constraint` は、`valid` の語彙のデコレータの名前（`min`、`length`、…）。
- **利用者が `valid` に足した制約**（設計書 §6.5）は、中身を人が書くもので、`Validate()` に実装を渡す形がまだない。使われていれば GOVALID-5。

## runtime

`go-valid` の出力と、それを呼ぶ相乗りが使う `github.com/mew-ton/hozo/runtime` の型（置き場は `docs/plugin-go.md`「runtime パッケージ」）。

```go
type Violation struct { Path, Constraint string }       // Path は違反した値への道（scalar 自身なら ""、model なら "body.email"、"lines[2].quantity"）
type ValidationError struct { Violations []Violation }  // Error() を持つ。Violations は確かめた順で、空にはならない
func CheckFormat(name, v string) bool                   // "email" / "uri" / "uuid" / "date-time"
```

`validAppend(dst, path, err)` は、`err` が `*runtime.ValidationError` なら、その違反の `Path` に `path` を前置して（元が空なら `path` だけ、そうでなければ `path + "." + 元`）`dst` に足す。それ以外のエラーは、`Constraint` にその文言を入れた違反一つにする。

## ほかの相乗りとの約束

- `Validate` を呼ぶ相乗りは、`requires` に `go-valid` を書く。**呼ぶコードの形を、相手の型が `Validate` を持つかどうかで変えない**（`docs/requirements.md`「出力を推論しない」）: どの入力にも同じ補助の呼び出しを出し、補助が、実行時に、値が `Validate() error` を持つかを見る（`docs/plugin-go-http.md`「制約の検査」、`docs/plugin-go-cli.md`「引数の解釈」）。自分の単位は `go-valid` を並べている（CFG-19）ので、N の、`Validate` を持つ型のメソッドは必ずある。
- どの型が `Validate` を持つか（`govalid.HasValidate(program, <型の FQN>)`。`docs/plugin-protocol.md`「相乗りが基底の形を知る方法」）を相乗りが使うのは、書いたものの整合の検査だけ: **別の名前空間 M の型**が `Validate` を持つのに、M の型の置き場の単位が `go-valid` を並べていなければ、その値は、確かめられないまま通る。呼ぶ側が自分の診断にする（`go-http` の GOHTTP-11、`go-cli` の CLI-9）。確かめ方は、`go-valid` と同じ `govalid.Unlisted(view, <名前空間>)`。
- 違反を自分の語彙の形にするのは、呼ぶ側（`docs/plugin-go-http.md`「op を呼ぶ前の失敗」）。

## 診断

`emit` の応答の `errors` で返す。

| ID | 重さ | 意味 |
|---|---|---|
| GOVALID-1 | error | 制約が元の型に合わない（「制約」の表）、元の型が `int` の `min` / `max` の `value` が整数でない、`length` に `min` も `max` もない、`pattern` が RE2 でない、`format` の名前を知らない、配列か、インデックスの model そのもの（を型に持つフィールド）に制約が付いている。位置は、付いた scalar か model |
| GOVALID-3 | error | `Validate` を持つ別の名前空間の型を、フィールドに持つか、scalar の元の型にするが、その名前空間の型の置き場の単位が `go-valid` を並べていない。メッセージに、その単位（何番目の `[[emit]]` か）を示す。位置は model（元の型なら、その scalar） |
| GOVALID-4 | error | フィールドの型が union で、そのアームに `Validate` を持つ型がある（「Validate を持つ型」）。位置は model |
| GOVALID-5 | error | 標準でない `valid` の制約（利用者が `valid` に足したデコレータ）が付いている。位置は、付いた scalar か model |
| GOVALID-6 | error | `Validate` を持つ model が、`validate` という名前のフィールドを持つ（Go で、フィールド `Validate` とメソッド `Validate` が当たる）。位置は model |
| GOVALID-7 | error | `[emit.options.go-valid]` に、知らないキーがある。位置なし |

- GOVALID-2 は欠番。「フィールドの既定値が、その型かフィールドの制約に合わない」という規則だったが、フィールドの既定値を言語からなくしたので、確かめるものがない（`docs/decisions.md`「設計書から離れた決定」S24）。値を入れるデコレータ（`@http.default`、`@cli.default`）の値は、それを読む相乗りが、生成するときに制約で確かめる（`docs/plugin-go-http.md`「補う値と制約」）。番号は別の意味に使い回さない（欠番の一覧は `docs/requirements.md`「検査の規則の一覧」）。
- Dir(U, N) の上に `go.mod` がないとき（同じ単位の基底が GO-1 を返し、何も書き出されない。`docs/plugin-go.md`「診断」）は、ファイルを返さず、GO-1 も重ねて返さない。置き場を求められないので、GOVALID-3 は確かめない。ほかの診断は、そのときも返す。
- 生成器の不具合（`View` が欠けている、生成したコードを `go/format` で整形できない）は、診断にせず、異常終了する（`proc.Crashed`。`docs/plugin-protocol.md`「起動」）。
