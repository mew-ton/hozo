# IDE の画面

## この文書が決めること

IDE の画面の要件: 画面の並び、画面ごとに見せるものと、できる操作、どの画面にも掛かる要件、想定する規模。そこから、画面を作る枠組み（フレームワークと部品）を選ぶ規準を導く。IDE が誰の、どのユースケースのためのものかと、道具の境目、作る順の持ち主は `tools.md`。

**この文書は、案。** 利用者が確かめていない（`open.md`「聞かずに決めて、確かめていない決定」）。どれも、まだ作っていない。「段」は `tools.md`「作る順」の段。

## 並び

プロジェクトのフォルダを開くと、一つのウィンドウに、次の五つが並ぶ（並ぶものは `tools.md`「決まっている前提」）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 上の帯: プロジェクトの名前 ／ 探す ／ 「今」と「変更」の切り替え        │
├───────────┬──────────────────────────────────────────┬───────────────┤
│ 左: 木     │ 中央: 作業面（タブ。左右に二つまで分けられる） │ 右: チャット   │
│  設計      │  手法ごとの画面 ／ 文面                     │               │
│  ファイル   │                                          │               │
├───────────┴──────────────────────────────────────────┴───────────────┤
│ 下の帯: ハーネスの状況（要約）。開くと、欠けの一覧                       │
└──────────────────────────────────────────────────────────────────────┘
```

| 場所 | 中身 | 段 |
|---|---|---|
| 上の帯 | プロジェクトの名前。宣言を名前と説明で探す。作業面の表示を「今」と「変更」で切り替える（「変更の重ね書き」） | 2（切り替えは 3） |
| 左: 木 | 二つの木を切り替える。**設計**: 名前空間ごとに、入口、ものの一生、型、そのほかの宣言。**ファイル**: `.hozo` と `hozo.toml` | 2 |
| 中央: 作業面 | 木で選んだものを、タブで開く。開くのは、手法ごとの画面（「画面」）か、文面。左右に分けて、画面と文面を並べられる | 2 |
| 右: チャット | AI とのやり取り（「チャット」） | 3 |
| 下の帯 | ハーネスの状況（`tools.md`「ハーネスの状況」）の要約を、いつも出す。開くと、欠けの一覧 | 2（検査だけ）、4（残り） |

左、右、下は、畳める。幅と、開いているタブは、プロジェクトごとに覚える（「状態の置き場」）。

## 画面

作業面に開く画面。どれも、同じ仕様（IR）の別の見え方（`tools.md`「IDE の画面」）。「形」は、その画面の主な描き方で、枠組みを選ぶ規準（「枠組みを選ぶ規準」）のもとになる。

| 画面 | 開く対象 | 形 | 見せるもの | 直せるもの（段 5） |
|---|---|---|---|---|
| 地図 | プロジェクト | 節と線の図（節は名前空間、線は呼び出し） | 名前空間、まとまり、呼ぶ相手、入口の数 | 名前空間の説明 |
| 入口と手順 | 入口一つ（op 一つ） | 入れ子のアウトライン（行は、読む、書く、手順、中身、分かれ道、失敗） | 手順、変えるもの、読むもの、失敗と、そのとき変わっているもの | 行の足し引きと並べ替え、分かれ道のアーム、失敗、説明 |
| ものの一生 | 分類一つ | 節と線の図（節はケース、線は効果） | ケース、移り変わり、移り変わりを起こす入口 | ケースの足し引き、移り変わりを線で引く、説明 |
| やり取り | 入口一つ | 縦の帯と矢印（帯は名前空間） | 名前空間をまたぐ呼び出しの順と、戻る失敗 | —（見るだけ） |
| 型 | 名前空間一つ | 表（model ごとに、フィールドの行）と、参照の線 | model、scalar、union、状態、失敗の運ぶ値 | フィールドの足し引き、型、説明 |
| 約束 | プロジェクト | 表 | 印のデコレータごとに、引数と、付いている宣言 | 約束の文、付ける先 |
| 変更 | プロジェクト | 一覧 | 基準の版からの差を、`tools.md`「変更を読む」の種類ごとに | —（受け入れる、戻す） |
| 文面 | ファイル一つ | 文面のエディタ | `.hozo` の文面。色、診断、定義への移動 | 文面（段 2 は読むだけ） |

- **節と線の図は、三つ**（地図、ものの一生、型の参照の線）。編集で線を引くのは、ものの一生だけ。
- **入口と手順は、図ではなく、アウトライン。** 試作（`tools.md`「試作で分かったこと」）で、入れ子の一覧が、手順を読むのに足りた。並べ替えと足し引きも、アウトラインの操作になる。
- **やり取りは、決まった形の図**（帯と矢印）で、節を動かす操作はない。
- 画面に入らない宣言（デコレータの宣言、`bind`）は、設計の木の「そのほかの宣言」と、文面で見える（`decisions.md`「決めたこと」184）。

## どの画面にも掛かる要件

### 選んでいるもの

IDE は、「今、選んでいるもの」を一つ持つ: 宣言（FQN）か、その中の一か所（手順の一行、ケース、フィールド）。

- どの画面で選んでも、ほかの画面、木、文面が、同じものを指す（文面は、その位置を見せる。木は、その節を見せる）。
- チャットに書くとき、選んでいるものが、AI に伝わる（`tools.md`「AI に頼む」の「画面の要素を指して言える」）。
- 文面でカーソルを動かすと、その位置の宣言が、選んでいるものになる。

### 追従

- ディスクの上のファイルが変わると、IDE は、検査し直して、開いているすべての画面を、新しい内容にする。誰が書いたか（AI、エンジニアのエディタ、IDE 自身）は、区別しない（`tools.md`「境目」の「ファイルが、つなぎ目」）。
- 追従しても、変わらないもの: 選んでいるもの（その宣言が残っていれば）、開いているタブ、開閉、スクロールの位置、図の中の、変わっていない節の位置。
- ファイルが変わってから、画面が変わるまでは、1 秒以内（「規模」）。
- 仕様に構文の誤りがある間も、読めた宣言は、画面に出す（今の状態: 解析は誤りに耐える。`requirements.md`「言語サーバー」の前提条件）。

### 図の配置

- 図の節の位置は、IDE が、仕様から決める。人が動かした位置は、覚えない: 位置は設計ではなく、仕様（`.hozo`）の外に、設計の一部を持たない（`requirements.md`「ただ一つの正」）。
- 同じ仕様からは、同じ配置になる。宣言を一つ足しても、ほかの節は、なるべく動かない（「追従」）。
- 図は、拡大、縮小、移動ができる。

### 欠けの重ね書き

- 検査の診断と、目を通すべきところ（説明のない宣言、進める効果のないケース、どの入口からも起きない移り変わり）は、どの画面でも、その要素の上に印で出す。
- 下の帯の一覧から選ぶと、その要素が、選んでいるものになる。
- 足りない宣言を足せる診断には、その印の横に、足すボタンを出す（段 5 より前に、`tools.md`「操作」の「足りない宣言を足す」ができた段で）。

### 変更の重ね書き

- 上の帯で「変更」に切り替えると、どの画面も、基準の版からの差を、その要素の上に出す: 足された、なくなった、変わった。なくなった要素も、なくなったものとして見える。
- 画面「変更」は、差の一覧。選ぶと、その要素を、「変更」の表示のまま、その手法の画面で開く。

### 画面での編集（段 5）

- 画面での編集は、要素への操作（`tools.md`「操作」の「要素を直す」）を、`hozoc` に送ること。画面は、仕様を自分では書き換えない。
- 結果は、ファイルの変化として戻り、「追従」で画面に出る。送ってから出るまで、1 秒以内。
- 検査を通らなくなる操作も、送れる。その結果は、欠けとして出る（「欠けの重ね書き」）。
- 取り消しの形（一つ前の文面に戻す）は、決めていない。
- 名前と説明は、その場で打ち直せる。日本語の入力（変換の途中）で、確定しない。

### チャット（段 3）

- AI の返事は、届いた分から出す。AI が道具（MCP サーバーの道具）を使ったことは、何をしたかの一行で出す。
- AI がファイルを書き換えたら、チャットの中に、変更への入口を出す（選ぶと、画面「変更」）。
- 選んでいるものを、書く欄の上に出し、外せる。

### 状態の置き場

- 仕様についてのデータは、どれも `hozoc` が持ち主。画面は、受け取ったものを描く（`tools.md`「IDE の形」の案）。
- 画面が持つのは、見え方の状態だけ: 選んでいるもの、開いているタブ、開閉、幅、表示の切り替え。プロジェクトごとに、手元に覚える。仕様のフォルダには、書かない。

### そのほか

- 手元だけで動く。画面は、外のネットワークから何も読まない（フォントも同梱する）。
- キーボードだけで、木、タブ、アウトライン、一覧を動かせる。
- 表示の言葉は、日本語と英語。仕様の中の名前と説明は、書かれたまま出す。
- 明るい色と、暗い色の、両方を持つ。
- OS の表示の部品（`decisions.md`「決めたこと」188）ごとに、図の画面を確かめる。

## 規模

サンプル `order-app`（`tests/samples/order-app/`）を、ふつうの大きさのプロジェクトとする。数字は、今の `hozoc` で測ったもの。

| もの | `order-app` | 画面が耐える大きさ |
|---|---|---|
| ファイル | 27（4,339 行。最大 577 行） | 300 |
| 名前空間 | 27 | 300（地図の節） |
| 宣言 | op 262、model 122、効果 64、分類 36、状態 35 | 10 倍 |
| 入口 | 37 | 500（木と一覧） |
| 一つの入口を、すべて開いた手順の行 | 最大 57 | 1,000 |
| 一つの分類のケースと移り変わり | 最大 5 と 7 | 30 と 60 |
| IR（JSON） | 3.6 MB | — |
| 検査の一回 | 約 30 ms | — |

- 検査が速いので、追従は、ファイルが変わるたびに、全体を検査し直す形でよい（今の状態: 言語サーバーも同じ。`lsp.md`「プロジェクト」）。
- IR の全体を、変わるたびに画面へ送ることは、しない（3.6 MB）。画面は、開いている画面に要る分だけを受け取る。

## 枠組みを選ぶ規準

上の要件から導く、画面の枠組み（フレームワークと、主な部品）に求めること。重い順。

| 規準 | 出どころの要件 |
|---|---|
| 1. 追従に耐える: 大きなデータの一部が、たびたび変わる。変わっていないところ（選択、開閉、スクロール、節の位置）を、作り直さずに保てる | 「追従」「規模」 |
| 2. 入れ子のアウトラインを、開閉、並べ替え、その場の打ち直しごと作れる。1,000 行で遅くならない | 画面「入口と手順」 |
| 3. 節と線の図: 節の中に自由な中身を描ける、線を引いてつなげる、配置は外から与えられる、拡大と移動 | 画面「地図」「ものの一生」「型」 |
| 4. 作業面: タブ、左右の分割、畳める三つの枠 | 「並び」 |
| 5. 文面のエディタを載せられる: TextMate の文法での色付け、言語サーバーへの接続 | 画面「文面」 |
| 6. 届いた分から出す表示 | 「チャット」 |
| 7. OS の表示の部品（WebView2、WebKit）で、同じに動く | 「そのほか」 |
| 8. 画面ごとの部品を、殻なしで（ブラウザで）自動のテストに掛けられる | `testing.md` の進め方（テストが先） |
| 9. 実装を AI に任せやすい: 書き方が広く知られ、部品の文書がそろっている | `CLAUDE.md` の進め方 |

5 と 6 は、どの枠組みでも、枠組みに依らない部品（エディタの部品など）で満たせる。差が出るのは、1〜4 と 9。
