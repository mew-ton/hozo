# IDE の画面の構成

## この文書が決めること

IDE の設計の段 3（`tools.md`「IDE の設計の段階」）: 段 2 の情報と操作（`ide-needs.md`）を、画面に割り当てたもの。画面の一覧、画面ごとに見せるものと直せること、画面の間の移り方。次の段（画面の見本）は、ここに並ぶ画面ごとに、見本を作る。

**この文書は、案。** 利用者が確かめていない（`open.md`「聞かずに決めて、確かめていない決定」）。

この文書は、画面の中の配置（どこに何を置くか）と、見た目を、決めない（段 4）。今の Hozo と `hozoc` で出せるかどうかは、画面の構成に影響させない（`ide-needs.md`「原則」）。

## 構成の考え方

- **画面は、「対象」と「手法」の組。** 対象は、設計する人が、今、見ているもの（アプリの全体、一つの入口、一つのもの、一つの概念）。手法は、それを見る形（図か、表か、記述か）。同じ対象を、いくつかの手法で見られる。
- **手法は、筋書きの問いに答えるものだけを、画面にする。** 設計の手法に合わせることは、目的ではない（`decisions.md`「決めたこと」177）。画面にしなかった手法と、その理由は「画面にしなかった手法」。
- **どの画面も、同じ仕様の、別の見え方。** 画面ごとに、別のデータを持たない（`requirements.md`「ただ一つの正」）。
- **仕様にあるものは、どれかの画面で、必ず見える**（`decisions.md`「決めたこと」184）。それを受け持つのは、「概念の宣言」と「文面」。
- **直せるのは、宣言したもの。導いたものは、直に直せない。** 受け渡し、「誰も作らないデータ」、「進んではいけない向き」は、宣言から導いたもの。直すには、もとの宣言（効果、行の遷移）を直す。画面は、そこへ移る道を出す。

## いつも出ているもの

どの画面を開いていても、出ているもの。

| もの | 中身 | 受け持つ情報と操作（`ide-needs.md`） |
|---|---|---|
| 選ぶところ | 対象を選ぶ。対象の種類は、アプリの全体、担い手、概念、入口、もの、約束、アプリの画面、ファイル。名前と説明で探せる | 「読むための操作」の、開く、探す |
| 選んでいるもの | 今、選んでいる要素（宣言か、その中の一か所）。画面を移っても、持ったまま | 「読むための操作」の、一つのものを持ったまま移る |
| AI とのやり取り | 言葉で頼む。選んでいるものを添える。AI の聞き返しに答える。AI の案を、書き換える前に見る。AI が書いている途中かが分かる。書き換えたら、「変更」への道が出る。やり取りの記録が残る | 「AI との操作」のすべて |
| 状況 | 検査の誤りの数、目を通すところの数、枠が今の仕様のものか、中身の欠けの数、確かめの結果の数、AI が書いている途中か。選ぶと、「欠けと決めごと」か「中身の状況」へ | 「欠け」「中身の状況」の要約 |

## 重ね

どの画面にも、要素の上に重ねて出せる印。画面ごとに、作り直さない。

| 重ね | 出すもの | 受け持つ情報 |
|---|---|---|
| 欠け | 検査の誤りと、目を通すところ。機械的に埋まるものには、足す操作 | 「欠け」 |
| 差 | 基準の版から、足された、なくなった、変わった。なくなった要素も、なくなったものとして出す | 「差」 |
| 確かめ | その要素についての、確かめた結果（通った、通らない、確かめていない） | 「中身の状況」 |
| 仕事 | 気づいたこと、目を通した印、後で決める、今回は作らない | 「設計ではないが、設計する人の仕事に要るもの」 |
| 出どころ | 設計する人が話したことか、AI が補ったことか | `ide-scenarios.md` の筋書き 7 |

## 画面ごとの中身

「見せるもの」は、`ide-needs.md`「情報」の行。「直せること」は、同「直すための操作」を、その画面の形の上で行うこと。「移る先」は、要素を選んで、移れる画面。

### 担い手とできること

- **見せるもの**: 担い手の一覧。担い手ごとの入口と、その説明。入口の種類（人の操作、外からの通知、自動）。入口に結ばれた約束があるか。
- **絞る**: 担い手で、概念で。
- **直せること**: 担い手を、足す、名前を変える、消す。入口の名前と説明。入口を足す（手順のない、骨組みの入口）。入口の担い手を、付け替える。
- **移る先**: 入口 →「入口の記述」。担い手 →「業務の流れ」（その担い手に絞る）。

### 業務の流れ

- **見せるもの**: 担い手ごとの行。入口。入口から入口への受け渡し（何が、どの状態になって、渡るか）。自動で動くもの、外からの通知、起きたことへの反応、待つこと。行の遷移に書いていない前提による順は、区別して出す。一つの入口が、いくつかのものを進めること（一生の絡み）。
- **絞る**: もので（注文だけ、支払いだけ）、担い手で。状態を変えない入口を、出す、出さない。
- **並べ方**: 流れの図と、担い手 × 順の表。
- **直せること**: 入口を足す（骨組み）。反応を足す。受け渡しは、導いたものなので、直に直せない: 受け渡しを選ぶと、もとの「ものの一生」の向きへ移る。
- **移る先**: 入口 →「入口の記述」。受け渡しのもの →「ものの一生（図）」。

### 構成

- **見せるもの**: こちらが作るものと、外にあるものの境。外の仕組みと、そこへ頼むこと、そこから受けること。概念と、依る向き。概念ごとの、データと入口の数。
- **直せること**: 概念の名前と説明。概念を足す。こちらと外を、付け替える。
- **移る先**: 概念 →「概念のモデル」「概念の宣言」。外の仕組み →「一覧」（外とのやり取り）。

### データと操作の表

- **見せるもの**: 行は入口（担い手か概念でまとめる）、列はデータ。ますは、作る、読む、変える、消す。誰も作らないデータ、誰も読まないデータ。「今回は作らない」とした空き。
- **直せること**: 空きを、「今回は作らない」「後で決める」にする。ますは、導いたものなので、直に直せない。
- **移る先**: 入口 →「入口の記述」。データ →「概念のモデル」。

### 約束

- **見せるもの**: 約束（誰に、何を）。約束ごとの、守る役と、それを通る入口。値についての規則。確かめた結果。要求の文書の一つ一つと、当たる約束。当たるところのない要求。守る役のない約束。どの入口も通らない守る役。
- **直せること**: 約束を、足す、文を直す、消す。守る役を、付ける、外す。値についての規則を、書く、直す。要求の項目と、結ぶ。
- **移る先**: 守る役 →「入口の記述」（その一歩）。通る入口 →「入口の記述」。確かめた結果 →「確かめ」。

### アプリの画面の流れ

- **見せるもの**: アプリの画面、画面ごとの状態、画面でできる操作、操作の後に、どの画面になるか。
- **直せること**: 画面と、その状態を、足す、消す。操作の行き先。
- **移る先**: 操作 →「入口の記述」。

### 一覧

- **種類**: 入口、もの、データ、失敗、外とのやり取り、自動で動くもの、約束、概念。
- **見せるもの**: 種類ごとの行と、名前、説明。失敗なら、起きうる入口の数、使う人まで出る入口の数、出たときに見せるもの。自動で動くものなら、間隔。外とのやり取りなら、相手、向き、相手が返す失敗。
- **探す、絞る、並べ替える。** 説明のないものだけ、に絞れる。
- **直せること**: 名前と説明（その場で）。
- **移る先**: 行 → その対象の、はじめの画面（入口なら「入口の記述」、ものなら「ものの一生（図）」）。

### 入口の記述

- **見せるもの**: 名前、説明、担い手。前提。基本の流れ（一歩ごとに、読む、書く、外に頼む、別の手順、中身に任せる、の別）。分かれ道（場合ごとに、すること。表として開ける）。終わった後に、変わっているもの。失敗の一覧と、失敗ごとに、何が変わっているか、使う人まで出るか、出たときに見せるもの、その後に人がすること。読むデータと、変えるデータ。関わる約束。
- **畳む、開く**: 失敗の枝。別の手順の中。
- **直せること**: 説明。前提。一歩を、足す、消す、入れ替える。分かれ道の、場合ごとにすること。失敗を、足す、消す。
- **移る先**: 別の手順 → その手順の「入口の記述」と同じ形。データ →「概念のモデル」。状態 →「ものの一生（図）」。失敗 →「一覧」（失敗）。約束 →「約束」。

### 入口の流れ図

- **見せるもの**: 「入口の記述」の流れと分かれ道を、概念ごとのレーンに置いた図。
- **直せること**: 「入口の記述」と同じ（一歩と、分かれ道）。
- **移る先**: 「入口の記述」と同じ。

### 入口のやり取り

- **見せるもの**: 関わる概念と、外の仕組みの帯。呼ぶ順。分かれ道。失敗が、どこまで戻るか。
- **直せること**: なし（見るだけ）。
- **移る先**: 帯 →「概念の宣言」。呼び出し →「入口の記述」（その一歩）。

### ものの一生（図）

- **見せるもの**: 状態と、その説明。進んでよい向き。向きごとの、起こす入口と担い手、進むための条件。入るところ。入れない状態、出られない状態。同じ入口が進める、ほかのもの。
- **直せること**: 状態を、足す、消す、名前と説明を直す。向きを、足す、消す。進むための条件。
- **移る先**: 起こす入口 →「入口の記述」。ほかのもの → その「ものの一生（図）」。

### ものの一生（表）

- **見せるもの**: 行は今の状態、列は起こすこと、ますは後の状態。進んではいけない向きの、すべて。入れない状態、出られない状態。
- **直せること**: ますを埋める（向きを足す）、空ける（向きを消す）。
- **移る先**: 「ものの一生（図）」と同じ。ます →「確かめ」（その向きの条件）。

### 状態の決め方

- **見せるもの**: 条件と、その状態。規則が、仕様に書いてあるか、中身に任せているか。
- **直せること**: 条件。
- **移る先**: 状態 →「ものの一生（図）」。

### 概念のモデル

- **見せるもの**: その概念のものと、項目、型、説明。もの同士の関連。データとして持つもの（表）と、そのキー、表の間の関連。
- **並べ方**: 関連の図と、項目の表。
- **直せること**: 項目を、足す、消す、名前と型と説明を直す。関連。
- **移る先**: もの →「ものの一生（図）」（一生を持つなら）。データ →「データと操作の表」（その列）。

### 概念の宣言

- **見せるもの**: その概念に宣言してあるものの、すべて: データ、分類、外から呼べる手順、中だけの手順、失敗、型、そのほか。それぞれの、名前、説明、付いている印。
- **直せること**: 名前と説明。
- **移る先**: 宣言 → その対象の画面。どの画面にも対象を持たない宣言は、「文面」。

### 確かめ

- **対象**: 一つの入口、一つのもの、一つの約束、アプリの全体。
- **見せるもの**: 確かめる条件の一覧: 進んでよい向き（前提、すること、結果）、進んではいけない向き、失敗のとき変わっていないもの、値についての規則。条件ごとの、確かめた結果。通っていないものが、中身の誤りか、仕様の誤りか。
- **直せること**: なし。条件は、仕様から導く。条件を変えるには、もとの宣言（向き、規則、約束）を直す。
- **移る先**: 条件 → そのもとの画面（「ものの一生（表）」「約束」「入口の記述」）。

### 変更

- **見せるもの**: 基準の版からの差の一覧。種類ごと（入口、手順、失敗、ものの一生、約束、データ、説明だけ）。頼んだことに関わる変更と、関わらない変更。
- **すること**: 基準の版を選ぶ。受け入れる。戻す。一部だけ、戻す。
- **移る先**: 差 → その要素の画面を、「差」の重ねを出して開く。

### 欠けと決めごと

- **見せるもの**: 検査の誤り（機械的に埋まるものと、判断が要るものに分ける）。目を通すところ。後で決めること。今回は作らないと決めたこと。気づいたこと。目を通した範囲と、まだの範囲。
- **すること**: 足りない宣言を、足す。抜けを、「今回は作らない」「後で決める」に分ける。気づいたことを、消す。AI に、まとめて埋めさせる。
- **移る先**: 行 → その要素の画面。

### 中身の状況

- **見せるもの**: コードの枠が、今の仕様のものか。仕様が求める中身のうち、まだないもの。確かめた結果の、約束ごと、ものごと、入口ごとの集計。
- **すること**: 枠を、出し直す。AI に、中身を書かせる。確かめを、走らせる。
- **移る先**: 集計の行 →「確かめ」。

### 文面

- **見せるもの**: `.hozo` と `hozo.toml` のファイル。文面。色、検査の誤り。
- **直せること**: 文面を、直に。
- **移る先**: 文面の中の宣言 → その対象の画面。ほかの画面の要素 → その文面の位置。

## 画面の間の移り方

移り方は、三つ。

| 移り方 | 例 |
|---|---|
| **同じ対象の、別の手法へ** | 一つの入口を、「入口の記述」から「入口のやり取り」へ。一つのものを、図から表へ |
| **選んでいるものを持って、別の対象へ** | 約束 → 守る役 → それを通る入口 → その入口が進めるもの → その向きの確かめ |
| **アプリの全体から、対象へ。対象から、全体へ** | 「業務の流れ」の入口 →「入口の記述」。「入口の記述」のデータ →「データと操作の表」の、その列 |

- 移っても、選んでいるものは変わらない。移った先の画面は、選んでいるものが見えるように開く。
- 移る前の画面へ、戻れる。
- 要素からは、いつでも、その文面へ移れる。

## 画面にしなかった手法

| 手法 | 理由 | 代わり |
|---|---|---|
| ロバストネス図 | 手順が、判断ごとに分かれているので、制御が多すぎて、図として読めなかった（`ide-methods.md`「手法ごとの結果」） | 「入口の記述」「入口のやり取り」 |
| イベントストーミング、イベントモデリング | 付箋の種類（コマンド、事実、方針）は、「業務の流れ」の、入口、受け渡し、反応と同じもの | 「業務の流れ」 |
| サービスブループリント、ストーリーマップ | 「業務の流れ」の、担い手 × 順の並べ方 | 「業務の流れ」の、表の並べ方 |
| BPMN | 業務フロー図に、開始の種類（時計、通知）を足したもの | 「業務の流れ」 |
| DFD | 一段目は「構成」、二段目は「データと操作の表」と同じ材料 | 「構成」「データと操作の表」 |
| C4 | コンテキストとコンポーネントは「構成」。コンテナ（どこで動くか）は、設定（`hozo.toml`）の話で、設計する人の筋書きに出てこなかった | 「構成」 |

## 割り当ての確かめ

### 情報

`ide-needs.md`「情報」のまとまりごとに、受け持つ画面。

| 情報のまとまり | 受け持つ画面 |
|---|---|
| アプリの全体 | 「担い手とできること」「構成」「一覧」 |
| 業務の流れ | 「業務の流れ」 |
| 一つの入口 | 「入口の記述」「入口の流れ図」「入口のやり取り」。読む・変えるデータは「データと操作の表」にも |
| ものの一生 | 「ものの一生（図）」「ものの一生（表）」「状態の決め方」 |
| データ | 「概念のモデル」「データと操作の表」 |
| 約束と要求 | 「約束」。ある決めごとに関わる場所は、「約束」から移る先のすべて |
| アプリの画面 | 「アプリの画面の流れ」 |
| 差 | 「変更」と、重ねの「差」 |
| 欠け | 「欠けと決めごと」と、重ねの「欠け」、いつも出ている「状況」 |
| 中身の状況 | 「中身の状況」「確かめ」と、重ねの「確かめ」 |
| 設計ではないが、仕事に要るもの | 「欠けと決めごと」と、重ねの「仕事」。受け入れた版は「変更」。AI とのやり取りの記録は、いつも出ている「AI とのやり取り」 |

### 操作

| 操作のまとまり | 受け持つところ |
|---|---|
| 読むための操作 | いつも出ている「選ぶところ」「選んでいるもの」。絞る、畳むは、画面ごと。比べるは「変更」 |

| 仕事のための操作 | 重ねの「仕事」と「欠けと決めごと」 |

### 筋書き

筋書き（`ide-scenarios.md`）の歩みを、画面でなぞる。

| 筋書き | 歩み → 画面 |
|---|---|
| 1 はじめて読む | 1 →「担い手とできること」。2 →「約束」。3 →「業務の流れ」→「ものの一生（図）」。4 →「入口の記述」（失敗の枝は畳んだまま）。5 →「約束」→ 守る役 →「入口の記述」。6 → 重ねの「仕事」（気づいたこと）。7 → 重ねの「仕事」（目を通した印）→「欠けと決めごと」 |
| 2 約束を追う | 1 →「約束」。2 → 守る役から、通る入口へ →「入口の記述」。3 →「ものの一生（表）」。4 →「状態の決め方」と、「約束」の値についての規則。5 →「入口の記述」の失敗。6 → 同じ（失敗の後に、人がすること）。7 →「確かめ」（その約束） |
| 3 AI に頼む | 1 →「ものの一生（図）」。2 → 状態を選び、「AI とのやり取り」。3 → 同じ（AI の案）。4 →「変更」。5 →「変更」の、関わらない変更。「データと操作の表」に「差」を重ねる。6 →「ものの一生（表）」に「差」を重ねる。7 →「入口の記述」。8 →「変更」で、受け入れる |
| 4 抜けを決める | 1 →「データと操作の表」。2 → 空きを、「今回は作らない」に。3 →「ものの一生（表）」。4 → 同じ表の ×、「確かめ」。5 →「一覧」（説明のないもの）。6 →「欠けと決めごと」 |
| 5 小さく直す | 1 → どの画面でも、名前を直す。2 → 同じ。3 →「ものの一生（図）」か（表）。4 →「入口の記述」。5 → 重ねの「差」。6 → 一つ前に戻す |
| 6 中身を知る | 1〜2 →「中身の状況」。3 →「確かめ」（ものごと、入口ごと）。4 →「確かめ」（約束ごと）、「約束」。5 →「確かめ」の、誤りの分け |
| 7 何もないところから | 1 →「AI とのやり取り」。2 →「担い手とできること」「構成」（重ねの「出どころ」）。3 →「約束」。4 →「業務の流れ」→「ものの一生（図）」。5〜6 →「欠けと決めごと」。7 →「AI とのやり取り」→「変更」。8 →「欠けと決めごと」と、「状況」 |

なぞって、分かったこと:

- どの筋書きも、はじめの画面は、アプリの全体の画面（「担い手とできること」「約束」「業務の流れ」「データと操作の表」「中身の状況」）か、「AI とのやり取り」。一つの入口や、一つのものの画面から始まる筋書きは、ない。
- 「入口の流れ図」と「アプリの画面の流れ」は、どの筋書きの歩みにも、はじめの答えとしては、出てこなかった。「入口の記述」と「担い手とできること」が、先に答える。置くかどうかは、決めていない（`open.md`「次の段」）。
- 「変更」と、重ねの「差」は、筋書き 3、5、7 に出る。AI が書き換えるたびに通る。
