# db の語彙のプラグイン

## この文書が決めること

語彙のプラグイン `db`（`docs/plugin-protocol.md`「語彙のプラグイン」）が持つ、`db` の語彙の、**言語にも、保存先の製品にも依らない決まり**: どの状態が表で、どのフィールドが列か（「表」「キーと参照」）、`read` と効果のデコレータが、宣言の何と合っていなければならないか（「read」「効果」「列と引数の型」）、書いたものの整合の検査（「診断」の DB-*）。プラグインは `plugins/db/`。決まりを読み解くコードは、Go のライブラリ `plugin/dbvocab`（`docs/packages.md`「`plugin/dbvocab`（公開）」）で、このプラグインと、`db` の語彙を SQLite と Go に出す `go-sqlite`（`docs/plugin-go-sqlite.md`）が、同じものを使う。

語彙の宣言（デコレータの一覧と、その意味）の持ち主は `docs/vocab.md`「`db` の語彙」。ある保存先と言語への出し方（列の型、SQL、メソッドの形）は、そのトランスパイラの文書が持つ（SQLite と Go は `docs/plugin-go-sqlite.md`）。

## マニフェスト

```toml
name     = "db"
wasm     = "plugin.wasm"
protocol = "1.0"

[read]
namespaces = ["db"]
```

- 読み解くのは、標準の語彙 `db`（`vocab/db.hozo`。hozoc に同梱）。このプラグインは、語彙の宣言（`.hozo`）を持たない。
- トランスパイラは、提供しない: ファイルを出さず、単位の `transpilers` に書く名前を持たない。
- 頼まれるのは、仕様のどこかに `db` のデコレータが付いているとき（`docs/plugin-protocol.md`「語彙のプラグイン」）。出力の単位は、要らない。

## 対象

仕様の、すべての名前空間（出力の単位がない名前空間も、含む。`docs/decisions.md`「決めたこと」429）を、一つずつ見る。以下、見ている名前空間を N とする。

- **表の状態**は、N に宣言した、`@db.table` の付いた状態。
- **`read` と効果**は、N に宣言したもののうち、`db` のデコレータの付いたもの。`read` の `reads` の状態も、効果の宛先の状態も、N の状態（`docs/check.md`「read の宛先」「効果の宛先」）。付いていない `read` と効果は、見ない（中身は、人が書く）。
- **`@db.transaction`**（op に付ける）は、このプラグインは、確かめない: op の中身を決めないデコレータで、書いたものどうしの整合が、ない。どこまでがトランザクションに入るかは、語彙を出すトランスパイラが決める（`docs/plugin-go-sqlite.md`「トランザクション」）。
- **しまい方のデコレータ**（`@db.text` など）は、このプラグインは、確かめない（「しまい方」）。
- 表の model でない model のフィールドに付いた `@db.key`、`@db.unique`、`@db.ref` は、読まない（確かめない）。
- `db` のデコレータを、付けられない宣言に付けたとき（`@db.find` を op に、など）は、hozoc が先に DEC-1 を返す（`docs/check.md`「デコレータ」）。

## 表

- 表の状態ごとに、表一つ。**表の model** M は、状態の要素の型（`State.element`。`@db.table state orders: list<type.Order>;` なら `type.Order`）で、列は、M のフィールド（フィールドごとに列一つ。名前は、フィールドの名前）。要素の型が、model でないか、インデックスの model（フィールドを持たない。`docs/types.md`「インデックスの model」）なら DB-1。
- 表の状態の形は `list` だけ。`nullable` と `single` の状態に `@db.table` が付いていれば DB-2（一行だけの表の形を、まだ決めていない）。
- 列が、値を持たなくてよいかは、フィールドの型の `?`（`docs/vocab.md`「`db` の表と、しまい方」）。

## しまい方

**このプラグインは、しまい方のデコレータ（`@db.text` / `@db.int` / `@db.float` / `@db.bool` / `@db.datetime` / `@db.date` / `@db.time` / `@db.json`。意味の持ち主は `docs/vocab.md`「`db` の表と、しまい方」）を、読まない。** 表の model のフィールドが、しまい方を持つか、それが型に合うかは、その表を、保存先に出すトランスパイラが確かめる（`docs/plugin-go-sqlite.md`「しまい方」の GOSQL-3、GOSQL-16、GOSQL-17、GOSQL-27）。

- 理由: しまい方は、列を、保存先に、どうしまうかで、表を出すときに、要る。設計だけの段階の仕様（出力の単位がない名前空間）は、表、キー、参照、引き方までを言い、しまい方を、まだ言わない（サンプル `tests/samples/order-app` の `domain/`）。このプラグインが、しまい方を求めると、その段階の仕様が、通らない。
- 線の引き方: このプラグインが、単位に依らず求めるのは、論理の決まり（表、キー、参照、`read` と効果の条件）。物理の決まり（列へのしまい方）は、保存先を出すトランスパイラが求める（`docs/decisions.md`「決めたこと」431）。

## キーと参照

- `@db.key` は、行を一つに決める列（の組）。`@db.unique` は、その列だけで行が一つに決まる列（意味の持ち主は `docs/vocab.md`「`db` の表と、しまい方」）。
- **`@db.ref(M2)` の指す先**は、要素の型が M2 の表の状態が N に**ちょうど一つ**あり、M2 が `@db.key` をちょうど一つ持つとき、その表の、その列。そうでなければ DB-11（指す先の表か列が、一つに決まらない）。黙って参照を省くことはしない: 仕様に書いた参照が、気づかないうちに表から消える。

## read

`@db.find` か `@db.list` を付けた `read` は、宣言の全体が、引くものを言う。以下、宣言の `reads` の状態を T、その表の model を M とする。

**宣言から読むもの**（デコレータは、これをもう一度言わない。`docs/vocab.md`「`db` の read と効果」）:

| 宣言の部分 | 読むこと | 合わなければ |
|---|---|---|
| `reads T` | 表。T は、N の表の状態 | DB-3 |
| 引数（`Read.params`） | **条件**。引数ごとに、その名前の列が、引数の値と同じ。引数の名前は、M のフィールドの名前で、型は、その列に合う（「列と引数の型」） | 名前のフィールドがなければ DB-4、型が合わなければ DB-5 |
| 結果の型（`Read.returns`） | 引くもの。`@db.find` なら `M?`、`@db.list` なら `M[]` | DB-6 |

**デコレータの決まり**:

| デコレータ | 決まり |
|---|---|
| `@db.find` | `@db.list` と一緒には付けられない（DB-12）。一行に決まらなければ DB-9 |
| `@db.list` | `@db.find` と一緒には付けられない（DB-12） |
| `@db.where("c", v)`（何度でも） | `@db.find` か `@db.list` の付いた `read` にだけ（DB-13）。c は M のフィールドの名前（DB-4）。v は、列 c の型に渡せる（DB-15） |
| `@db.latest("c")` | `@db.find` か `@db.list` の付いた `read` にだけ（DB-13）。c は M のフィールドの名前（DB-4）。c のしまい方が、新しい順に並べられるものかは、トランスパイラが確かめる（`docs/plugin-go-sqlite.md`「read の中身」の GOSQL-27） |

- **条件**は、引数（宣言の順）の後ろに、`@db.where`（書いた順）を並べたもの。一つの列を、二つの条件に書けない（引数と `@db.where`、二つの `@db.where`）。書いていれば DB-14。
- **`@db.find` は、一行に決まる**ものでなければならない。次のどれかを満たさなければ DB-9:
  1. 条件の列が、M の `@db.key` のフィールドを**すべて**含む（M が `@db.key` を一つ以上持つとき）。
  2. 条件の列が、`@db.unique` のフィールドを一つ以上含む。
  3. `@db.latest` が付いている（条件に合う行のうち、いちばん新しい一行に決まる。条件がなくてもよい）。
- **`@db.where` のリテラル**は、列のフィールドの型（scalar は元の核の型。省略可能は外して見る）に渡せなければならない（`docs/types.md`「互換」の 10: 整数のリテラルは `float` にも渡せる）。型が `datetime`、`date`、`time`、`duration`、`array`、model の列には、渡せるリテラルがない。
- 列は引数の名前なので、仕様の予約語（`docs/grammar.md`「予約語」）と同じ名前のフィールドの列は、引数の条件にできない（フィールドの名前には予約語を書けるが、引数の名前には書けない）。その列で引くなら、フィールドの名前を変えるか、その `read` を人が書く。`@db.where` と `@db.latest` の `column` は文字列なので、名指しできる。`@db.delete` の効果の引数も同じ。

## 効果

`@db.insert` / `@db.update` / `@db.delete` を付けた効果は、宣言の全体が、表にすることを言う。表 T は、効果の宛先の状態で、M は、その表の model。

| デコレータ | 効果の宛先（合わなければ DB-7） | 引数 |
|---|---|---|
| `@db.insert` | `T.post` | M の行一つ（引数は一つで、型は M そのものか、M を分類のケースで絞り込んだ型 `M on C.K`: 行の引数。`docs/check.md`「行の遷移」の「行と、行の分類」）。そうでなければ DB-5 |
| `@db.update` | `T.put` | M の行一つ（同じ）。M は `@db.key` を一つ以上と、キーでない列を一つ以上持つ（DB-10: 書き換える行を選べないか、書き換えるものがない） |
| `@db.delete` | `T.delete` | **条件**: 引数ごとに、その名前の列が、引数の値と同じ（「read」と同じ決まり。名前のフィールドがなければ DB-4、型は「列と引数の型」）。引数は一つ以上（DB-16） |

- T は、N の表の状態（DB-3）。**宛先は、組み込みの効果でなければならない**: 分類の遷移を宛先にする効果（`effect fn e(): effects Checkout as Shopping -> Ordered;`）に、この三つのどれかが付いていれば DB-7（一つの遷移が、どの表に何をするかは、宣言からは決まらない）。その効果は、人が書く。
- 効果は、三つのうち、高々一つを持つ（二つ以上なら DB-8）。
- **未決: 引数のない `@db.delete`**。「引数がなければ、すべての行」は、`@db.list` では決めたが、消す方では決めていない（書き忘れた引数が、表を空にする）。決まるまで DB-16。
- **`@db.conflict(E)`** は、`@db.insert` か `@db.update` と一緒に付ける（`docs/vocab.md`「`db` の read と効果」）。どちらも持たない効果に付いていれば DB-18。E は、その効果の `throws` にあり、引数を持たない例外（どちらかが違えば DB-19）。
- **`@db.update` は、行の遷移（`Effect.row`。`docs/check.md`「行の遷移」）の後のケースが、行の引数の型の言う、前のケースの並びにないとき、付けられない**（DB-17）: `effect fn start(order: Order on Stage.Accepted): effects orders.put as Stage.InProduction;` に渡る行は、`Accepted` にあると分かっている行。`@db.update` は、その行を、そのまま書く（`docs/vocab.md`「`db` の read と効果」）ので、書いた後の行も `Accepted` のままで、宣言した `InProduction` にならない。行を `InProduction` にする書き方（どの列を、何に変えるか）は、宣言から決まらないので、その効果は、人が書く。付けられるのは、行の引数を、その分類で絞り込んでいない形（`effect fn forceShip(order: Order): effects orders.put as Stage.Shipped;`）、後のケースが、前のケースの並びにある形、`as else` の形。
- **`@db.delete` は、行の遷移を持つ効果に、付けられない**: 行の遷移を持つ効果は、行を引数に取る（STATE-7）。`@db.delete` の引数は、列の条件で、行の引数の名前の列は、ない（DB-4）。**未決: 行を受け取る `@db.delete`**（キーが、引数の行と同じ行を消す）。決まるまで、今の規則のまま。

## 列と引数の型

値を、名前の同じ列と比べるところ（`read` と、`@db.delete` の効果の、引数の条件）のすべてに掛かる、ただ一つの規則（`docs/decisions.md`「決めたこと」96）:

**引数の型は、列の型（M のそのフィールドの型）と等しくなければならない。列の型が union なら、引数は、その一部でよい。** `T?` は「T」と「値がない」の union と数える。向きは一方だけで、列より広い引数は DB-5。

| 列の型 | 引数の型 | 合う行 |
|---|---|---|
| `T` | `T` | 列の値が、引数と同じ行 |
| `T?` | `T` | 同じ。値のない行は、どの値にも合わない |
| `T?` | `T?` | 引数に値があれば、同じ。値がなければ、値のない行 |
| `T` | `T?` | —（DB-5。列より広い） |

- 「等しい」は `docs/types.md`「等しい」。scalar は名前で比べる（`type.Token` の列に `string` の引数は渡せない）。
- 今、列にできる union は `T?` だけ（アームを持つ union の列を、しまえるトランスパイラは、ない。`docs/plugin-go-sqlite.md`「しまい方」の GOSQL-3）。
- この規則は、書いたものの整合の検査で、出力を変えない（条件の出し方は、トランスパイラの文書: `docs/plugin-go-sqlite.md`「列と引数の型」）。

## 診断

`read` の応答の `errors` で返す（`docs/plugin-protocol.md`「read」）。順は、名前空間の IR の順。一つの名前空間の中は、表の状態（宣言順）、`@db.ref`（表の model の順、フィールドの順）、`read`（宣言順）、効果（宣言順）。同じ診断（ID、位置、メッセージが同じ）は、一度だけ。warning は、返さない。

| ID | 重さ | 意味 |
|---|---|---|
| DB-1 | error | `@db.table` の付いた状態の要素の型が、model でないか、インデックスの model（「表」）。位置は状態 |
| DB-2 | error | `@db.table` の付いた状態の形が `list` でない（`nullable`、`single`）。位置は状態 |
| DB-3 | error | `db` のデコレータを付けた `read` の `reads` の状態か、効果の宛先の状態が、N の表の状態でない（`@db.table` が付いていない）。位置は、その `read` か効果 |
| DB-4 | error | 列を名指しするもの（`read` と `@db.delete` の効果の引数の名前、`@db.where` と `@db.latest` の `column`）が、表の model のフィールドにない。位置は、その `read` か効果 |
| DB-5 | error | 引数が、デコレータの言うものと合わない: 条件の引数（`read` と、`@db.delete` の効果）の型が、列に合わない（「列と引数の型」）。`@db.insert` / `@db.update` の効果の引数が、表の model の行一つでない。位置は、その `read` か効果 |
| DB-6 | error | `read` の結果の型が、デコレータの言うものと合わない: `@db.find` は `M?`、`@db.list` は `M[]`（M は表の model）。位置は `read` |
| DB-7 | error | 効果のデコレータが、効果の宛先と合わない（「効果」）: 宛先が組み込みの効果でない（分類の遷移）か、操作が合わない（`@db.insert` は `post`、`@db.update` は `put`、`@db.delete` は `delete`）。位置は効果 |
| DB-8 | error | 一つの効果が、`@db.insert` / `@db.update` / `@db.delete` のうち二つ以上を持つ。位置は効果 |
| DB-9 | error | `@db.find` の `read` が、一行に決まらない: 条件の列が、表の model の `@db.key` のすべても、`@db.unique` の列も含まず、`@db.latest` もない（「read」）。位置は `read` |
| DB-10 | error | `@db.update` の表の model が、`@db.key` を一つも持たないか、キーでない列を一つも持たない。位置は効果 |
| DB-11 | error | 表の model のフィールドの `@db.ref(M2)` の指す先が、一つに決まらない: 要素の型が M2 の表の状態が、N にないか、二つ以上ある。または、M2 の `@db.key` が一つでない（「キーと参照」）。位置は model |
| DB-12 | error | 一つの `read` が、`@db.find` と `@db.list` の両方を持つ。位置は `read` |
| DB-13 | error | `@db.where` か `@db.latest` の付いた `read` が、`@db.find` も `@db.list` も持たない。位置は `read` |
| DB-14 | error | 一つの `read` の条件が、同じ列を二度名指ししている（引数と `@db.where`、二つの `@db.where`）。位置は `read` |
| DB-15 | error | `@db.where` のリテラルが、列の型に渡せない（「read」）。メッセージに、列、リテラル、型を示す。位置は `read` |
| DB-16 | error | `@db.delete` の効果が、引数を一つも持たない。まだ決めていない形（「効果」の未決）。位置は効果 |
| DB-17 | error | `@db.update` を付けた効果の行の遷移（`Effect.row`）の、行の引数の型が、同じ分類で絞り込んだ型（`case`）で、後のケース（`to`）が、その `cases` にない（「効果」）。位置は効果 |
| DB-18 | error | `@db.conflict` を付けた効果が、`@db.insert` も `@db.update` も持たない（「効果」）。位置は効果 |
| DB-19 | error | `@db.conflict` の例外が、使えない: その効果の `throws` にない。引数を持つ。メッセージに、どちらかを示す。位置は効果 |

- **どの診断も、書いたものの整合の検査**: デコレータと宣言が食い違っていれば、error にする（`docs/requirements.md`「出力を推論しない」）。
- **一つの食い違いを、重ねて報告しない**: 表にならなかった状態（DB-1 か DB-2 を返した）を `reads` の状態か宛先にする `read` と効果に、DB-3 は出さない。DB-8、DB-12、DB-13 を返した宣言と、宛先が分類の遷移の効果（DB-7）は、ほかの検査をしない（デコレータが何を言っているのかが、決まらない）。DB-18 を返した効果も、同じ。条件の列がフィールドになかった（DB-4）`@db.find` に、DB-9 は出さない（一行に決まるかどうかを、言えない）。一つの `read` が同じ列を三度名指ししていても、DB-14 は、列ごとに一つ。
- **メッセージの型は、言語の綴り**（`docs/grammar.md`「型」。絞り込んだ型は `T on C.K`）。
- **DB-* は、`go-sqlite` の診断（GOSQL-*）のうち、言語にも保存先にも依らないものを、移したもの。** 番号の対応は `docs/plugin-go-sqlite.md`「診断」の「欠番」。
- 仕様が、検査の前提を欠くとき（要求に `spec` がない）は、診断にせず、異常終了する（`Crashed`。`docs/plugin-protocol.md`「起動」）。
