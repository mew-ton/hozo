# go-http プラグイン

## この文書が決めること

`http` の語彙（`docs/vocab.md`「同梱する語彙」「`http` の語彙」）の付いた op を、`net/http` のハンドラにするトランスパイラ `go-http`。Go の基底 `go`（`docs/plugin-go.md`）と、検証の `go-valid`（`docs/plugin-go-valid.md`）に相乗りする。プラグインは `plugins/go-http/`。期待する出力の実物は、サンプル `tests/samples/shop-server/` の `gen/server/http.go`（ハンドラ）と `gen/server/servertest/http.go`（インテグレーションテストの口）。

この文書は三つを決める: 生成する Go のコード（「出力」）、**通信の上の形**（「通信の形」）、入口ごとのインテグレーションテストを受け取る口（「インテグレーションテストの口」）。二つ目は、このサーバーを呼ぶどの実装（別の言語のクライアントのトランスパイラを含む）も合わせる規範で、Go のコードの都合で変えない。

デコレータが出すコードは、型に依らない（`docs/requirements.md`「出力を推論しない」）: 経路ごと、フィールドごとに出すコードは、デコレータの引数だけから作り、どの型でも同じ形（同じ補助の呼び出し）にする。値で変わる振る舞い（値がなければ 204、文字列の読み方）は、共通の補助が、実行時に決める（「補助」）。要求に項目がないときの扱い（誤りにする、決まった値を入れる）は、デコレータ（`@http.required`、`@http.default`）が言い、補助に引数で渡す（「入力の読み方」）。型は、書いたものが食い違っていないかを確かめるのにだけ使う（「診断」）。

## マニフェスト

```toml
name     = "go-http"
command  = ["go", "run", "github.com/mew-ton/hozo/plugins/go-http"]
protocol = "0.17"

[[transpiler]]
name     = "go-http"
language = "go"
requires = ["go", "go-valid"]
```

- 読む語彙は、標準の `http`: op の `@http.get(path)` / `@http.post(path)`、フィールドの `@http.header` / `@http.query` / `@http.body`（項目の形）と `@http.headerObj` / `@http.queryObj` / `@http.bodyObj`（全体の形）、`@http.required` と `@http.default(value)`（項目がないときの扱い）、例外の `@http.status(code)`。`@http.retry` は読まない（印）。語彙は提供しない。
- `go-valid` への依存は、オプションによらない（`docs/config.md`「基底と相乗り」）。`validate = false` でも、単位の `transpilers` に `go-valid` が要る。

## オプション

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `validate` | 真偽値 | `false` | `true` なら、入力を読んだ後、op を呼ぶ前に、入力の制約（`@valid.*`）を確かめる（「制約の検査」） |

知らないキーと、型の違う値は GOHTTP-9。

## 対象

N の単位の対象の op（`docs/config.md`「in」）のうち、`@http.get` か `@http.post` の付いたものが**経路の op**。一つもなければ、ファイルを一つも出さず warning を一つ返す。経路は、op に付いた `@http.get` / `@http.post` ごとに一つ（両方が付いた op は、書かれた順に二つの経路を持つ）。

- **経路の op は `export` が付いていなければならない。** ハンドラは、名前空間の外からの呼び出しを op に届ける入口で、op は基底の入口の `Ops`（`export` の op だけ）のメソッドとして呼ぶ。付いていなければ GOHTTP-1。黙ってその経路を飛ばすことはしない（仕様に書いた経路が、気づかないうちにサーバーから消える）。`@http.*` が付いていれば `export` と見なすこともしない（語彙のデコレータが、本体の検査の結果を変えることになる）。
- 経路の op の引数は、0 個か、model 一つ（**入力の model**）。それ以外は GOHTTP-2。インデックスの model（`docs/types.md`「インデックスの model」）は、フィールドを持たないので、入力の model にできない（GOHTTP-2）。
- 入力の model の各フィールドは、要求のどこから読むかを言う六つのデコレータのどれかを、**ちょうど一つ**持つ。そうでなければ GOHTTP-3。六つは、三つの場所（ヘッダ、クエリ、本文）ごとの、**項目の形**（`@http.header` / `@http.query` / `@http.body`。名前を省けば、フィールドの名前）と、**全体の形**（`@http.headerObj` / `@http.queryObj` / `@http.bodyObj`）。意味の持ち主は `docs/vocab.md`「`http` の語彙」で、そこが言う二つの決まりを、このトランスパイラが確かめる:
  - 全体の形は、型が、フィールドを持つ model のフィールドにだけ付けられる（省略可能な model、配列、インデックスの model には、付けられない）。そうでなければ GOHTTP-12。
  - 全体の形は、一つの場所に高々一つで、同じ場所の項目の形とは一緒に書けない（`@http.bodyObj` と `@http.body` を、一つの入力の model に書けない）。そうでなければ GOHTTP-13。
- **要求に項目がないときの扱い**は、項目の形を持つフィールドに足す、二つのデコレータが言う（意味の持ち主は `docs/vocab.md`「`http` の語彙」）: `@http.required` は、op を呼ばずに 400 を返す。`@http.default(<リテラル>)` は、フィールドをその値にする。どちらもないフィールドは、零値のまま op に渡る（省略可能なフィールドは、値がない）。フィールドの型（省略可能かどうか）からは決めない。型の宣言に書く既定値（`page: int = 1`）は、言語にない（`docs/decisions.md`「設計書から離れた決定」S24）: 値を入れるのは、要求を読むこの境界で、それを言うのがデコレータ。このトランスパイラが確かめる決まりは四つ:
  - 二つのデコレータを付けられるのは、項目の形（`@http.header` / `@http.query` / `@http.body`）を持つフィールドだけ。そうでなければ GOHTTP-14。全体の形のフィールドにも、全体の形で受け取る model の中のフィールドにも、付けられない: 全体の形の中の項目は、なければ、いつも零値のまま（扱いを言いたい項目は、項目の形で書く）。
  - 省略可能なフィールド（`T?`）には、どちらも付けられない。付いていれば GOHTTP-15。型は「なくてよい」と言っている: なければ誤りにするなら、また、なければ値を入れるなら、省略可能にしない。
  - 一つのフィールドに、両方は付けられない。付いていれば GOHTTP-17。
  - `@http.default` のリテラルは、フィールドの型（scalar は元の核の型）に渡せなければならない（`docs/types.md`「互換」の 10: 整数のリテラルは `float` にも渡せる）。渡せなければ GOHTTP-18。
- フィールドの型（scalar は元の核の型で見る）。全体の形では、その model のフィールドの一つずつを、同じ場所の項目として見る:

| 場所 | 受け付ける型 | それ以外 |
|---|---|---|
| ヘッダ | `string`、その省略可能 | GOHTTP-4 |
| クエリ | `string` / `int` / `float` / `boolean`、その省略可能 | GOHTTP-4 |
| 本文 | JSON にできる型（下の「JSON にできる型」） | GOHTTP-5 |

- `@http.get` の op は、本文のデコレータ（`@http.body`、`@http.bodyObj`）のフィールドを持てない（GOHTTP-6）。
- 経路の op の結果の型は、省略可能な配列（`T[]?`）でも、省略可能な、インデックスの model（`Attrs?`。`docs/types.md`「インデックスの model」）でもいけない。そうなら GOHTTP-16。Go では、どちらも `nil` が「値がない」を表すので、補助は、実行時に、値がない（204）ことと、空である（200）ことを見分けられない。省略可能な model と scalar（`type.Order?`）は、結果にできる（「通信の形」の「成功の応答」）。
- この表は、書いたものの整合の検査で、出力を変えない（どの型でも、同じ補助の呼び出しになる。「入力の読み方」）。
- パスは、`/` で始まる、決まった文字列。`{` か `}` を含むパス（パスの中の値）は、それを入力のフィールドに結ぶ語彙がまだないので GOHTTP-7。同じメソッドとパスの組が二つあれば GOHTTP-8。
- **JSON にできる型**: 核の型、scalar、model（インデックスの model を含む）、`optional`、`array` と、それらの組み合わせ。union（`arms`）と、union を中に持つ型は、通信の上の形をまだ決めていないので、本文（`@http.body`、`@http.bodyObj`）、結果、`@http.status` を持つ例外の引数の型のどこに現れても GOHTTP-5。

## 出力

出すファイルは三つ: N の**入口のパッケージ**（`docs/plugin-go.md`「相乗りのファイル」）の `http.go`（この見出し）と、N のテストのパッケージの `http.go` と、その、テストの対応表 `hozo-tests.go-http.json`（「インテグレーションテストの口」）。

入口のパッケージの `http.go` の先頭は `// Code generated by hozoc go-http <版>; DO NOT EDIT.`。標準ライブラリだけを使う（Go 1.22 以降の `http.ServeMux` のパターン）。並びはどれも宣言順。公開の名前は `NewHandler` 一つで、非公開の名前は `http` で始める。

```go
// NewHandler は ops を net/http のハンドラにする。@http.get / @http.post の付いた op ごとに経路を一つ持つ。
// 入力を読んだ後、op を呼ぶ前に、入力の制約を確かめる（単位のオプション validate = true）。
//
//	GET /orders   server.getOrders
//	POST /orders  server.placeOrder
func NewHandler(ops Ops) http.Handler {
	mux := http.NewServeMux()

	// server.getOrders
	mux.HandleFunc("GET /orders", func(w http.ResponseWriter, r *http.Request) {
		var in GetOrdersInput
		req := httpRequest{r: r}
		req.header("Authorization", &in.Token)
		req.query("page", &in.Page, httpDefault(1))
		if !req.ok(w) {
			return
		}
		if !httpValidate(w, in, httpPlace{"token", "header.Authorization"}, httpPlace{"page", "query.page"}) {
			return
		}
		out, err := ops.GetOrders(r.Context(), in)
		if err != nil {
			httpWriteError(w, err)
			return
		}
		httpWriteResult(w, out)
	})
	…
	return mux
}
```

- `NewHandler` が受け取るのは、基底の入口の `Ops`（`New` の戻り値を、そのまま渡す）。経路の op だけのインターフェースは作らない。
- コメントの二行目は、`validate = true` のときだけ。経路の一覧は、`<メソッド> <パス>` を、いちばん長いものに合わせて空白で埋め、二つの空白の後に op の FQN。
- 経路ごとに、`// <op の FQN>` のコメントと、`mux.HandleFunc("<メソッド> <パス>", …)`。メソッドは `@http.get` なら `GET`、`@http.post` なら `POST`。経路の間は一行空ける。`/` で終わるパス（`/` そのものを含む）は、`http.ServeMux` のパターンではその下のすべてのパスに合ってしまうので、パターンの末尾に `{$}` を足して、そのパスだけに合わせる（`"GET /{$}"`。コメントの経路の一覧には、仕様のパスのまま書く）。
- op には `r.Context()` を渡す（op のメソッドは、どれも `ctx` を取り、`error` を返す。`docs/plugin-go.md`「op の形」）。
- `NewHandler` とハンドラの中の局所の名前（`ops`、`mux`、`w`、`r`、`in`、`req`、`out`、`err`）が、このファイルが import するパッケージの名前（型と例外の名前空間のパッケージ）と当たれば、局所の名前の方の末尾に `_` を足す（`docs/plugin-go.md`「名前」の「局所の名前」と同じ扱い）。

ハンドラの中は、この順。1、2、3、5 の行は、入力の model の宣言と、フィールドの型と、戻り値の型によらず、同じ形。4 は、二つの形を持つが、振る舞いは同じ。

1. **入力を置く**: `var in <Model>`。どのフィールドも零値で始まる。基底は、初めの値を入れる関数を出さない（`docs/plugin-go.md`「model」）。引数のない op は、入力を持たず、1〜3 を出さない。
2. **入力を読む**: `req := httpRequest{r: r}` の後、フィールドの順に、フィールドごとに一行（「入力の読み方」）。その後に `if !req.ok(w) { return }`: 読めなかった最初の理由で 400 を返して終わる。
3. **制約の検査**（`validate = true` のとき、入力を持つすべての経路に）: `if !httpValidate(w, in, <場所の一覧>) { return }`。場所の一覧は、入力の model のすべてのフィールドについて、フィールドの順に `httpPlace{"<フィールド名>", "<場所>"}`。入力が `Validate` を持つかどうかは、補助が実行時に見る（「制約の検査」）。
4. **op を呼ぶ**: 戻り値があれば `out, err := ops.<Op>(r.Context(), in)`、なければ `if err := ops.<Op>(r.Context(), in); err != nil { … }`（引数のない op は、`in` を渡さない）。失敗は `httpWriteError(w, err)`。**行の形が二つあるのは、呼ぶ相手の、基底のメソッドの形（引数と戻り値を持つか。`plugin/golang` の `Signature`）を写しているからで、行の形は、振る舞いを運ばない**: どちらの形も、op を呼び、失敗なら `httpWriteError` に渡すだけ。何を返すかは、5 の補助が決める。
5. **成功を返す**: `httpWriteResult(w, out)`。戻り値のない op は `httpWriteResult(w, nil)`。ステータスも、本文も、ここには書かない: 何を返すかは、補助が、実行時に、渡された値で決める（「通信の形」の「成功の応答」）。

### 入力の読み方

フィールドごとに、デコレータと、その引数（か、フィールドの名前）だけで決まる一行。

| デコレータ | Go |
|---|---|
| `@http.header` | `req.header("<名前>", &in.<F>)` |
| `@http.query` | `req.query("<名前>", &in.<F>)` |
| `@http.body` | `req.body("<名前>", &in.<F>)` |
| `@http.headerObj` | `req.headerObj(&in.<F>)` |
| `@http.queryObj` | `req.queryObj(&in.<F>)` |
| `@http.bodyObj` | `req.bodyObj(&in.<F>)` |

`<名前>` は、デコレータの引数。省いていれば、フィールドの名前。

**項目がないときの扱いを言うデコレータは、同じ行の最後の引数になる。** 行に足すのは、デコレータが言ったことだけで、フィールドの型で変わるものは、何も足さない。

| デコレータ | 足す引数 | 例 |
|---|---|---|
| `@http.required` | `httpRequired` | `req.body("lines", &in.Lines, httpRequired)` |
| `@http.default(<リテラル>)` | `httpDefault(<リテラル>)` | `req.query("page", &in.Page, httpDefault(1))` |

`<リテラル>` の Go での書き方は、基底と同じ（`docs/plugin-go.md`「値」の表の `literal` の行。`duration` は `time.Duration(<ナノ秒>)`）。フィールドの型への変換は書かない: 補助が、実行時に、読む先の型に変える。

読み方は、補助 `httpRequest` が、実行時に、読む先の Go の型を見て決める（`reflect`）:

- **ヘッダとクエリの項目**（文字列一つを読む）: 読む先がポインタ（省略可能）なら、値を置く先を作ってから読む。文字列はそのまま、整数は `strconv.ParseInt(v, 10, 64)`、小数は `strconv.ParseFloat(v, 64)`、真偽値は `strconv.ParseBool(v)`。読めなければ、文言 `<場所> <名前>: invalid <int / float / boolean>`（`query page: invalid int`）。クエリの同じ名前が二度あれば、最初の値。ヘッダの値は、そのまま読む（`Bearer ` などの前置きを外さない）。空の文字列のヘッダは、ないものと読む。
- **項目がないとき**（ヘッダ、クエリ、本文の項目のどれも同じ）: 行に `httpRequired` があれば、読めない要求で、文言 `<場所> <名前>: missing`（`header Authorization: missing`、`body lines: missing`）。`httpDefault(v)` があれば、読む先を v にする（`reflect` で、読む先の型に変える）。どちらもなければ、読む先に何も書かない（1 で置いた零値のまま）。読む先の型は、見ない。
- **本文の項目**（`req.body`）: 本文は JSON のオブジェクトで、初めて呼ばれたときに一度だけ読む。キーの値を、`encoding/json` で読む先に読む。キーがなければ、項目がない（上）。キーがあれば、値が `null` でも、あるものと読む。本文が JSON のオブジェクトとして読めない（空の本文、配列、本文の全体が `null` のときを含む）、キーの値の型が合わないときは、文言 `body: invalid JSON`。
- **本文の全体**（`req.bodyObj`）: 本文を、`encoding/json` で、読む先の model に読む。読めなければ `body: invalid JSON`。知らないキーは無視し、ないキーのフィールドは零値のままにする（`encoding/json` の既定）。
- **ヘッダとクエリの全体**（`req.headerObj`、`req.queryObj`）: 読む先の model（Go の構造体）のフィールドごとに、その `json` タグの名前（仕様のフィールドの名前。基底が付ける）の項目を、項目の形と同じに読む。その項目には、`httpRequired` も `httpDefault` も渡らないので、なければ、零値のまま（「対象」の GOHTTP-14）。
- 本文の大きさは制限しない。
- 場所（`httpPlace` の二つ目と、違反の `path` の先頭）は、項目の形が `header.<名前>`、`query.<名前>`、`body.<名前>`、全体の形が `header`、`query`、`body`。

### 補助

`http.go` の、`NewHandler` の後ろに、使うものだけを、この順で出す。中身は、サンプルの `gen/server/http.go` の通り。

| 名前 | 中身 |
|---|---|
| `httpErrorBody`、`httpBadRequest`、`httpViolation` | 失敗の応答の本文の形（「通信の形」） |
| `httpPlace` | 入力の model のフィールドと、通信の上の場所の組 |
| `httpOption`、`httpRequired`、`httpDefault(v any) httpOption` | 項目がないときの扱い（`httpOption`）と、それを作る二つ: `@http.required` の `httpRequired` と、`@http.default(v)` の `httpDefault(v)`。`missing` を出すときに、三つとも出す |
| `httpRequest` | 要求一つを、入力のフィールドに読む。読めなかった最初の理由を持ち、その後は何も読まない。メソッドは、使うものだけを、`header`、`query`、`body`、`headerObj`、`queryObj`、`bodyObj`、`missing`（項目がないときの扱い。ヘッダ、クエリ、本文の項目の、どの読み方も使う）、`text`（ヘッダとクエリの値を読む共通の中身）、`ok` の順。項目の形のメソッドは `header(name string, dst any, opts ...httpOption)`（`query`、`body` も同じ引数）で、`opts` を見るのは `missing` だけ |
| `httpValidate(w http.ResponseWriter, in any, places ...httpPlace) bool` | 入力の制約を確かめる。`in` が `Validate() error` を持つかどうかを、実行時に見る（持たなければ、何もせず `true`）。違反があれば 400 を返して `false`。`validate = true` のときだけ出す |
| `httpWriteJSON(w http.ResponseWriter, status int, v any)` | 値を JSON にして返す |
| `httpWriteResult(w http.ResponseWriter, out any)` | 成功の応答。返す値があるかどうかを、実行時に見る（「通信の形」の「成功の応答」） |
| `httpWriteError(w http.ResponseWriter, err error)` | op が返したエラーを応答にする |
| `httpThrown[E runtime.Exception](w http.ResponseWriter, err error, status int) bool` | `err` が例外 E（値）なら、そのステータスと、例外の FQN（`E` の `HozoException()`）と、運ぶ値を返して `true`。値を運ぶ例外かどうか（例外の構造体が、引数ごとのフィールドを一つでも持つか。`docs/plugin-go.md`「exception」）は、実行時に見る。運ぶ値は、例外の値そのものの JSON（「失敗の応答」） |

```go
// httpWriteResult は、op が成功したときの応答。何を返すかは、実行時に、out で決める:
// 返す値がない（戻り値のない op は nil を渡す。省略可能な戻り値で、値がない）なら、204 で本文なし。
// あれば、200 と、その JSON。値のない配列（nil）は空の配列 [] に、値のない、インデックスの model（nil のマップ）は空のオブジェクト {} にする。
func httpWriteResult(w http.ResponseWriter, out any) {
	v := reflect.ValueOf(out)
	switch {
	case !v.IsValid(), v.Kind() == reflect.Pointer && v.IsNil():
		w.WriteHeader(http.StatusNoContent)
		return
	case v.Kind() == reflect.Slice && v.IsNil():
		out = reflect.MakeSlice(v.Type(), 0, 0).Interface()
	case v.Kind() == reflect.Map && v.IsNil():
		out = reflect.MakeMap(v.Type()).Interface()
	}
	httpWriteJSON(w, http.StatusOK, out)
}

func httpWriteError(w http.ResponseWriter, err error) {
	switch {
	case httpThrown[pkgtype.InvalidCredentials](w, err, 401):
	case httpThrown[rate.LimitExceeded](w, err, 429):
	case httpThrown[pkgtype.Unauthorized](w, err, 401):
	default:
		httpWriteJSON(w, http.StatusInternalServerError, httpErrorBody{Error: "internal"})
	}
}
```

- `httpValidate` は、`Validate` が返した `*runtime.ValidationError` の違反ごとに、`Path` の先頭（入力の model のフィールド名）を、場所の一覧の通りに置き換える（項目の形のフィールド `lines` の `lines[1].quantity` は `body.lines[1].quantity` に。全体の形のフィールド `body` の `body.email` は、場所が `body` なので `body.email` のまま）。
- `httpWriteError` は、経路の op のどれかが投げうる例外（`Op.signature.exceptions`）のうち、`@http.status(code)` を持つものを、最初に現れた順（op の宣言順、その中は `exceptions` の順）に、例外ごとに一行 `case httpThrown[<例外の型>](w, err, <code>):`。引数を持つ例外も、持たない例外も、同じ形（引数の数と型は、行を変えない）。例外の型は、その名前空間の型の置き場の入口のパッケージから import する。`@http.status` を持つ例外が一つもなければ、`switch` を書かず、いつも 500。
- 例外は値の型で見分ける。葉の実装が例外をポインタで返せば、見分けられずに 500 になる（基底の `throw` は値で返す。`docs/plugin-go.md`「exception」）。
- 補助に、受け付けない型の値が渡ることは、GOHTTP-4 と GOHTTP-5 が先に断るので、ない（そのときの振る舞いは、決めない）。読む先を型引数にしないのは、省略可能な読む先（`**T`）と、そうでない読む先（`*T`）を、一つの関数で、型を書かずに受け取れないため（Go は、その二つの和の制約から T を推論できない）。

## 通信の形

**この節は規範。** `@http.get` / `@http.post` の付いた op を HTTP で呼ぶとき、要求と応答は次の形をしていなければならない。サーバーを出すこのトランスパイラも、クライアントを出すトランスパイラも、これに合わせる。

### 要求

| 部分 | 形 |
|---|---|
| メソッドとパス | `@http.get(path)` は `GET <path>`、`@http.post(path)` は `POST <path>` |
| `@http.header` のフィールド | ヘッダ `<名前>`。値は、フィールドの値の文字列そのまま。値がない（省略可能で、ない）なら、ヘッダを送らない。空の文字列のヘッダは、ないものとして読まれる |
| `@http.query` のフィールド | クエリの `<名前>=<値>`。`string` はそのまま（URL のエンコードだけ）、`int` は 10 進、`float` は 10 進の小数か指数、`boolean` は `true` / `false`。値がないなら、送らない |
| `@http.body` のフィールド | 本文が、JSON のオブジェクトで、キー `<名前>` の値が、フィールドの値の JSON。`@http.body` のフィールドが一つでも、オブジェクトで包む。省略可能で値がないフィールドは、キーを省く。`Content-Type: application/json` |
| `@http.headerObj` / `@http.queryObj` のフィールド | その model のフィールドの一つずつが、フィールドの名前の、ヘッダ一つ、クエリの項目一つ（上の二行と同じ） |
| `@http.bodyObj` のフィールド | 本文が、その model の JSON（「値の JSON」）。フィールドの名前では包まない。`Content-Type: application/json` |

`<名前>` は、デコレータの引数。省いていれば、フィールドの名前（「対象」）。

**要求に項目がないときに、サーバーがどう読むかは、フィールドのデコレータで決まる。**

| フィールド | 項目を送らないと |
|---|---|
| `@http.required` | op は呼ばれず、400（「op を呼ぶ前の失敗」）。呼ぶ側は、必ず送る |
| `@http.default(v)` | サーバーが、v として読む。呼ぶ側は、v でよければ、送らなくてよい |
| どちらもない | サーバーは、零値として読む（省略可能なフィールドは、値がない） |

値を入れるのは、要求を読むサーバーで、呼ぶ側は、`@http.default` の値を自分では入れない。

### 値の JSON

| 型 | JSON |
|---|---|
| `string` | 文字列 |
| `int` | 数（整数）。64 ビットの範囲。2^53 を超える値は、数を倍精度で持つ言語では正確に読めない |
| `float` | 数 |
| `boolean` | `true` / `false` |
| `datetime` | RFC 3339 の文字列（小数部は 0〜9 桁、時刻帯は `Z` か `±hh:mm`） |
| `date` | `2026-11-21` の形の文字列 |
| `time` | `09:30:00` の形の文字列。秒より細かい部分は、小数部（書くときは、末尾の 0 を除く。読むときは、0〜9 桁） |
| `duration` | 数（整数のナノ秒） |
| scalar | 元の型の JSON |
| model | オブジェクト。キーはフィールド名（仕様に書いたまま）。並びはフィールドの順 |
| `optional(T)` のフィールド | 値がなければ、キーを省く。読む側は、キーがないことと `null` を、どちらも「ない」と読む |
| `array(T)` | 配列。読む側は、`null` も空の配列と読む（op の結果そのものが空の配列なら、必ず `[]` を返す。model の中の空の配列は、`[]` か `null`） |
| インデックスの model への `ref` | オブジェクト。キーは、キーの型の文字列 |
| union | 決めていない（GOHTTP-5） |

読む側は、知らないキーを無視する。

### 成功の応答

| 返す値 | ステータス | 本文 |
|---|---|---|
| ある | 200 | その JSON。`Content-Type: application/json`。空の配列は値で、`[]` |
| ない（戻り値のない op。省略可能な戻り値で、値がない） | 204 | なし |

- 一つの op が、呼び出しによって 200 も 204 も返す（省略可能な戻り値）。op の型では決まらず、返す値で決まる。`null` は返さない。
- 省略可能な配列と、省略可能な、インデックスの model（`T[]?`、`Attrs?`）を返す op は、経路にできない（GOHTTP-16。「対象」）: 値がないことと、空であることを、分けて返せない。
- 値のない配列（Go の `nil`）は、空の配列で、`[]` を返す。値のない、インデックスの model（Go の `nil` のマップ）は、空の構造で、`{}` を返す。

### 失敗の応答

本文は、どれも `Content-Type: application/json` の、例外の形:

```json
{ "error": "<例外の FQN>", "value": { "<引数の名前>": <その値の JSON>, … } }
```

- `value` は、**例外の引数の名前をキーにしたオブジェクト**（`exception LimitExceeded(retryAfter: duration);` なら `{"error":"rate.LimitExceeded","value":{"retryAfter":30000000000}}`）。キーの並びは、宣言の引数の順。値の形は「値の JSON」で、省略可能な引数で値がなければ、キーを省く。引数が一つでも、オブジェクトで包む。
- `value` は、引数のない例外にはない。

| 場合 | ステータス | 本文 |
|---|---|---|
| op が、`@http.status(n)` を持つ例外を投げた | n | `{"error":"<FQN>"}`。引数を持つ例外なら `value` を足す |
| op を呼ぶ前の失敗（下） | 400 | `{"error":"http.BadRequest","value":{"message":…,"violations":[…]}}` |
| それ以外（`@http.status` を持たない例外、保存先のエラー、中断を含むほかのエラー） | 500 | `{"error":"internal"}`（中身を出さない。`internal` は例外の FQN ではない） |

- 例外の FQN は、その例外を宣言した名前空間の名前を含む（`type.Unauthorized`）。例外を別の名前空間に移すと、通信の上の名前が変わる。
- 経路にない要求（404）と、メソッドの合わない要求（405）は、`net/http` の既定の応答（JSON ではない）。

### op を呼ぶ前の失敗

op を呼ぶ前の失敗は、`http` の語彙の例外 `http.BadRequest`（`docs/vocab.md`「同梱する語彙」）で伝える。`value` は、その二つの引数: `{"message": string, "violations": [{"path": string, "constraint": string}]}`（`violations` は、空でも `[]`）。op は呼ばない。

| 場合 | `message` | `violations` |
|---|---|---|
| 要求を入力に読めない（本文が JSON として読めない・型が違う、クエリが読めない、`@http.required` の付いた項目がない。「入力の読み方」） | `<場所>: <理由>` の決まった文言: `body: invalid JSON`、`query <名前>: invalid int`（`float`、`boolean`）、`<場所> <名前>: missing`（場所は `header`、`query`、`body`） | `[]` |
| 読んだ入力が制約に合わない（`validate = true` のときだけ） | `invalid input` | 違反の一覧。確かめた順 |

- 違反の `path` は、**通信の上の場所**（「入力の読み方」の末尾）と、その中のパス（`body.email`、`body.lines[1].quantity`、`query.page`）。入力の model のフィールド名（通信に現れない名前）は出さない。`constraint` は、`valid` の語彙のデコレータの名前（`min`、`length`、…）。
- 読めない要求が先で、次に制約の検査、その後に op。認証を op の中で確かめる仕様では、トークンのない要求でも、本文が制約に合わなければ 400 が先になる。

## 制約の検査

制約は型の性質で、いつ確かめるかを決めるのは、境界を持つこのトランスパイラ（`docs/plugin-go-valid.md`「この文書が決めること」）。

- 確かめるのは、単位のオプション `validate = true` のときだけ。確かめる相手は、入力。結果は確かめない。
- **入力が `Validate` を持つかどうかで、出すコードを変えない。** 入力を持つどの経路にも、同じ `httpValidate(w, in, …)` を出し、補助が、実行時に、`in` が `Validate() error` を持つかを見る（持たなければ、確かめるものがない）。
- 入力の model が**別の名前空間 M のもの**で、`Validate` を持つ型（`govalid.HasValidate`。`docs/plugin-go-valid.md`「Validate を持つ型」）なら、`Validate` は M の型の置き場（`docs/config.md`「型の置き場」）の定義のパッケージのメソッドなので、その単位も `transpilers` に `go-valid` を並べていなければならない。並べていなければ GOHTTP-11: 生成したコードはコンパイルできるが、`validate = true` と書いたのに、その入力は確かめられないまま op に渡る。書いたものの食い違いなので、error にする。置き場の単位の `transpilers` は `View.namespaces` にあるので、`View` だけから分かる（`govalid.Unlisted`。`docs/packages.md`「`plugin/govalid`（公開）」）。N の model は、自分の単位が `go-valid` を並べている（CFG-19）。
- 制約に合わない入力で投げる `http.BadRequest` は、設定で増える例外で、呼ぶ側の名前空間が仕様から計算する `throws` には現れない。読めない要求の `http.BadRequest` も同じ（`@http.get` / `@http.post` の `throws` に、まだ入れていない。`docs/vocab.md`「同梱する語彙」）。

## 補う値と制約

`@http.default` の値は、生成するときに、そのフィールドの制約（`@valid.*`。フィールドに付いたものと、型の scalar に付いたもの）で確かめる。合わなければ GOHTTP-19。書いたものどうしの矛盾なので、実行時の検査（合わなければ、その項目のない要求がいつも 400 になる）には任せない。`validate` の設定によらない。確かめるのは `plugin/govalid` の、値一つを制約で確かめる関数（`docs/packages.md`「`plugin/govalid`（公開）」）で、`go-cli` の `@cli.default` も同じ関数を使う（`docs/plugin-go-cli.md`「補う値と制約」）。

## インテグレーションテストの口

経路の op（「対象」）ごとに、インテグレーションテストを受け取る口と、それを、HTTP の層を通して走らせる関数を出す（`docs/decisions.md`「決めたこと」374、376、382〜391）。何を、本物で通し、何を、にせものにするか、どのケースを、Hozo が作るかの決まりの持ち主は、`docs/ide-chain.md`「テストの規約」の「インテグレーションテスト」「インテグレーションテストの作り直し」。Hozo が担保することと、確かめる所は、同「担保すること」。この節が決めるのは、HTTP の層と、Go での形。期待する出力の実物は、サンプル `tests/samples/shop-server/` の `gen/server/servertest/http.go`。

人が書くのは、口を満たす型と、それを走らせる関数に渡す、一行のテスト:

```go
func TestHTTP(t *testing.T) { servertest.RunHTTP(t, leaves, httpCases{}) }
```

### 置き場と名前

- 口は、N の**テストのパッケージ**（`docs/plugin-go.md`「単体テストの口」の「テストのパッケージ」。`gen/server/servertest`）に、`http.go` を一つ。先頭は `// Code generated by hozoc go-http <版>; DO NOT EDIT.`。経路の op が一つもなければ、出さない（「対象」）。
- **テストの中の組み立ては、基底のものを使う**: 同じパッケージの `Fakes` と `NewOps`（`docs/plugin-go.md`「テストのにせもの」。形は `golang.TestKitOf` で求める）。N の出力が、`fakes.go` を持たないとき:
  - `New` が、引数を取らない出力: にせものにするものがない。`Fakes` を使わない形で出す（「口の形」の最後の項）。
  - 組み立てを作れない出力（同「別の名前空間」: 呼ぶ先の名前空間に、同じ基底の単位が、二つ以上ある、など）: `http.go` と、テストの対応表を、出さず、warning を一つ返す（「診断」）。ハンドラ（入口のパッケージの `http.go`）は、出す。二つの単位を、どう組み合わせて通すかは、決めていない（`docs/open.md`「Hozo の側の改善する点」）。
- 公開の名前は、入口ごとの `<Op>HTTPCases` と `<Op>HTTPCase`、まとめの `HTTPCases`、走らせる `RunHTTP`。`<Op>` は、op のメソッドの名前（`docs/plugin-go.md`「名前」）。基底の `<Op>Cases` と分けるのは、経路の op が、葉でもありうるため（`export` の付いた、本体のない op に、`@http.get` を付けたもの）。非公開の名前は `http` で始める。
- 公開の名前が、テストのパッケージの、基底の公開の名前（`golang.PublicTestNames`。`docs/packages.md`「`plugin/golang`（公開）」）か、自分のほかの名前と当たれば、GOHTTP-20（葉 `fooHTTP` の `FooHTTPCases` と、経路の op `foo` の `FooHTTPCases`。分類 `HTTP` の `RunHTTP`）。
- 同じ単位が、子の名前空間 `N.<N のパッケージ名>test` を出力するなら、GOHTTP-21（基底が、同じことを GO-4 で返す出力では、重ねて返さない。`docs/plugin-go.md`「診断」）。
- import の名前の決まりは、テストのパッケージのもの（`docs/plugin-go.md`「単体テストの口」の「テストのパッケージ」: N の入口のパッケージは、いつも、名前を書いて import する）。import の名前に使わないのは、このファイルの関数の本体が、決まった名前で使う識別子: `t`、`c`、`k`、`f`、`cases`、`send`、`force`、`call`、`res`、`got`、`method`、`path`。
- 失敗の文面（`t.Fatalf`）は、英語で書く（基底と同じ）。
- 同じディレクトリに、`RunHTTP` のテストの、**テストの対応表** `hozo-tests.go-http.json` を出す。形と、行の取り方は、基底と同じ（`docs/plugin-go.md`「テストの対応表」。`golang.TestMap` で作る）: テスト一つは、いちばん内側の `t.Run`。Hozo が作るケースも、載る。

### 口の形

```go
	OK() LogoutHTTPCase
	// UnauthorizedAuthenticateAbsent は、例外 type.Unauthorized を、server.authenticate.Absent が投げるケース: 401。
	UnauthorizedAuthenticateAbsent() LogoutHTTPCase

type LogoutHTTPCase struct {

	// Given は、要求を送る前に、にせものに、流れの端が返す値を言う（nil なら、呼ばない）。
	Given func(f *Fakes)

}
```

- **`RunHTTP` の引数**は、`t`、人が書いたもの、`c`（`HTTPCases`）。人が書いたものは、`NewOps` が取るもの（`docs/plugin-go.md`「テストのにせもの」の「Fakes と NewOps」: 葉の実装と、分類の述語。本物を通す、別の名前空間の出力のものを含む）で、名前と並びは、同じ。このファイルの import の名前か、本体が決まった名前で使う識別子と当たれば、当たらなくなるまで、末尾に `_`。出来上がったハンドラは、受け取らない。
- **ケースごとに、新しく、組み立てる**（`send`）: `Fakes` を作り、`Given`、`force`（Hozo が作るケースが、にせものに言うこと）の順に呼び、`NewHandler(NewOps(f, …))` に、要求を送る。ケースの間で、何も、引き継がれない。
- **`<Op>HTTPCase` のフィールド**は、この順: 入力（op の引数。名前は、フィールド名と同じ決まりで、`Given`、`Request`、`Then` と当たれば、末尾に `_`。型は、入力の model。引数のない op には、ない）、`Given`、`Request`、`Then`。
- **`Given`** は、にせものに、流れの端（`read fn`、外の仕組みの op）が返す値を言う。言わなかった端は、零値を返す（`docs/plugin-go.md`「テストのにせもの」）。
- **`Request`** は、組み立てた要求を、送る前に、手直しする。`<Op>HTTPCase` の入力は、型の付いた値なので、読めない本文や、項目のない要求は、値では作れない。そのケース（`BadRequest`）と、入力の値では送れない形（`@http.default` の項目を送らない、など）のために置く。
- **`Then`** は、値を返す op なら `func(t *testing.T, got <結果の型>, res *httptest.ResponseRecorder, f *Fakes)`、返さない op なら `func(t *testing.T, res *httptest.ResponseRecorder, f *Fakes)`。走らせる側が、結果の見分けを済ませた後に、呼ぶ。どの効果が、何の値で呼ばれたかは、`f` で確かめる。例外が運ぶ値と、`http.BadRequest` の中身（`message`、`violations`）は、`res` の本文から読む。
- **経路を二つ以上持つ op**（「対象」）は、テスト一つの下に、経路ごとの段 `<メソッド> <パス>` を足し、経路ごとに、ケースを取り直して、送る（`send` は、引数 `method`、`path` を取る）。
- ケースを取り出すメソッド（`cases.OK()`）は、そのテストの中で、呼ぶ。
- **`Fakes` を使わない形**（N の出力の `New` が、引数を取らない）: `<Op>HTTPCase` に `Given` がなく、`Then` は、`f` を取らない。`send` は、`force` を取らず、応答だけを返す。ハンドラは、`NewHandler(<入口>.New())`。`RunHTTP` の引数は、`t` と `c`。

### 必要なケース

入口ごとに、次のテストを、この順に走らせる。数えるのは、ハンドラが、その経路から返しうる応答の種類（「通信の形」の「成功の応答」「失敗の応答」）で、例外は、出どころごと（`docs/ide-chain.md`「テストの規約」の「インテグレーションテストの作り直し」）。

| 結果 | テストの名前 | ある op | ケースを書くのは | 走らせる側が確かめること |
|---|---|---|---|---|
| 正常 | `<op>/OK` | `never` を返す op のほかの、どの op にも | 人か AI（口のメソッド `OK`） | 成功の応答。値を返さない op: 204 で、本文なし。値を返す op: 200 と、`Content-Type: application/json` と、結果の型に読める JSON（`null` でない）。結果が、Go でポインタになる省略可能な型（`type.Order?`）なら、204 で本文なし、でもよい（`got` は `nil`） |
| op を呼ぶ前の失敗 | `<op>/BadRequest` | 入力の model が、本文のデコレータ（`@http.body`、`@http.bodyObj`）のフィールドか、`@http.required` の付いたフィールドを、一つでも持つ op | 人か AI（口のメソッド `BadRequest`） | 400、`error` が `http.BadRequest`、`value` に、`message`（空でない文字列）と `violations`（配列） |
| 例外（出どころごと） | `<op>/<例外の名前>/<出どころ>` | op が投げうる例外（`Op.signature.exceptions` の順）の、出どころごと（`golang.ThrowSources` の順） | Hozo が作れる出どころ: Hozo。作れない出どころ: 人か AI（口のメソッド `<例外の名前><出どころの名前>`） | `@http.status(n)` を持つ例外: n、`error` が、例外の FQN。`value` は、引数を持つ例外なら、例外の型に読めるオブジェクトで、持たない例外なら、ない。持たない例外: 500 と `{"error":"internal"}` |
| 例外（出どころが、見つからない） | `<op>/<例外の名前>` | 流れを辿っても、投げるものが見つからない例外（読む者のないデコレータが運ぶ例外など） | 人か AI（口のメソッド `<例外の名前>`） | 同じ |

- **出どころ**と、**Hozo が作れるか**は、`golang.ThrowSources`（`docs/packages.md`「`plugin/golang`（公開）」）で求める。決まりの持ち主は、`docs/ide-chain.md`「テストの規約」の「インテグレーションテストの作り直し」の「Hozo が作る、例外のケース」。
- **出どころの書き方**:

| 出どころ | テストの名前の `<出どころ>` | 口のメソッドの `<出どころの名前>` |
|---|---|---|
| 葉の op、効果、外の仕組みの op、`never` を返す op | その FQN（`server.requireFresh`、`mailer.send`） | メソッドの名前（`RequireFresh`、`Send`） |
| 配線の `match` の、`throw` のアーム | `<配線の op の FQN>.<ケース>`（`server.sessionOf.LoggedOut`）。アームが、二つ以上のケースを受けるなら、`+` でつなぐ | op のメソッドの名前と、ケースの名前を、先頭大文字でつないだもの（`SessionOfLoggedOut`） |
| 継ぎ目（op に付いたデコレータ） | `<op の FQN>@<デコレータの FQN>`（`server.login@rate.limited`） | 継ぎ目のメソッドの名前（`LoginRateLimited`） |

- **例外の名前**は、基底と同じ決まり（`docs/plugin-go.md`「単体テストの口」の「葉の op」の「結果の名前」）: 宣言の名前。その op の中で、名前が当たる例外（別の名前空間の、同じ名前の例外。例外 `OK`、`BadRequest`）は、名前空間のセグメントを先頭大文字にして、前に付ける。
- **`t.Run` の重ね方**: op、結果（`OK`、`BadRequest`、例外の名前）、例外なら、出どころ。出どころが見つからない例外は、例外の名前の段が、テスト。
- **Hozo が作るケース**は、正常のケース（`cases.OK()`）を取り、その `Given` の後に、`force` で、にせものに言う（`ThrowSources` の `Steps` を、順に、一行ずつ）。確かめるのは、応答が、その例外のものであること。`Then` は、呼ばない。

| `Steps` の種類 | Go の一行 |
|---|---|
| 例外を投げる | `f.<パス>.Throws(<例外の型>{})` |
| 「ない」を返す | `f.<パス>.Returns(nil)` |
| 状態の分類の述語が、真偽を返す | `f.<パス>.Returns(true)` / `f.<パス>.Returns(false)` |
| 値の分類・op の分類の判定が、そのケースになる | `f.<パス>.Is(<ケースの定数>)` |

- **`never` を返す op**（正常のケースがない）の例外は、どれも、人か AI が書く。
- **例外は、デコレータが運ぶものも数える**（`@rate.limited` の `rate.LimitExceeded`）。数える集合は、`httpWriteError` が見分ける例外（「補助」）と同じ `Op.signature.exceptions`。
- **`BadRequest` を数える op は、デコレータだけで決める**（型は見ない。`docs/requirements.md`「出力を推論しない」）。本文のデコレータがあれば、読めない本文を送れる。`@http.required` があれば、その項目を省ける。どちらも、`Request` で、いつでも作れる。ヘッダと、`@http.required` のないクエリだけの入力（`AuthInput`）は、どう送っても、読めない要求にならないので、数えない。クエリの値が読めない（`query page: invalid int`）ことと、制約の違反（`validate = true`）は、型で決まるので、数える理由にしない。`BadRequest` を持つ op のケースを、制約に合わない入力の値で書くことは、できる（`Request` は要らない）。
- **`@http.status` を持たない例外は、応答では、見分けられない**（どれも、500 と `internal`）。走らせる側が確かめるのは、そこまで。
- 人か AI が書く出どころが増えるか、`@http.required` を初めて付ければ、`<Op>HTTPCases` のメソッドが一つ増え、口を満たしていた型は、`RunHTTP` に渡すところで、コンパイルできなくなる。Hozo が作れる出どころが増えたときは、テストが、増えるだけ。
- `@http.*` の付かない `export` の op には、この口は、出ない（`docs/open.md`「語彙とプラグイン」）。

### 要求の組み立て

走らせる側は、入力の値から、要求を、「通信の形」の「要求」のとおりに組み立てる。「入力の読み方」の裏返しで、フィールドごとに、デコレータと、その引数（か、フィールドの名前）だけで決まる一行:

| デコレータ | Go |
|---|---|
| `@http.header` | `call.header("<名前>", k.<入力>.<F>)` |
| `@http.query` | `call.query("<名前>", k.<入力>.<F>)` |
| `@http.body` | `call.body("<名前>", k.<入力>.<F>)` |
| `@http.headerObj` | `call.headerObj(k.<入力>.<F>)` |
| `@http.queryObj` | `call.queryObj(k.<入力>.<F>)` |
| `@http.bodyObj` | `call.bodyObj(k.<入力>.<F>)` |

- `@http.required` と `@http.default` は、行を変えない: 入力の値は、いつも、送る。値がない（省略可能なフィールドで、`nil` のポインタ）ときだけ、ヘッダ、クエリの項目、本文のキーを、送らない。省略可能でないフィールドの項目を送らない要求は、`Request` で作る。
- ヘッダとクエリの値の文字列は、補助 `httpText` が、実行時に、値の型で決める（文字列はそのまま、整数は 10 進、小数は `strconv.FormatFloat(v, 'g', -1, 64)`、真偽値は `true` / `false`）。クエリは、URL のエンコードをする。
- 本文の項目（`@http.body`）があれば、本文は、JSON のオブジェクトで、キーは、フィールドの順。項目が一つも送られなくても、`{}` を送る。本文の全体（`@http.bodyObj`）は、その model の JSON。どちらも、`Content-Type: application/json` を付ける。値の JSON は、`encoding/json` と、基底の型のタグが決める（「値の JSON」）。
- 入力の値から、組み立てられない要求は、ない: 入力の model のフィールドは、どれも、六つのデコレータの一つを持ち（GOHTTP-3）、型は、その場所が受け付けるもの（GOHTTP-4、GOHTTP-5、GOHTTP-12）。
- 送り方は、`httptest.NewRequest` と `httptest.NewRecorder` で、`handler.ServeHTTP` を、直に呼ぶ。ネットワークは、使わない。

### テストの補助

テストのパッケージの `http.go` の、`RunHTTP` の後ろに、この順で出す。中身は、サンプルの `gen/server/servertest/http.go` の通りで、型にも、仕様にも依らない。

| 名前 | 中身 | 出すとき |
|---|---|---|
| `httpCall`、`httpItem` | 送る要求一つと、本文の項目一つ | いつも |
| `httpCall` のメソッド `header`、`query`、`body`、`headerObj`、`queryObj`、`bodyObj` | 「要求の組み立て」の表の一行 | 使うものだけ |
| `httpCall` のメソッド `send(t, handler, edit)` | 要求を組み立て、`edit` を呼んでから、`handler` に送り、応答を返す | いつも |
| `httpText` | ヘッダとクエリの値の文字列 | ヘッダかクエリを使うとき |
| `httpFields` | 全体の形の model のフィールドの一つずつを、`json` タグの名前の項目にする | `headerObj` か `queryObj` を使うとき |
| `httpWantResult(t, res, dst)` | 成功の応答であることを確かめ、値を `dst` に読む（値を返さない op は `nil` を渡す） | いつも |
| `httpWantBadRequest(t, res)` | op を呼ぶ前の失敗であることを確かめる | `BadRequest` のケースがあるとき |
| `httpWantThrown[E runtime.Exception](t, res, status)` | 例外 E の失敗の応答であることを確かめる。値を運ぶ例外かどうかは、実行時に見る（`httpThrown` と同じ見方。「補助」） | `@http.status` を持つ例外のテストがあるとき |
| `httpWantInternal(t, res)` | 500 と `internal` であることを確かめる | `@http.status` を持たない例外のテストがあるとき |
| `httpWantFailure(t, res, status, name)` | 失敗の応答の本文の形と、`error` を確かめ、`value` を返す | 上の三つのどれかを出すとき |
| `httpWantJSON(t, res, status)` | ステータスと、`Content-Type: application/json` を確かめ、本文を返す | いつも |

`emit` の応答の `errors` で返す。位置は、表に書いた宣言の FQN。

| GOHTTP-17 | error | 一つのフィールドに、`@http.required` と `@http.default` の両方がある。見るフィールドと位置は GOHTTP-14 と同じ |
| GOHTTP-18 | error | `@http.default` のリテラルが、フィールドの型（scalar は元の核の型）に渡せない（「対象」）。メッセージに、フィールド、リテラル、型を示す。見るフィールドと位置は GOHTTP-14 と同じ |

| GOHTTP-20 | error | テストのパッケージに足す公開の名前（`<Op>HTTPCases`、`<Op>HTTPCase`、`HTTPCases`、`RunHTTP`）が、そのパッケージの、基底の公開の名前か、自分のほかの名前と当たる。`<Op>HTTPCases` のメソッドの名前どうしが当たるときも（名前空間を前に付けても、同じ名前になる二つの例外。例外の名前と、出どころの名前をつないだものが、同じになる二つのケース。「インテグレーションテストの口」）。位置は、当たった自分の名前を生んだ経路の op。決まった名前（`HTTPCases`、`RunHTTP`）が当たったなら、相手の名前を生んだ宣言（葉の op か、分類） |
| GOHTTP-21 | error | テストのパッケージのディレクトリが、同じ単位が出力する、子の名前空間 `N.<N のパッケージ名>test` の出力先と重なる（「インテグレーションテストの口」の「置き場と名前」）。基底が、同じことを GO-4 で返す出力（基底も、テストのパッケージを作る）では、返さない。置き場が要るので、`go.mod` がないときも、返さない。位置は、最初の経路の op |

warning（コードは `PLUGIN`）は二つ: 経路の op が一つもない。N の出力の、テストの中の組み立てを、作れない（「インテグレーションテストの口」の「置き場と名前」。メッセージに、理由を入れる。テストのパッケージの `http.go` と、対応表は、出さない）。

- GOHTTP-3〜GOHTTP-6、GOHTTP-11〜GOHTTP-19 は、書いたものの整合の検査: デコレータが言ったことと、model と op の宣言が食い違っていれば、出力を型に合わせて変えずに error にする（`docs/requirements.md`「出力を推論しない」）。
- Dir(U, N) の上に `go.mod` がないとき（同じ単位の基底が GO-1 を返し、何も書き出されない。`docs/plugin-go.md`「診断」）は、ファイルを返さず、GO-1 も重ねて返さない。上の診断は、GOHTTP-21 のほかは、そのときも返す。
- 生成器の不具合（`View` が欠けている、生成したコードを `go/format` で整形できない）は、診断にせず、異常終了する（`proc.Crashed`。`docs/plugin-protocol.md`「起動」）。
