# go-cli プラグイン

## この文書が決めること

`cli` の語彙（このプラグインの語彙のファイル `plugins/go-cli/cli.hozo`。リポジトリ直下の `cli.hozo`（hozoc 自身の仕様。`docs/cli.md`）とは別のファイル。出典は設計書の `examples/hozoc.hozo`）を Go の CLI の骨組みにするトランスパイラ `go-cli`。Go の基底 `go`（`docs/plugin-go.md`）と、検証の `go-valid`（`docs/plugin-go-valid.md`）に相乗りする。プラグインは `plugins/go-cli/`。hozoc 自身の骨組みもこれで生成する（`docs/requirements.md`「自己展開」）。

## マニフェスト

```toml
name     = "go-cli"
command  = ["go", "run", "github.com/mew-ton/hozo/plugins/go-cli"]
protocol = "0.4"

vocabulary = ["cli.hozo"]

[[transpiler]]
name     = "go-cli"
language = "go"
requires = ["go", "go-valid"]
```

- 提供するトランスパイラは `go-cli` の一つ（`hozo.toml` の `transpilers = ["go", "go-valid", "go-cli"]` で選ぶ）。要求の `transpiler` がそれ以外なら `code: "unsupported"`（`docs/plugin-protocol.md`「要求と応答」）。
- `cli` の語彙はこのプラグインが提供する（`docs/vocab.md`「同梱しない語彙」）。`plugins/go-cli/cli.hozo`（マニフェストの `vocabulary = ["cli.hozo"]` はマニフェストからの相対パス）の中身は `examples/hozoc.hozo` の `namespace cli` を写し、`x?: T` は `x: T?` に直す。
- 読む語彙は、`cli` の `command` / `arg` / `flag` / `env` / `exitCode`。`@proc.stdio` などのほかの語彙は読まない（基底が、付いた op を人が実装する葉として出す）。
- `go-valid` に依存するのは、解釈した入力の制約を確かめるため（「引数の解釈」）。
- オプションはない。`[emit.options.go-cli]` にキーがあれば CLI-8。
- `command` が `go run` なのは、このリポジトリの中で `plugin_dirs = ["plugins"]` から使うため（配布のしかたは `docs/plugin-go.md`「マニフェスト」）。

## 出力

`View.viewer` の名前空間 N について、`View.config.dir` の下に `cli/cli.go`（パッケージ `cli`）を一つ（`docs/plugin-go.md`「相乗りのファイル」）。`@cli.command` の op が一つもなければファイルを出さず warning を一つ返す。先頭は `// Code generated by hozoc go-cli <版>; DO NOT EDIT.`。N の入口のパッケージと、例外の型の置き場の入口のパッケージ（別の名前空間の例外。`hozoc` なら `proc`）を import する。import パスと名前は `plugin/golang`（`docs/packages.md`「`plugin/golang`（公開）」）で求める。

```go
// Main は引数を解釈して ops の op を呼び、結果を p で表示し、終了コードを返す。ctx は op にそのまま渡す。
func Main(ctx context.Context, ops hozoc.Ops, p Presenter, args []string, env func(string) string, stdout, stderr io.Writer) int

// Presenter は結果と例外の表示。既定は JSON（JSONPresenter）。
type Presenter interface {
    Present(w io.Writer, command string, input any, result any) error
    PresentError(w io.Writer, command string, input any, f Failure) error
}

// Failure は例外の内容。Name は例外の FQN、Value は運ぶ値、Err は op が返した error そのもの（Presenter がメッセージに使える）。
// 生成した cli.go が例外の型を見分けて入れる。宣言にない例外なら Name は空で Err だけ
type Failure struct { Name string; Value any; Err error }

type JSONPresenter struct{}
```

- `Main` は `package main` ではない。人が書く `main.go` は、実装を組み立てて `os.Exit(cli.Main(ctx, ops, p, os.Args[1:], os.Getenv, os.Stdout, os.Stderr))` を呼ぶだけ。
- `ops` の型は、N の入口の `Ops`（`docs/plugin-go.md`「Ops」）。基底の `New` の戻り値を、そのまま渡す。
- 同じ単位が、N の子の名前空間 `N.cli` を出力するなら CLI-7（Dir(U, N.cli) が、このパッケージのディレクトリと重なる）。
- パッケージ `cli` の非公開の名前は、コマンドごとの `run<Op>` / `fail<Op>` / `usage<Op>`（`<Op>` は op 名を先頭大文字にしたもの）と、補助の `cli<名前>`（`cliUsage`、`cliParseArgs` など。使うものだけを出す）。どれも大文字を含むので、import する名前空間のパッケージの名前（小文字と数字だけ）とは当たらない。パッケージの変数は持たない。
- `Main` とコマンドごとの関数の中の局所の名前（`ctx`、`ops`、`p`、`args`、`env`、`in`、`err` など）が、このファイルが import するパッケージの名前（N と、例外の名前空間のパッケージ）と当たれば、局所の名前の方の末尾に `_` を足す（`docs/plugin-go.md`「名前」の「局所の名前」と同じ扱い。名前空間 `env` なら、`Main` の引数は `env_`）。

## 対象

`View.viewer` の名前空間の op のうち、単位の対象（`docs/config.md`「in」。`View.files`）で、`@cli.command(name)` の付いたものがサブコマンド（`plugin.OpsWith`）。

- **`@cli.command` の付いた op は `export` が付いていなければならない。** `Main` は、名前空間の外から、入口の `Ops`（`export` の op だけ）を通して op を呼ぶ。付いていなければ CLI-6（`go-http` の GOHTTP-1 と同じ理由。`docs/plugin-go-http.md`「対象」）。
- 引数は 0 個か、model 一つ。それ以外は CLI-1。
- 引数の model の各フィールドは、`@cli.arg`、`@cli.flag(name)`、`@cli.env(name)` のどれかを持つ。`@cli.env` は `@cli.arg` か `@cli.flag` と一緒に付けられる（与えられなかったときの代わり）。`@cli.arg` と `@cli.flag` の両方、またはどれもなければ CLI-2。
- フィールドの型は `string`、`boolean`、`int`、`float`、元がこれらの `scalar`、またはそれらの `optional`、`@cli.arg` に限り `string`（と `string` の scalar）の `array`（`optional` は付けない。0 個を表せるため）。それ以外（model、`Record`、`Time`、`optional` の `array`）は CLI-3。
- `@cli.arg` の `array` のフィールドは、`@cli.arg` のフィールドの中で最後の一つだけ。違えば CLI-4。
- `@cli.arg` に `boolean` は付けられない（CLI-3）。
- 同じ `@cli.flag` の名前、同じ `@cli.command` の名前が二つあれば CLI-5。

CLI-* は emit の応答の `errors` で返す（`docs/plugin-protocol.md`「emit」）ので、どれも error の診断になる。

## 引数の解釈

```
hozoc <command> [flags] [args]
```

- `<command>` がなければ使い方を標準エラーに出して 64。`help` か `--help` / `-h` なら使い方を標準出力に出して 0。`<command> --help` はそのコマンドの使い方。
- フラグは `--name value`、`--name=value`。`boolean` は `--name` で true（値は取らない。`--name=false` は取れる）。同じフラグが二度あれば後のものが勝つ。`-x` の形はフラグではなく位置引数（`-h` を除く。負の数を渡せるようにするため）。`--` 以降は位置引数。
- 知らないフラグ、フラグの値がない、値を型に変換できない（`int` に `"x"`）、必須のフラグがない、位置引数が足りない・多い → 使い方を標準エラーに出して 64。
- 必須: 型が `optional` でなく、`default` もないフィールド。
- `@cli.env` は、フラグが与えられなかったときに環境変数の値を使う（フラグが優先）。環境変数が空文字列なら「ない」とみなす。
- `@cli.arg` は `@cli.arg` のフィールドの宣言順に位置引数を当てる。`array` は残りすべて（0 個でもよい）。
- 値の変換: `int` は `strconv.ParseInt(v, 10, 64)`、`float` は `ParseFloat`、`boolean` は `ParseBool`。scalar は元の型で変換してから scalar の型にする。
- 解釈した入力の model が `Validate` を持つなら（`govalid.HasValidate`。`docs/plugin-go-valid.md`「Validate を持つ型」）、`Validate()` を呼び、違反は 64（メッセージに `Violation` の `Path` と `Constraint`。使い方は出さない）。入力の初めの値は、既定値を持つ model なら基底の `New<Model>()`、そうでなければ零値。
- 入力の model が**別の名前空間 M のもの**なら、`Validate` は M の型の置き場（`docs/config.md`「型の置き場」）の定義のパッケージのメソッドなので、その単位も `transpilers` に `go-valid` を並べていなければならない。並べていなければ CLI-9（生成した `in.Validate()` がコンパイルできなくなるのを、先に報告する。`go-http` の GOHTTP-11 と同じ。`docs/plugin-go-http.md`「制約の検査」。確かめ方は `govalid.Unlisted`）。N の model は、自分の単位が `go-valid` を並べている（CFG-19）。

## 実行と表示

1. `ops.<Op>(ctx, input)` を呼ぶ（引数が 0 個なら `ops.<Op>(ctx)`）。`@cli.command` の付いた op はデコレータを持つので、いつも `ctx` を取り、`error` を返す（`docs/plugin-go.md`「op の形」）。
2. 成功なら `p.Present(stdout, command, input, result)` を呼び（void なら `result` は `nil`）、0。
3. 例外なら、`Signature.exceptions` の順に `errors.As` で例外の値の型を見分けて `Failure` を作り（例外は値で返る。`docs/plugin-go.md`「exception」）、終了コードを決めてから `p.PresentError(stderr, command, input, failure)` を呼ぶ。終了コードは、見分けた例外に `@cli.exitCode(code)` があればその `code`、なければ 70。見分けられなければ `Failure{Err: err}` で 70。
4. `Present` / `PresentError` 自体が失敗したら、そのエラーを標準エラーに出して 70。

`JSONPresenter`:

- `Present`: `result` を `json.MarshalIndent(result, "", "  ")` で標準出力に。`nil` なら何も出さない。
- `PresentError`: `Name` があれば `{"error": "<Name>", "value": <Value>}`（`Value` が `nil` なら `value` を省く）を、なければ `{"error": "<Err.Error()>"}` を標準エラーに。

## 使い方の表示

```
usage: hozoc <command> [flags]

commands:
  check   仕様を検査する。ファイルは書き出さない
  emit    仕様を検査し、単位ごとにトランスパイラを呼んで、生成したファイルを書き出す
```

- コマンドの一行は `Op.description.summary`。コマンドごとの使い方は、フィールドの `description.summary` を `--flag` / `ARG` / `ENV` と並べる。
- 使い方に出すプログラム名は `filepath.Base(os.Args[0])`。`Main` の `args` は `os.Args[1:]` の約束で、プログラム名を含まない。

## Go の名前

N のパッケージと、その型・メソッドの名前と形は `plugin/golang`（`docs/packages.md`「`plugin/golang`（公開）」）で求める。この文書は、基底の規則を書き写さない（`docs/plugin-protocol.md`「相乗りが基底の形を知る方法」）。

## 診断

| ID | 重さ | 意味 |
|---|---|---|
| CLI-1 | error | `@cli.command` の op の引数が、0 個でも model 一つでもない。位置は op |
| CLI-2 | error | 入力の model のフィールドに `cli` のデコレータがない、または `@cli.arg` と `@cli.flag` の両方がある。位置は model |
| CLI-3 | error | フィールドの型が受け付けられない。位置は model |
| CLI-4 | error | `array` の `@cli.arg` が最後でない、または二つ以上。位置は model |
| CLI-5 | error | フラグ名かコマンド名の重複。位置は、フラグ名なら model、コマンド名なら後ろの op |
| CLI-6 | error | `@cli.command` の付いた op に `export` がない。位置は op |
| CLI-7 | error | このトランスパイラのディレクトリ `cli` が、同じ単位が出力する子の名前空間 `N.cli` の出力先と重なる。位置なし |
| CLI-8 | error | `[emit.options.go-cli]` に、知らないキーがある。位置なし |
| CLI-9 | error | `Validate` を持つ入力の model が別の名前空間のもので、その名前空間の型の置き場の単位が `go-valid` を並べていない（「引数の解釈」）。メッセージに、その単位（何番目の `[[emit]]` か）を示す。位置は op |

warning（コードは `PLUGIN`）は一つ: `@cli.command` の op が一つもない。

- 入力の model の診断（CLI-2〜CLI-5 のフラグ名）は、同じ model を二つのサブコマンドが使っていても、一度だけ返す。
- Dir(U, N) の上に `go.mod` がないとき（同じ単位の基底が GO-1 を返し、何も書き出されない。`docs/plugin-go.md`「診断」）は、ファイルを返さず、GO-1 も重ねて返さない。上の診断は、そのときも返す。
- 生成器の不具合（`View` が欠けている、生成したコードを `go/format` で整形できない）は、診断にせず、異常終了する（`proc.Crashed`。`docs/plugin-protocol.md`「起動」）。
