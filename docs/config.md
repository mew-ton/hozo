# hozo.toml

## この文書が決めること

プロジェクトの設定ファイル `hozo.toml` の形と読み方、設定に関わる検査（CFG-*）。設計書 §4.5 の名前空間ごとの設定を、出力の単位の一覧に変えたもの（`docs/decisions.md`「設計書を変える決定」S14）。読むのは `internal/config`。

## 置き場と探し方

- `hozoc` は `--config <path>` か環境変数 `HOZO_CONFIG` で指定されたファイルを読む。どちらもなければ、作業ディレクトリから親へ向かって最初に見つかる `hozo.toml`。指定されたファイルが読めなければ CFG-7（`ConfigInvalid`。`docs/diagnostics.md`「終了コード」）。指定がなく、どこにも見つからなければ「設定なし」で、何も出力せず、設定の検査（CFG-*）もプラグインの探索も行わない。`hozoc check` と `hozoc lsp` は設定なしで動き、`hozoc emit` は書き出すものがないので CFG-7。設計だけの段階で検査できるようにするため（`docs/requirements.md`「モデルが先」）。
- `hozo.toml` のあるディレクトリが**プロジェクトのルート**。`.hozo` の探索、`in`、`out`、プラグインの探索の起点。

## 形

```toml
[hozo]                              # 全体の設定。省略できる
sources      = ["**/*.hozo"]        # ルートからの glob。既定はこの一つ。各単位の out の下と、plugin_dirs の下は常に除く（隠しディレクトリは除かない）
plugin_dirs  = ["plugins"]          # プラグインを探すディレクトリ（docs/plugin-protocol.md「探索」）。ルートからの相対パス。既定は []
max_bindings = 5                    # WIRE-6 の閾値（docs/check.md「配線」）。既定はそこに書いた値

[[emit]]                            # 出力の単位。いくつでも書ける。書いた順が「設定の順」
in          = ["api/**/*.hozo"]     # 省略できる。ルートからの glob。既定は読み込んだすべてのファイル
namespace   = "server"              # 必須。視点の名前空間（FQN）
transpilers = ["go-http", "sqlc"]   # 必須。一つ以上。トランスパイラの名前（docs/plugin-protocol.md「探索」）
out         = "api/internal/generated"   # 必須。ルートの下のディレクトリを、ルートからの相対パスで

[[emit]]
namespace   = "server"              # 同じ名前空間を複数の単位に書ける
transpilers = ["go-cli"]
out         = "cmd/gen"
```

- TOML の読み込みは `github.com/BurntSushi/toml`（`docs/packages.md`「依存の向き」）。
- トップレベルに書けるのは `[hozo]` と `[[emit]]` だけ。ほかのキーは CFG-7。名前空間ごとのテーブル（`[server]`）はない。名前空間の名前に使えない名前もない。
- 知らないキー、値の型違いは CFG-7。`emit` はテーブルの配列（`[[emit]]`）で、テーブル一つ（`[emit]`）は CFG-7。CFG-7 か CFG-12 のあった単位は使わない（ほかの単位はそのまま読む）。
- `out` はプロジェクトのルートの下のディレクトリ。絶対パス、ルートの外へ出るパス（`../gen`。`./` や `..` を畳んだ後で見る）、ルートそのもの（`.`）は CFG-7。ルートの外を許さないのは、hozoc が書いて消すファイルをプロジェクトの中に限るため（`docs/cli.md`「emit」）。ルートそのものを許さないのは、`out` の下が `sources` から常に除かれ、何も読めなくなるため。
- `[[emit]]` を一つも書かなければ、何も出力しない（検査はできる）。

## 単位

`[[emit]]` の一つが**単位**。一つの単位は、どのファイルを（`in`）、どの名前空間から見て（`namespace`）、どのトランスパイラで（`transpilers`）、どこへ書き出すか（`out`）の組。

- 設定が選ぶのはトランスパイラで、プラグインではない（二つの言葉の定義は `docs/plugin-protocol.md`「この文書が決めること」）。プラグインを入れるとトランスパイラが増え、設定はその中から使うものを名前で選ぶ。
- 名前空間ごとのテーブルに `language` と `plugins` を書き、子の名前空間が継ぐ形（§4.5）をやめた理由: 「プラグインが処理を決める」形は、どの設定がどの出力を作るのかが読み取りにくい。単位にすれば、入力・視点・変換・出力先が一か所に並ぶ（Vite の「プラグインを入れる」と「設定で使う」の分け方と同じ）。同じ名前空間から、トランスパイラごとに別の出力先へ書き出すこともできる。
- 単位の**言語**は、そのトランスパイラの `language`（マニフェストが持つ）。一つの単位のトランスパイラの言語はそろっていなければならない（CFG-16）。設定に `language` は書かない。
- `transpilers` の名前からトランスパイラを探す手続き（どのプラグインのものか、見つからないとき、二つ以上あるとき）は `docs/plugin-protocol.md`「探索」。

## 単位の対象

名前空間 N（FQN）を**対象にする単位**は、次の手続き（CFG-13）で決まる。単位 U から見れば、U が対象にする名前空間が **U の対象の名前空間**（単に「単位の対象」と言えばこれ）。

1. A(N) は、N とその祖先のうち、どれかの単位の `namespace` に書かれている最も近いもの（N 自身が書かれていれば N）。どれも書かれていなければ、N を対象にする単位はない。
2. N を対象にする単位は、`namespace` が A(N) であるすべての単位（設定の順）。

つまり、単位はその `namespace` とすべての子孫を対象にする。ただし、別の単位が子孫の名前空間を `namespace` に書いていれば、その子孫と、その下のすべては、祖先の単位の対象から外れる。

- どの単位の対象にもならない名前空間は出力せず、エラーにもしない（人の操作や外部のシステムのように、コードを生成しない部分をモデルに含められる。`docs/requirements.md`「モデルが先」）。検査は出力しない名前空間にも同じに掛かる。
- 単位 U での名前空間 N の出力先 Dir(U, N) は、`U.out` に、`U.namespace` から N までのセグメントをパスにして足したもの（N が `U.namespace` 自身なら `U.out`、`namespace = "server"` の単位での `server.admin` なら `<out>/admin`）。既定の出力もトランスパイラも、U での N のファイルは Dir(U, N) の下に置く（トランスパイラがそこでないパスを返せば PLG-1。`docs/plugin-protocol.md`「emit」）。
- 単位の出力先は `out` とその下のすべて。二つの単位の `out` が同じか、一方が他方の下にあれば CFG-17（比べるのは、`./` や余分な `/` を取り除いたパス。「形」の CFG-7 で使えなかった単位は比べない）。出力先ごとの記録（`docs/cli.md`「emit」の `.hozoc-outputs.json`）と、Dir(U, N) の持ち主を一つに決めるため。
- 同じ名前空間を対象にする複数の単位は、互いに独立。それぞれが自分の `out` に、自分のトランスパイラが選んだ宣言の出力をすべて持つ（`docs/emit-go.md`「出力の対象」）。

## in

- `in` は、単位が出力する範囲をファイルで絞る。glob の書き方は `sources` と同じで、照らす相手は読み込んだファイル（`sources` に合い、除かれなかったもの）。`in` はファイルを読み足さない。省略すれば、読み込んだすべてのファイル。
- **単位の対象の宣言**は、単位の対象の名前空間の宣言のうち、`in` に合うファイルに書かれたもの。対象の名前空間が、`in` に合うファイルに宣言を一つも持たなければ、その単位はその名前空間を出力しない（トランスパイラも起動しない）。
- 単位 U と、U が出力する名前空間 N（U の対象の名前空間のうち、単位の対象の宣言を一つでも持つもの）の組 (U, N) を**出力**と呼ぶ。出力ごとにトランスパイラを起動し（`docs/plugin-protocol.md`「起動」）、既定の出力を一度作り（`docs/emit-go.md`）、Dir(U, N) に書き出す（`docs/cli.md`「emit」）。「対象」と付く言葉はほかに二つあり、どれも別のもの: 出力の中に何の宣言を出すかが**出力の対象**（`docs/emit-go.md`「出力の対象」）、一度の `hozoc emit` がどの出力を書き出すかが **emit の対象**（`docs/cli.md`「emit」）。
- 検査は変わらない。`sources` の全体を一つのプログラムとして読み、検査する。`in` が絞るのは出力だけ。
- トランスパイラが選べるのは単位の対象の宣言だけ（`docs/plugin-protocol.md`「選択」）。`in` の外の宣言が出力にどう現れるかは `docs/emit-go.md`「出力の対象」。
- `in` の glob が、読み込んだファイルのどれにも合わなければ CFG-18。

単位の設定と Dir(U, N)、`in` に合ったファイルは、`View.config`、`View.namespaces`、`View.files` としてトランスパイラに渡す（`docs/ir.md`「その名前空間から見た IR」）。

## 診断

| ID | 重さ | 手続き |
|---|---|---|
| CFG-5 | error | 書き出すファイルのパス（ルートからの相対パスに正規化したもの）が、二つ以上の出どころ（既定の出力、各トランスパイラ）から出た。出どころを `Related` 相当としてメッセージに示す。何も書き出さない。例外は `OutputConflict` |
| CFG-6 | warning | 単位のトランスパイラのマニフェストの `unsupported` にあるデコレータの FQN が、その単位の対象の宣言に付いている。付いた位置に出す |
| CFG-7 | error | 知らないキー（`hozo` と `emit` 以外のトップレベルのキーを含む）、値の型違い、TOML の構文エラー、一つの単位の `transpilers` に同じ名前が二度ある、単位の `out` がルートの下のディレクトリでない（絶対パス、ルートの外、ルートそのもの。「形」）。`--config` か `HOZO_CONFIG` で指定されたファイルが読めないとき（「置き場と探し方」）と、設定なしで `hozoc emit` したとき（`docs/cli.md`「手で書くもの」）も CFG-7 |
| CFG-8 | error | 単位の `namespace` が語彙の名前空間（`docs/vocab.md`「語彙の名前空間」）である。または、その名前空間とその子孫のどれも `state` と `op` を持たない（`namespace` に書いた名前空間が自分では持たなくても、子孫が持っていればよい） |
| CFG-10 | error | 単位の `namespace` の名前空間も、その子孫も `.hozo` にない |
| CFG-11 | error | 単位の言語が `"ts"` だが、TS の既定の出力はまだない（段階 5 まで） |
| CFG-12 | error | 単位に `namespace` / `transpilers` / `out` のどれかがない、または空（空の文字列、空の配列）。その単位は使わない |
| CFG-13 | — | 対象の手続き（「単位の対象」）。診断なし |
| CFG-14 | error | `transpilers` の名前のトランスパイラを、入っているどのプラグインも提供していない（探し方は `docs/plugin-protocol.md`「探索」） |
| CFG-15 | error | `transpilers` の名前のトランスパイラを、二つ以上のプラグインが提供している（同上）。どのプラグインかをメッセージに示す |
| CFG-16 | error | 一つの単位のトランスパイラの `language` がそろっていない。例外は `LanguageMismatch` |
| CFG-17 | error | 二つの単位の `out` が同じか、一方が他方の下にある |
| CFG-18 | error | 単位の `in` の glob が、読み込んだファイルのどれにも合わない |

- CFG-1〜CFG-4 と CFG-9 は欠番。名前空間ごとのテーブル、使えない名前、継承、名前空間の `language` とプラグインの照合、`plugins` の名前の探索は、単位の一覧に変えたときになくなった。番号は別の意味に使い回さない。
- `hozo.toml` の診断は位置を持たない（ファイルだけ）。単位を指すときは、何番目の `[[emit]]` か（1 始まり）と、その `namespace` と `out` をメッセージに書く。
- CFG-16 と CFG-5 以外の error は `ConfigInvalid`。終了コードは `docs/diagnostics.md`「終了コード」。
