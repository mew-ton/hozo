# IDE の動きの要件と、枠組み

## この文書が決めること

IDE の設計の段 5（`tools.md`「IDE の設計の段階」）: 画面の構成（`ide-screens.md`）と、見本（`ide-mock.md`）から導く、動きの要件。そこから、画面を作る枠組み（フレームワークと、キャンバスの部品）を選ぶ規準と、候補の比べ。

**この文書は、案。** 利用者が確かめていない（`open.md`「聞かずに決めて、確かめていない決定」）。枠組みは、まだ決めていない: 決めるのは、「動く試作」で確かめた後。

殻（Tauri 2）と、裏方（`hozoc`）は、決まっている（`decisions.md`「決めたこと」187、188）。画面は、OS の表示の部品（Windows は WebView2、macOS は WebKit）の上で動く。

## 動きの要件

### ノート（キャンバス）

| 要件 | 中身 | 出どころ |
|---|---|---|
| 自由に置く | 図形を、置く、動かす、大きさを変える。ノートを、拡大、縮小、移動する。ノートの全体の中の、今の位置が分かる | `ide-screens.md`「決まっている前提」、`ide-mock.md`「直すこと」 |
| 図形の中身が自由 | 図形の中に、文、表、入れ子の一覧、入力の欄を置ける。塊の中で、畳む、行を入れ替える、ますを埋める | `ide-screens.md`「塊」 |
| 入れ物 | 担い手の囲みは、入口を入れると、その担い手の入口になる。囲みを動かすと、中のものも動く。意味を持たない自由な囲みも、ある | `decisions.md`「決めたこと」195 |
| 線が、データから出る | 置いてある図形の間に、仕様の上のつながりがあれば、線が出る。図形を動かせば、線が付いてくる。線に、文と札を付ける。線の種類（宣言、導いた、自由）で、見た目が違う | `ide-screens.md`「結ばれた線」 |
| 線を引く | 人が、図形から図形へ、線を引く。引ける相手は、図形の種類で決まる（状態から状態へ、は引ける。状態から担い手へ、は引けない） | 同上 |
| 自由な図形 | 矩形、ラベル、付箋、自由な線。付箋は、図形に付けると、一緒に動く | `ide-screens.md`「自由な図形」 |
| その場で打ち直す | 図形の名前と説明、塊の中の文を、その場で直す。日本語の入力の、変換の途中で、確定しない | `ide-needs.md`「直すための操作」 |
| 選ぶ、写す、戻す | いくつも選ぶ。写して、貼る。一つ前に戻す。結ばれた図形についての「戻す」は、仕様の書き換えを戻すこと | 同上 |
| 重ね | 図形と線ごとに、印を、出す、隠す | `ide-screens.md`「重ね」 |
| 図形は、定義から描く | 図形と線は、プラグインの定義（形、入力の欄、つなぎ口、つなげる相手、線の見た目）から、IDE が描く。IDE は、手法ごとの図形を、作り込まない | `ide-shapes.md`「決まっている前提」 |

### 追従

| 要件 | 中身 |
|---|---|
| 外からの変更 | AI や、エディタが、仕様のファイルを変えたら、1 秒以内に、置いてある図形の中身と、線が変わる。配置、選んでいるもの、拡大の度合いは、変わらない。人が図形を動かしている最中でも、崩れない |
| データの持ち主 | 図形の中身と線は、`hozoc` のデータから描く。ノートが持つのは、配置と自由な図形だけ（`ide-screens.md`「図形の二つの種類」）。キャンバスの部品が、自分の中に、設計の写しを持たない |
| 直すこと | 描く、線を引く、打ち直すことは、`hozoc` への操作を送ること。結果は、データの変化として戻る。送ってから、画面が変わるまで、1 秒以内 |

検査は、サンプル `order-app`（4,339 行）で、一回およそ 30 ms（今の `hozoc` で測った）。ファイルが変わるたびに、全体を検査し直す形で足りる。

### 規模

| もの | サンプル `order-app` | 耐える大きさ |
|---|---|---|
| ノートの数 | 全体 1、コンテキスト 21、自由なノート | 300 |
| 一つのノートの図形 | 見本で、30〜40。すべて置くと、支払いで 70 ほど | 300 |
| 一つのノートの線 | 見本で、15〜20 | 500 |
| 一つのノートの塊 | 見本で、2 | 20 |
| 一つの塊の行 | 手順で、22 | 300 |

図形を動かす、ノートを拡大する、の動きが、この大きさで、引っかからない。

### 配ること

- 手元だけで動く。画面は、外のネットワークから、何も読まない。
- このリポジトリの、ほかの部分（VS Code 拡張、TS の SDK）は、MIT ライセンス。IDE を、同じように、誰でも、費用なしで使える形で配るなら、画面の部品も、それを許すライセンスでなければならない。**IDE を、どのライセンスで配るかは、決めていない。**

### 作ること

- 画面の部品は、殻なしで（ブラウザで）、自動のテストに掛けられる（`testing.md` の進め方: テストが先）。
- 実装を、AI に任せやすい: 書き方が広く知られ、部品の文書がそろっている（`CLAUDE.md` の進め方）。

## 枠組みを選ぶ規準

重い順。

1. **データから描ける。** 図形と線を、外のデータ（`hozoc` が出すもの）から描き、外のデータが変われば、変わる。部品が、自分の文書を、ただ一つの正として持つ形は、合わない（「追従」の「データの持ち主」）。
2. **図形の中身が、自由な HTML。** 塊（表、入れ子の一覧）を、ふつうの画面の部品として書ける。図形の見た目は、プラグインの側が用意する（`decisions.md`「決めたこと」201、203）ので、実行時に読んだ、プラグインの見た目を、図形の中に載せられる（載せ方は、決めていない: 直に載せるか、iframe か）。
3. **線に、型がある。** データから線を出せる。人が引くときに、引ける相手を決められる。図形の種類、つなぎ口、つなげる相手を、実行時に読んだ定義から決められる（`ide-shapes.md`）。
4. **入れ物がある。**
5. **ライセンスが、配り方を縛らない。**
6. **自由なキャンバスの操作が、はじめからある。** 拡大、移動、選ぶ、写す、戻す、付箋、囲み。ないものは、自分で作る。
7. **AI に任せやすい。**

## 候補

調べたのは、2026 年 11 月 17 日。版と、ライセンスは、そのときのもの。動かして確かめたものは、ない。

| 候補 | 何か | 規準 1〜4（データ、中身、線、入れ物） | 規準 5（ライセンス） | 規準 6（操作） |
|---|---|---|---|---|
| React Flow（`@xyflow/react` 12） | 節と線の図を作る部品。React | 節と線は、外から渡すデータ。節の中身は、React の部品（HTML）。線の種類を作れ、つなぐときに、相手を確かめられる。親子の節がある | MIT | 拡大、移動、選ぶ、位置の表示、大きさを変える、は、ある。写す、戻す、付箋、自由な線は、自分で作る |
| tldraw（SDK 4） | Miro に近い、自由なキャンバスの部品。React | 図形は、React の部品として作れる。線は、図形に結び付く矢印。囲み（フレーム）がある。図形の置き場は、部品の中の文書で、外のデータと、二重に持つことになる | **本番で使うには、ライセンスキーが要る**（SDK 4.0、2025 年 9 月から）。商用は有償で、価格は公開されていない。趣味用のライセンスは、審査があり、透かしが付く | ほぼ、すべて、ある（付箋、囲み、矢印、写す、戻す、位置の表示） |
| Svelte Flow（`@xyflow/svelte`） | React Flow と同じ作者の、Svelte の部品 | React Flow と、ほぼ同じ | MIT | React Flow と、ほぼ同じ。今の版と、安定の度合いは、確かめていない |
| JointJS | 図を作る部品。枠組みを選ばない | 図の部品（UML の図形、線の経路、入れ物）が、豊富。図形は SVG で、中に HTML を置くのは、得意でない | 核は MPL 2.0。上位の JointJS+ は有償 | 拡大、移動、選ぶ、は、ある。付箋や、写す、戻すは、上位版 |
| Excalidraw | 手描き風のホワイトボード。React | 図形の中に、自由な HTML を置きにくい。塊が作れない | MIT | ほぼ、すべて、ある |
| 自分で作る（HTML と SVG） | 見本（`ide-mock/notes.html`）と同じ作り | すべて、思いどおり | —（縛りなし） | すべて、自分で作る |

## 比べて、言えること

- **tldraw は、操作の感じが、いちばん近いが、二つ、合わない。** ライセンス（規準 5）と、図形の置き場が部品の中にあること（規準 1）。ノートが持つのは配置だけ、という分け（`ide-screens.md`「図形の二つの種類」）を、部品の文書の上に、作り直すことになる。
- **React Flow は、型が、いちばん合う。** 「結ばれた図形と、型のある線」は、「節と線」そのもの。節も線も、外から渡すデータなので、「データから描く」が、そのまま書ける。足りないのは、自由なキャンバスの操作（付箋、写す、戻す）で、作る量が、そこに掛かる。
- **Excalidraw は、塊が作れないので、外れる。JointJS は、塊（HTML の表と一覧）が弱い。**
- **自分で作る道は、見るだけなら、見本で足りた。** 動かす、線を引く、拡大する、を、すべて作ることになり、作る量が、いちばん多い。
- **枠組み（React か、Svelte か）は、キャンバスの部品で決まる。** React Flow と tldraw は React、Svelte Flow は Svelte。

## 勧め

**React と、React Flow。** ただし、動く試作で、次のことを確かめてから、決める。

| 確かめること | なぜ |
|---|---|
| 図形 300、線 500、塊 20 のノートで、動かす、拡大する、が、WebKit（macOS）と WebView2（Windows）で、引っかからないこと | 図形の中身が HTML なので、数が増えると、重くなりうる |
| 外のデータが変わったとき、人が図形を動かしている最中でも、崩れないこと | 「追従」 |
| 担い手の囲みに、入口を、入れる、出す | 「入れ物」 |
| 線の文と札が、混んだノートで、読めること。線の経路 | 見本では、手で並べた |
| その場で打ち直すとき、日本語の変換の途中で、確定しないこと | 「その場で打ち直す」 |
| 付箋、自由な囲み、写す、戻すを、作る量 | React Flow に、ないもの |
| IDE が、はじめの中身を、自動で並べられること（自動の配置の部品） | `ide-mock.md`「見本では、確かめられなかったこと」 |

試作は、設計の段の外の、捨てるもの: 確かめた結果を、この文書に書き、試作の作りは、引き継がない。
