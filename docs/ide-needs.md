# IDE が要る情報と操作

## この文書が決めること

IDE の設計の段 2（`tools.md`「IDE の設計の段階」）: 筋書き（`ide-scenarios.md`）の一歩ごとに、設計する人が要る情報と、要る操作を、洗い出したもの。次の段（画面の構成）は、ここに並ぶ情報と操作を、画面に割り当てる。

**この文書は、案。** 利用者が確かめていない（決定 D563、D565）。

## 原則

**今の Hozo と `hozoc` で出せないことを、画面の設計の制約にしない**（決定 D191）。

- 情報と操作は、筋書きが要るものを、すべて並べる。今、出せるかどうかで、落とさない。
- 画面の設計（段 3 から先）は、ここに並ぶ情報と操作が、すべてあるものとして行う。
- 今、出せないものは、Hozo の側（言語、語彙、`hozoc`）の改善する点として、別に残す。一覧の持ち主は `open.md`「Hozo の側の改善する点」。

## 読み方

「要る歩み」は、筋書きの番号と、歩みの番号（`2-5` は、筋書き 2 の歩み 5）。「全」は、どの筋書きでも。

「今」は、その情報や操作が、今、どこから得られるか:

| 今 | 意味 |
|---|---|
| 宣言 | 仕様の宣言として、IR にある（`ir.md`） |
| 検査 | 検査が計算していて、IR にある（`check.md`「計算」） |
| 導く | 宣言と検査の結果から計算できるが、その計算が、`hozoc` にない |
| 語彙 | 語彙のデコレータの意味を読めば、出る。言語は、知らない |
| ない | 今の Hozo では、言えない。または、`hozoc` に、その仕組みがない |
| 外 | 設計ではない。仕様（`.hozo`）には入れず、IDE が持つ |

## 洗い出して分かったこと

- **情報のうち、いちばん多いのは「導く」**: 宣言と検査の結果は、すでにあり、足りないのは、それを逆に引いたり、並べ替えたりする計算。言語を変えずに、`hozoc` に足せる。
- **操作のうち、読むためのものは「導く」で、直すためのものは、すべて「ない」。** 直すための操作は、どれも、要素への操作を文面の書き換えにする、一つの仕組みに懸かっている。
- **「ない」のうち、言語に懸かるもの**: 担い手、前提、進むための条件、値についての規則、反応、操作の後の画面、こちらと外の境。画面の設計は、これらが、あるものとして行う（「原則」）。
- **「ない」のうち、ハーネスに懸かるもの**: 中身の有無、確かめた結果。テストの生成（`requirements.md`「段階」）と、結果を仕様の要素に結ぶ仕組みが要る。
- **「外」の情報は、置き場が一つ要る**: 気づいたこと、目を通した範囲、後で決めること、受け入れた版、AI とのやり取り。プロジェクトごとに、人ごとに持つのか、チームで共有するのかは、決めていない。
