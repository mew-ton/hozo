# サンプル

## この文書が決めること

サンプルとは何か、置き方、テストがそれをどう使うか。これらの事実の持ち主はこの文書（`docs/testing.md`「トランスパイラのテスト」がここを指す）。

## サンプルとは

**（Hozo の仕様、完成したコード）の組**を、手で書いたもの。トランスパイラのプロトコルと、生成するコードの形についての問いは、具体的な組がなければ決められない。サンプルはその具体例で、二つの役目を持つ。

- **まだないトランスパイラの仕様**。トランスパイラを実装したら、サンプルの入力に `hozoc emit` を掛けた出力が、サンプルの期待する出力とバイト単位で同じにならなければならない（ブラックボックスのテスト。`docs/testing.md`「トランスパイラのテスト」）。
- **今の設計の点検**。理想のコードを書く途中で、今の設計（共有する形、プロトコル、語彙）が与えてくれなかったものを、サンプルの `README.md`「分かったこと」に残す。

期待するコードは、本当にコンパイルできて動くものにする。動かないコードは、仕様として信用できない。

## 置き方

```
tests/samples/<名前>/
  README.md      ファイルごとの出どころ、各トランスパイラが従う規則、「分かったこと」
  hozo.toml      本物の設定。単位の transpilers には、まだないトランスパイラの名前をそのまま書く
  *.hozo         仕様
  sample.json    トランスパイラごとの、選ぶ宣言と、出すファイル（下）
  go.mod, go.sum サンプル自身の Go のモジュール（Go のサンプルのとき）
  <out>/         単位の out。期待する出力（共有する形のファイルと、トランスパイラのファイルと、記録 .hozoc-outputs.json）
  それ以外       人が書くコード（葉の op の本体、準備、main、テスト）
```

- 期待する出力は、`hozo.toml` の単位の `out` のディレクトリそのものに置く。`hozoc emit` が書き出す場所と同じで、置いたままコンパイルできる。
- 期待する出力のファイルの出どころは二つ。**共有する形**（`docs/emit-go.md`。hozoc の既定の出力）のファイルは、今の `hozoc emit` が書いたものをそのまま置き、手で直さない。**トランスパイラのファイル**は、そのトランスパイラが出すべき内容を人が書く。どちらであるかは `sample.json` が決める。
- サンプルは自分の `go.mod` を持つ、リポジトリのモジュールとは別のモジュールにする。リポジトリの `go build ./...` / `go vet ./...` / `go test ./...` はサンプルの Go を見ない（サンプルだけが使う依存を、リポジトリのモジュールに入れないため）。生成したコードが import する `runtime` は、`replace github.com/mew-ton/hozo => ../../..` で解決する。`gofmt -l .` はモジュールを見ないので、サンプルの Go も整形しておく。
- 共有する形が、理想のコードを書きにくく（または書けなく）していても、生成器も、共有する形のファイルも変えない。「分かったこと」に書く。

## sample.json

```json
{
  "transpilers": {
    "go-http": {
      "select": { "roots": ["http.get", "http.post"] },
      "files": ["both/server/http.go", "httponly/server/http.go"]
    }
  }
}
```

- `transpilers` のキーは、`hozo.toml` の単位に書いたトランスパイラの名前。単位に書いた名前はすべてここに要り、ここに書いた名前はどれかの単位が使っていなければならない。
- `select` は、そのトランスパイラが出力の対象に選ぶ宣言（`docs/plugin-protocol.md`「選択」）を、テスト用のプラグイン `tests/plugins/pick` の規則の形（デコレータの FQN。`tests/plugins/pick/main.go` の先頭）で書いたもの。トランスパイラがまだない間、`pick` がこの規則でそのトランスパイラの代役をして、共有する形を作る。
- `files` は、期待する出力のうち、そのトランスパイラが出すファイル（サンプルのルートからの相対パス）。単位の `out` の下の、ここにないファイルは共有する形（と、出力先ごとの記録）。

## テスト

`tests/samples_test.go` の `TestSamples` が、`tests/samples/*/sample.json` のあるディレクトリをサンプルとして見つけ（足せば自動で入る）、サンプルごとに四つを確かめる。

| サブテスト | 確かめること |
|---|---|
| `check` | サンプルの仕様が `hozoc check` を error なしで通る |
| `shared` | **共有する形が古くなっていない**: 代役のトランスパイラで `hozoc emit` した出力が、期待する出力のうち共有する形のファイルとバイト単位で同じ。単位の `out` の下のファイルは、既定の出力が書くか、`sample.json` の `files` にあるかのどちらかでなければならない。記録 `.hozoc-outputs.json` は、代役の記録に `files` を足したものと比べる |
| `go` | **サンプルが動く**: サンプルのモジュールで `go vet ./...` と `go test ./...` が通る（期待する出力がコンパイルでき、人が書いたコードと合わせて仕様の通りに動く） |
| `transpilers` | **トランスパイラのブラックボックスのテスト**: 本物の `hozo.toml` と、リポジトリの `plugins/` のプラグインで `hozoc emit` した出力の全体（共有する形、トランスパイラのファイル、記録）が、期待する出力とバイト単位で同じ。サンプルのトランスパイラを `plugins/` のどのプラグインも提供していなければ、理由を書いて飛ばす（保留）。提供するプラグインを足せば、何も変えずに走る |

- `check` と `shared` は、サンプルの入力（`hozo.toml`、`.hozo`、`go.mod`）を一時ディレクトリに写して走らせる。本物の `hozo.toml` は書き換えない: まだないトランスパイラと同じ名前のトランスパイラを提供する代役のプラグイン（`pick` を `go build` したものと、`sample.json` の `select` から作ったマニフェストと `pick.json`）を、プロジェクトの外のディレクトリに置き、`HOZO_PLUGIN_PATH` として hozoc に渡す（`docs/plugin-protocol.md`「探索」の 2）。代役がなければ、単位のトランスパイラが見つからず CFG-14 になる。
- 共有する形の更新は `go test ./tests -run TestSamples -update`。共有する形のファイルと記録を書き直し、既定の出力が書かなくなったファイルを消す。トランスパイラのファイルと人が書くコードには触らない（生成器を変えて共有する形が変わったら、それに合わせて手で直す。`go` が、合っていないことを教える）。
- `go` は、サンプルの `go.sum` の通りの依存をモジュールキャッシュから使う（`GOFLAGS=-mod=readonly`、`GOTOOLCHAIN=local`、`GOWORK=off`）。キャッシュにあればネットワークは要らない。なければ `go` が `GOPROXY` から取りに行き、取れなければ（オフラインなど）失敗する。飛ばさないのは、動くと確かめていないサンプルを仕様として通さないため。先に取っておくには、サンプルのディレクトリで `GOTOOLCHAIN=local go mod download`。
- サンプルだけを手で確かめるには、サンプルのディレクトリで `GOTOOLCHAIN=local go vet ./... && GOTOOLCHAIN=local go test ./...`。
